## 三、升级 cloudflared（计划任务版）

```powershell
# ① 备份旧版（回滚用）
Copy-Item D:\dino_backend\cloudflared.exe "$env:TEMP\cf-old.exe" -Force
& D:\dino_backend\cloudflared.exe --version

# ② 下载新版
Invoke-WebRequest "https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-windows-amd64.exe" -OutFile "$env:TEMP\cf-new.exe"

# ③ 停任务 + 杀进程（❗只停任务不够：exe 被进程占用会导致替换失败）
Stop-ScheduledTask -TaskName dino_tunnel
Get-Process cloudflared -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep -Seconds 2
Get-Process cloudflared -ErrorAction SilentlyContinue   # 应无输出

# ④ 替换
Copy-Item "$env:TEMP\cf-new.exe" D:\dino_backend\cloudflared.exe -Force

# ⑤ 起任务 + 验证
Start-ScheduledTask -TaskName dino_tunnel
& D:\dino_backend\cloudflared.exe --version
Get-ScheduledTask -TaskName dino_tunnel | Format-List TaskName, State
```

> ⚠️ 替换期间隧道中断数秒，建议无人使用时操作。
> ⚠️ 隧道是**命名隧道**（`tunnel run dino-backend`），凭证在 `%USERPROFILE%\.cloudflared\` 或系统级目录，**升级 exe 不涉及凭证**。

### 回滚
```powershell
Stop-ScheduledTask -TaskName dino_tunnel
Get-Process cloudflared -ErrorAction SilentlyContinue | Stop-Process -Force
Start-Sleep -Seconds 2
Copy-Item "$env:TEMP\cf-old.exe" D:\dino_backend\cloudflared.exe -Force
Start-ScheduledTask -TaskName dino_tunnel
& D:\dino_backend\cloudflared.exe --version
```

## 四、后端重启（改完 `dino_backend.py` 必做）

```powershell
# 服务器上：
# 1) 结束旧进程（或在原窗口 Ctrl+C）
Get-Process python -ErrorAction SilentlyContinue | Where-Object { $_.Path -like '*python*' } | Stop-Process -Force
# 2) 启动（不带参数 = 启动 watchdog，worker 崩溃自动拉起）
cd \\SERVER\dino_backend
python dino_backend.py
```

**期望输出**：
```
[watchdog] dino_backend watchdog started (never exits, worker auto-restart)
dino_backend listening on :8080
  RCON_HOST=...
```

> 只跑服务体（无自动重启）：`python dino_backend.py --worker`

## 五、常见故障速查

| 症状 | 含义 | 处理 |
|---|---|---|
| cloudflared 日志 `dial tcp 127.0.0.1:8080 ... actively refused` | **后端进程不在**（8080 无监听） | 重启后端；看有无 `[watchdog] worker exited rc=?` |
| 浏览器 502 Bad Gateway + 同时报 CORS | CF 拿不到源站响应（502 页无 ACAO 头，属次生现象） | 同上；若反复出现，检查后端是否被压崩 |
| `ERR_ABORTED` / `ERR_CONNECTION_CLOSED` | 链路或代理中途切断 | 检查代理直连规则：`*.whiterober.ccwu.cc` → DIRECT |
| 页面数据少 / 版本号是旧版 | 浏览器 SW 旧缓存"降级" | F12 → Application → **Clear site data** |
| 隧道报 `Your version ... is outdated` | 仅**版本提醒**，不影响功能 | 按第三节升级（不紧急） |

## 六、已知架构要点（排查时先看）

1. **请求分两类**：
   - **不带 `?cb=`**（HEAD 探测/缓存命中）→ 走 **CF 边缘缓存**，不回源
   - **带 `?cb=<时间戳>`**（数据下载）→ **必然回源** → 依赖后端存活
   → 所以「我这边测着正常、你页面一直失败」是常见错觉，要确认**请求打到哪里**
2. **后端并发**：`_GuardedServer` 信号量 **32**（2026-09-11 加入）；
   前端刷新轮询已改指数退避（400→3000ms），单次刷新请求量约 **130**（原先 1000~2000）
3. **数据文件 404 属正常**：`Bob_*`（俱乐部黑名单服无导出）
