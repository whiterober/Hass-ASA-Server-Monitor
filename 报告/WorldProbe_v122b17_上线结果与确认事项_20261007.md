## 2. 与「改动前」逐键对拍结论
以 **v122b11 时代**的 Sco `weather slim=1` 样本（真正改动前的存档）为基线：

- **`weatherState` 键集完全一致**（老 38 / 新 38，新增 0 / 丢失 0），`weatherName` 一致（`PartlyCloudy`）。
- 唯一差异是两个**诊断计数**：`semFieldsFound` 31 → 32、`semUnreadable` 0 → 1（UDS 图）。
  原因：新实现把 `CurrSequenceSettings`（用来取天气名的结构）也计入 `sem_val`，旧实现只读它的名字、不计入。
  ⇒ **判据字段零差异**，若前端展示这两个计数可忽略；已在"下次构建顺带对齐"清单里。

## 4. 全命令回归（v122b17，11 图 × 8 个只读命令）
- 结果：**全部 OK**（`ok=true`、JSON 合法、关键字段齐全）；Bob 除外（未装插件）。
- 耗时：**冷启 8~170 ms**（重启后首调，含 actor 索引重建约 60 ms、部分图的锚点兜底全名扫描约 170 ms，
  以及各图自身的静态表重建；每 `probe_rescan_seconds`（默认 30 s）最多一次）；
  **稳态 2.6~22 ms**（优化前 `weather` 为 255 ms）。
- 说明：用"每次新建连接"的方式调用时（每次约 1.2 s），通常**看不到响应 TTL 命中**；
  要看插件真实开销请读 `cache.workUs`，不要用墙钟耗时。
