## 三、后端能力摘要（前端对接面）

### 3.1 容器改名命令

```
TransferIdentityFix.RenameContainer <objName|尾部数字> <新名字>
```

- 成功：`{ok:true, objName, class, field:"BoxName", old, new, readback, verified, dup, detail}`
- 失败：`{ok:false, error, hint?, detail}`；`error` ∈ {`usage: …`、`name empty`、`name too long (N bytes, max 60)`、`name contains control char`、`world/level not ready`、`container not found`、`ambiguous id (N matches)`}
- `hint`：非容器结构（如 `StructureBP_Coffin_C`）会提示"only container boxes can be renamed"
- 支持范围：`APrimalStructureItemContainer` 及其子类（储物箱/保险柜/CryoFridge/展示台/泰克专储/工业熔炉/化学台…）
- **床 / 棺材 / 牌子无官方同步通道，按设计拒绝**

### 3.2 取 `<objName>` 的途径

- `InvProbe <类名关键字> <tribeId> <最多容器数>` → `list[].id` 即 `objName`
- ⚠️ `InvProbe` 跳过**空容器**（`itemCount <= 0`）
- **前端已有更省的途径**：`facilities[].class` 形如 `StorageBox_Huge_C_2144016418` ⇒ **尾部数字即实例号**，可直接作第一个参数（无需先探测）；`facilities[].key` 是 32 位哈希，**不可用于改名**

### 3.3 新增字段 `colorRegions`

- 位置：`facilities[]` 与 `structures[]` 条目上；**仅当有染色数据时出现**（缺省 ≠ 空数组）
- 语义：变长数组，**下标 = 染色区域号 0–5**；值 `-1` = 未设置（注意：**颜色 0 是合法值**）；值 = ARK 调色板索引（非 RGB）
- 实测覆盖（Isl）：`facilities` 1316 条中 92 条带该字段；`structures` 124 条中 0 条

### 3.4 `structures` 收录变更

- 新增：`Sign_Wall_Metal_C`、`Sign_Wall_Wood_C`（Isl 87 → 124，+15 面壁挂牌）
- 前端影响：`LB_AREA_SIGN_RE` 已含 `Sign_Wall_Metal`（v1319）⇒ 无需改动；装饰排除正则已同步

## 四、方案 A：容器手动改名

### 4.1 按钮（与生物完全一致）

| 项 | 生物（现状） | 容器（新增） |
|---|---|---|
| 按钮形态 | 卡片右下角图标按钮（`.lb-id-btn` + `mdi-pencil`） | **容器没有卡片** ⇒ 只能放**手风琴标题行**：`.lb-rel-rename` 同款文字按钮，**文案「改名」** |
| 位置 | 卡片右下角 | 与既有 `.lb-rel-rename`（一键起名）**同一位置/同一视觉基准**（`<summary>` 右侧；CSS L302-304 的 `margin:-5px -6px -5px 0` 对齐规则照搬） |
| 显隐条件 | 仅"我自己的 + 放出状态"（`r._canRename`） | 仅**我的部落** + 该容器属可改名箱子（见 §4.4） |
| 携带数据 | `data-rn='{"srv","id1","id2","cn"}'` | `data-cn='{"srv","obj","cls","cn","tribe"}'`（`obj` = `containerClass` 尾部数字） |

> 说明：**容器不存在卡片**（UI 上只有手风琴标题 + 内容列表）⇒ “卡片角标”方案不成立，已从待确认项中移除。

### 4.2 弹窗（照搬 `lbOpenRename`）

- 结构、尺寸、配色、按钮排列**逐项对齐**：`360px` 卡 / `#7c3aed55` 边框 / 标题紫色 `#a78bfa` / 输入框同款样式 / 消息区 `#lbRenameMsg` / 右下 `关闭`
- 唯一差异：**去掉「🎲 自动命名」按钮**（容器无模板命名需求），`提交改名` 占满整行
- 标题文案：`✏️ 容器改名`；副标题：`<服名> · <容器中文名> · 实例号 <obj>` + 「当前名：<b>原名</b>」
- **入口按钮文案统一为「改名」**（不出现“一键/批量”字样）

### 4.3 提交流程

```js
// 新增（建议命名）：lbOpenContainerRename(ev, btn) / lbDoContainerRename(d)
POST {LB_API}/api/rename_container
  body: { username, server, obj: '2144016418', cls: 'StorageBox_Huge_C', name: '<新名>' }
```

**前端本地校验（提交前，避免无谓 RCON）**

| 校验 | 规则 | 提示 |
|---|---|---|
| 非空 | `name.trim() !== ''` | 请输入新名字 |
| 长度 | `new TextEncoder().encode(name).length <= 60` | 名字太长（N/60 字节） |
| 控制字符 | `/[\\x00-\\x1F\\x7F]/.test(name)` | 名字含非法字符 |
| 同名 | `name === 当前名` | ⚠ 新名与当前名相同，未改动 |

**成功回执解析**（字段与生物改名**同构**，便于复用同一渲染片段）

```
✅ 改名成功
旧名：… → 新名：…
游戏内已同步：✅ 是 / ❌ 否      ← verified
读回确认：…                      ← readback
同名容器：N 个（含自身）          ← dup（新增字段，≥1 正常）
```

**成功后本地写回**：新增 `lbLocalApplyContainerRename(srv, obj, newName)`（对标 `lbLocalApplyRename`）——把 `data.recs` / `facilities` / `structures` 里对应容器的 `containerName`（或 `name`）改写，再 `lbRenderKeepView()` 无感重渲染。

**失败提示映射**（`error` → 中文）

| error | 提示 |
|---|---|
| `usage: …` | 用法错误（前端不应触发） |
| `name empty` | 请输入名字 |
| `name too long (N bytes, max 60)` | 名字太长 |
| `name contains control char` | 名字含非法字符 |
| `world/level not ready` | 世界未就绪，稍后重试 |
| `container not found`（带 `hint`） | 「该设施不支持改名（仅容器箱可改名）」+ hint |
| `ambiguous id (N matches)` | 实例号命中多个对象，请刷新后重试 |

### 4.4 可改名设施白名单（前端显隐判据）

- 命中即显示改名按钮：`StorageBox_*`、`Vault`、`CryoFridge`、`DisplayCase`、`TekStorage`、`IndustrialForge`、`ChemBench`、`Refrigerator`、`IceBox`、`LinkedStorage`、`DedicatedStorage` …
- **实现方式**：不硬编码 → 用**排除法**：`LB_BED_RE`（床/棺材/睡眠舱）、`Sign_*`、`Gravestone`、`StructureBP_HangingSign` 等已知**不可改名**类一律不显示按钮；其余容器类显示（与后端"仅容器箱"对齐）
- ⚠️ 更稳的做法：**白名单只列 `APrimalStructureItemContainer` 对应前端已知容器子类型**（`lbContainerTypeOf` 派生的 `sub` ∈ {storage, fridge, vault, dedicated, tek, forge, chem, display…}）—— 见 §7 待确认 ②

## 五、方案 B：不做一键/批量改名（只锁定“位置/样式基准”）

- **生物侧**：`.lb-rel-rename`（`一键起名`）**完全不动**
- **容器侧**：按用户口径 **不新增任何批量改名**；容器只有一个改名入口 —— 手风琴标题行的 **「改名」** 按钮（手动、单个容器）
- 该按钮的**位置与样式基准** = 既有 `.lb-rel-rename`（CSS L302-304）在容器手风琴 `summary` 右侧的形态 ⇒ 与“一键起名”按钮并排，视觉一致、互不冲突（不同 `data-*`）

> ⇒ 结论：**方案 B 无独立工作量**，仅为 §四 按钮的“样式基准”说明。

## 六、方案 C：设施着色显示

### 6.1 数据接入

1. `cryo.facilities` 透传（L4248 附近）：facility rec 增加 `colorRegions: f.colorRegions`（缺省不写）
2. `cryo.structures` 透传（L4243）：`structures.push(s)` 保持原对象（`colorRegions` 自然保留）
3. `LB_SCHEMA_VER` +1（新增字段 ⇒ 丢弃旧 IndexedDB/内存缓存，避免读到无字段的旧结构）

### 6.2 渲染（只读色块）

```html
<!-- 只画「已着色」的区域；未着色 / 从未染色 一律不出现 -->
<span class="lb-fcol" title="区域5 色号67">
  <i style="background:#<lbColorHex(67)>"></i>
</span>
```

| 项 | 规格（参照 `lbRouteColorHtml` 的“色”视觉） |
|---|---|
| 形态 | **圆色点**：`width:10px;height:10px;border-radius:50%;display:inline-block;margin:1px 2px 0 0;border:1px solid #ffffff33`（原 15×15 圆角方块**已废弃**） |
| 只画已着色 | 值 `-1` / 缺省（数组未包含该下标）⇒ **不渲染该点**；全部区域均未着色 ⇒ 整个 `span` **不输出** |
| 颜色 | `lbColorHex(idx)`（色号 **0 也照常渲染**，0 是合法颜色） |
| 提示 | `title="区域N 色号X"`（多区域用 ` \| ` 连接）；**不再出现**“未着色 / 从未染色”字样 |
| 交互 | **只读**（无 `onclick`、无 `cursor:pointer`），与路线浮窗的“可选”态区分 |
| 挂载点 | ① 容器标题 `lbContainerLabel` 末尾（该容器有 `colorRegions` 时追加）；② 设施 chip（`_mkAreaChips`） |

### 6.3 性能

- 仅 92/1316 条设施带该字段 ⇒ 绝大多数分支零开销（`if(!r.colorRegions) return '<span></span>'` 早退）
- 色块串预生成可缓存（按 `colorRegions.join(',')` 做 memo）

## 十二、附：关键代码骨架（P2/P3 用）

```js
/* ---------- 容器改名：按钮（手风琴 summary 右侧，文案「改名」；样式基准 = .lb-rel-rename） ---------- */
function lbContainerRenameBtn(r){
  if(!lbCanRenameContainer(r)) return '';
  var d = { srv:r.server, obj:lbObjSuffix(r.containerClass), cls:r.containerClass, cn:r.containerName||'', tribe:Number(r.containerTribe||0) };
  return '<button class="lb-rel-rename" data-cn="'+lbAttr(JSON.stringify(d))+'"'
       + ' onclick="event.stopPropagation();lbOpenContainerRename(event,this)" title="改名">改名</button>';
}
function lbObjSuffix(cls){ var m = String(cls||'').match(/_C_(\d{4,})$/); return m ? m[1] : ''; }

/* ---------- 容器改名：弹窗（照搬 lbOpenRename 结构与样式） ---------- */
function lbOpenContainerRename(ev, btn){

function lbDoContainerRename(d){
  var input = document.getElementById('lbRenameInput'), msg = document.getElementById('lbRenameMsg');
  if(!input || !msg) return;
  var name = (input.value||'').trim();
  var bytes = 0; try{ bytes = new TextEncoder().encode(name).length; }catch(e){ bytes = name.length; }
  if(!name){ msg.textContent='请输入新名字'; msg.style.color='#f87171'; return; }
  if(bytes > 60){ msg.textContent='名字太长（'+bytes+'/60 字节）'; msg.style.color='#f87171'; return; }
  if(/\x00-\x1f\x7f/.test(name)){ msg.textContent='名字含非法字符'; msg.style.color='#f87171'; return; }
  if(d.cn && name === String(d.cn).trim()){ msg.textContent='⚠ 新名与当前名相同，未改动'; msg.style.color='#fbbf24'; return; }
  msg.textContent='执行中…'; msg.style.color='#999';
  var auth = null; try{ auth = JSON.parse(localStorage.getItem('dinoAuth')||'null'); }catch(e){}
  fetch(LB_API + '/api/rename_container', { method:'POST', headers:{'Content-Type':'application/json'},
    body: JSON.stringify({ username: auth?auth.user:'', server: d.srv, obj: d.obj, cls: d.cls, name: name }) })
  .then(function(r){ return r.json(); }).then(function(j){
    if(j && j.ok){
      var lines = [];
      if(j.old !== undefined && j.new !== undefined) lines.push('旧名：'+escapeHtml(String(j.old))+' → 新名：'+escapeHtml(String(j.new)));
      if(j.verified !== undefined) lines.push('游戏内已同步：'+(j.verified?'✅ 是':'❌ 否'));
      if(j.readback) lines.push('读回确认：'+escapeHtml(String(j.readback)));
      if(j.dup) lines.push('同名容器：'+j.dup+' 个（含自身）');
      msg.innerHTML = '✅ 改名成功'+(lines.length?'<br>'+lines.join('<br>'):'');
      msg.style.color = '#22c55e';
      if(typeof lbLocalApplyContainerRename==='function') lbLocalApplyContainerRename(d.srv, d.obj, name);
      if(typeof lbRenderKeepView==='function') lbRenderKeepView();
    } else {
      var map = { 'name empty':'请输入名字', 'name contains control char':'名字含非法字符', 'world/level not ready':'世界未就绪，稍后重试' };
      var err = String((j&&j.error)||'未知错误');
      var txt = map[err] || (/^name too long/.test(err) ? '名字太长' : (/^container not found/.test(err) ? '该设施不支持改名（仅容器箱可改名）' : (/^ambiguous id/.test(err) ? '实例号命中多个对象，请刷新后重试' : err)));
      msg.innerHTML = '❌ 改名失败：'+escapeHtml(txt)+(j && j.hint ? '<br><span style="color:#888">'+escapeHtml(String(j.hint))+'</span>' : '');
      msg.style.color = '#f87171';
    }
  }).catch(function(e){ msg.textContent='请求失败：'+e; msg.style.color='#f87171'; });
}

/* ---------- 着色点（只画「已着色」区域；圆点；只读） ---------- */
var _lbFColMemo = {};
function lbFacColorHtml(cr){
  if(!cr || !cr.length) return '';
  var key = String(cr.join(','));
  if(_lbFColMemo[key] !== undefined) return _lbFColMemo[key];
  var tips = [], dots = '';
  for(var i = 0; i < cr.length && i < 6; i++){
    var v = cr[i];
    if(v === undefined || v === null || v === -1) continue;   // 未设置 ⇒ 不画；数组未包含的下标 = 从未染色 ⇒ 同样不画
    tips.push('区域' + (i + 1) + ' 色号' + v);
    dots += '<i style="display:inline-block;width:10px;height:10px;border-radius:50%;background:'+lbColorHex(v)+';border:1px solid #ffffff33;margin:1px 2px 0 0"></i>';
  }
  if(!dots){ _lbFColMemo[key] = ''; return ''; }               // 全部未着色 ⇒ 整个 span 不输出
  var out = '<span class="lb-fcol" title="'+lbAttr(tips.join(' | '))+'" style="margin-left:6px;white-space:nowrap">'+dots+'</span>';
  _lbFColMemo[key] = out;
  return out;
}
```
