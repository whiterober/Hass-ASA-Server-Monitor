## 1. 需求（用户口径原文 + 澄清）

**入口**：「待制作」按钮**旁边**新增功能按钮「**维护列表**」。

**面板分两部分**：

| 部分 | 内容 |
|------|------|
| **① 生物** | **血或食物不满**的**放出生物 + 载具**；每个显示**距离开始掉血还有多久** |
| **② 设施** | **被关注设施**的**自带库存进度条** + **停机时间**（风机＝额外查**耐久**进度条与耐久耗尽倒计时）——【用户澄正：其余 9 类**只需库存内容**，**无需耐久**】 |

**可关注设施（仅这 10 类）**：风机（耐久）、发电机、泰克发电机、耕地×3（小/中/大）、饲料槽×2（饲料槽/泰克饲料槽）、小存储箱、宝藏箱。

**关注按钮交互（用户澄清）**：
- **样式与交互完全同步生物卡片的关注图标**（`.lb-id-btn` 小方钮 + `mdi-eye`/`mdi-eye-off-outline` + 金色 `lb-watch-on` 态；点击切换、图标联动）
- **聚落设施区**：**仅上述 10 类设施**才显示关注图标
- 位置：**改名按钮左边**（= 聚落设施区 `summary` 里的改名按钮 `lbContainerRenameBtn` 左侧）
- **chip 小徽章** 和 **可展开的设施**都要有

## 2. 数据源（已逐条核实，全部为现网现有能力）

| 数据 | 来源 | 证据 / 说明 |
|------|------|------|
| **当前血/食值** | 导出数据 `rec.currentStatValues`（快照） | 字段在 L4492 落库；卡片早有"血/食/重不满且显示当前值"机制（v375，L6197-6280）。数组索引：`[0]`=血、`[4]`=食（当前），`statValues[0]/[4]`=对应最大值 |
| **放出判定** | `lbContainerTypeOf(r)==='released'` | 现网容器类型判定（L6450 同款判断） |
| **实时刷新（可选）** | `ArkGetDino` 单龙 RCON（`/api/services/script/get_dino`） | 关注未成年面板已用（5s 轮询、`_watchBusy` 防重入、found=false 自动摘除）；**建议只对"维护列表已展开/置顶项"按需刷新**，不做全量轮询 |
| **风机耐久/停机** | **`POST /api/wind_status?server=X`**（今日 v4670 已上线） | 返回 `turbines[]`：health/maxHealth/pct/depleteHours/decayHours；60s 缓存；**按图分组各调一次**（Isl 8 台一次请求 ~13s 冷/1.6s 暖） |
| **其余 9 类设施** | ⚠️ **缺口**：需 RCON 结构探针（**只查库存内容**——容量/燃料数/物品数等；**不查耐久**） | 参照风机流程：类名核对 → `actor` 4-token 取 props（容量/燃料数等）或 InvProbe（内容明细，串行防撞）→ 后端扩展或新接口。**属二期** |

### 2.1 「距开始掉血」的计算

游戏机制：**食物降到 0 后开始掉血** ⇒ `距掉血 ≈ 当前食物 / 食物消耗速率`。

**消耗速率来源（三选项，待定）**：

| 选项 | 说明 | 状态 |
|------|------|------|
| **a. 插件端提供** | 向插件端提需求：批量返回"当前 HP/Food + 食物消耗率"（与风机文档同模式） | 备选（后续可升级） |
| **b. 公式近似** | 用物种库数据（ASB values）或游戏公式的食物消耗系数估算 | ✅ **已定（用户 10-16）** |
| **c. 快照差分** | 利用两期导出快照（`currentStatValues` 变化 ÷ 时间差）算实际速率 | 备选 |

> **已定：b. 公式近似**。实施时在 `values.json`/`ASA-values.json` 与游戏公式中寻找可用的食物消耗系数（如 foodDrainMultiplier / TamedFoodDrainMultiplier）；缺失项按体型/食性同类均值兜底。

## 3. UI 设计

### 3.1 入口按钮（筛选栏）

- 位置：`lb-filter-bar` 内、**`lbTodoBtn`（待制作）右侧**；样式照 `lbTodoBtn`（`lb-class-btn` + 图标 + 角标）
- 图标建议：`mdi-tools`（或 `mdi-wrench`）；**角标**（照 `lbTodoCnt` 样式）：显示 **Part① 不满数 + Part② 异常设施数**（>0 才显示；颜色建议橙色 `#f59e0b` 系）

### 3.2 维护列表浮窗（照 `lbTodoOpen`/`lbWatchOpen` 模式）

```
┌─ 🛠 维护列表 ───────────────────────────── ✕ ┐
│ ① 生物（血/食不满 · 放出中）           [n 只]  │
│  ├ 卡：图标 · 名字 Lv · 血 3642/6000 (61%)    │
│  │      食 120/300 (40%) · 距掉血 ~4.2h ⚠️    │
│  ...                                          │
│ ② 关注设施                              [n 座]  │
│  ├ 卡：风机 ⚡ WindTrubine_C_…56 · 图 Isl      │
│  │      [███████░░░] 61% · 停机 ~72.8h        │
│  │      展开 ▾（x/y/z · decay 96h · wind 3）  │
│  ...                                          │
└───────────────────────────────────────────────┘
```

- **Part① 卡**：生物图标 / 名（`lbZhDeep`+`LB_SPECIAL_NAMES`）/ Lv / **血条+食条**（当前/最大，`<20%` 橙、`<10%` 红闪）/ **距掉血**（<2h 红、<6h 橙）/ 点击卡=定位（复用现有"发卡"逻辑或浮动条）；**载具**（可拥有单位）同卡模板（无食物时只显示耐久/或标注不可喂）
- **Part② 卡**：设施图标 / **改名后名称**（取现有设施命名链）/ 所属图 / **进度条**（风机=耐久 pct；其他=库存 pct，二期）/ **停机时间**（`depleteHours`）/ **可展开**（▾ 展开：objectName、坐标、decayHours、wind、cacheAge）
- **刷新**：打开时拉一次；Part② 设施按图分组调 `wind_status`（60s 缓存内秒回）；手动「刷新」钮传 `fresh:1`

### 3.3 聚落设施区的关注按钮（关键新增）

- **仅 10 类**设施在 `summary` 行显示：把**关注钮插在改名按钮左边**（`lbContainerRenameBtn` / `lbFacBatchRenameBtn` 前）
- 关注钮样式**完全同步生物卡片**：`class="lb-id-btn"`（16px 小方钮）+ `mdi-eye` / 已关注 `mdi-eye-off-outline` + `lb-watch-on` 金色态；`onclick` 切换 + 同步刷新图标（照 `lbWatchToggle` 的 `data-*` 联动模式）
- **显示逻辑**同现有按钮：跟随 `summary` 的展开态（CSS `.acc[open]` 才显示）——**即"可展开的设施"均有关注钮** ✓
- **chip 小徽章关注按钮**（用户 10-16 定）：**无边框、只要图标**（纯 `mdi-eye` / `mdi-eye-off-outline` 图标，颜色切换金色；**不套 `.lb-id-btn` 边框盒**），**可点击切换**（需 `stopPropagation`，不干扰 chip 点击弹改名浮窗）
- **仅 10 类的判定**：按设施类名白名单（风机 / 发电机 / 泰克发电机 / 耕地小中大 / 饲料槽 / 泰克饲料槽 / 小存储箱 / 宝藏箱；**具体类名在实施时用 `流程\工具\class_lookup.py` 查证**）

### 3.4 关注状态存储

- 新 localStorage 键（如 `lbMaintWatch_v1`），结构照 `lbWatchList`：`{sv, fid/坐标, cls, name, ts}`
- **生物部分无需关注**（全自动列出"放出+不满"）；关注仅用于**设施**（Part② 与聚落设施区联动）
- 取消关注 → Part② 卡移除（浮窗内快照延用 `lbTodo` 模式：开窗快照，关闭后消失）
