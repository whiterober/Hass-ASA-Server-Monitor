# 静态表与图标库刷新流程（dino-import）

> 日期：2026-09-20　适用：dino-import（CF 架构）打包与图标库维护
> 背景：打包链路原本 SFTP 从 HA 拉 9 个静态表 + 2 个 values 表；HA 端 `list_icons.py` 又因 `ModuleNotFoundError: No module named 'boto3'` 无法刷新图标库。
> 本次改造：**打包完全脱钩 HA（不拉、不兜底）；图标库刷新回归「扫 R2 → 增量合并本地」既有链路**。

## 3. 图标库刷新链路（R2 → 本地增量合并）

脚本：`tmp/_icons2_sync.py`

```powershell
# 只刷新本地（默认）
C:\Python312\python.exe "b:\项目\Hass ASA Server Monitor\tmp\_icons2_sync.py"

# 需要时顺带上传 HA（可选，默认关闭）
C:\Python312\python.exe "b:\项目\Hass ASA Server Monitor\tmp\_icons2_sync.py" --push-ha
```

步骤：
1. 基准 = `汉化/icons2.json`（**唯一真源**）
2. 扫 R2 `ASA/` 全量（`dino_backend._r2_list`，自动分页，约 5110 个对象）
3. **增量追加**：R2 有、基准没有的名字 ⇒ 追加（打上 `https://img.whiterober.ccwu.cc/<key>`）
4. 写回 `汉化/icons2.json` + `汉化/_upload/icons2.json`（旧版先备份到 `bak/`），输出 diff 报告：新增 / 仅本地保留 / 总数 / 硬编码关键名命中

### 🔴 铁律：绝不「用 R2 全量覆盖」本地
R2 上旧名会被改名或删除（已中招：`Embryo_Egg`→`Embryo`、`M.D.S.M`、`RaptorHead Icon`→`RaptorHeadIcon`），而前端有多处硬编码引用这些名字 ⇒ 全量覆盖会让图标成片消失。脚本只做**追加**，并显式打印「仅本地保留（R2 已无，不删除）」。

> 历史教训：HA 端 `list_icons.py` 报 `No module named 'boto3'`，若不慎执行了「R2 全量重建」会连带破坏前端引用。故刷新一律走本脚本。

## 4. 配套：缩略图（96px WebP）

新增图标后若需要 96px 缩略图：

```powershell
C:\Python312\python.exe "b:\项目\Hass ASA Server Monitor\tmp\_webp_incremental.py"
```
- 扫 R2 全量 → 未压过的用 Pillow `thumbnail((96,96))` + WEBP q70 → `tmp/webp96/<md5(key)[:12]>_w96.webp`
- 更新 `tmp/webp_map.json`（key → 缩略图 URL）
- 打包时按 `icons2 urls ∩ webp_map` 复制进 `thumbs/webp96/` 并生成 `packs/*.bin` + `assets.idx`

## 6. 日常操作速查

| 场景 | 操作 |
|------|------|
| 新增/上传图标到 R2 | 跑 `tmp/_icons2_sync.py`（会自动把新名并入本地库） |
| 图标需要缩略图 | 跑 `tmp/_webp_incremental.py` |

| 打包报「缺少本地静态表」 | 按第 2 节路径补文件；**不要**改回去连 HA |
| 需要改 HA 端同步（旧架构） | 显式加 `--push-ha`，并先确认 HA 备份成功 |
