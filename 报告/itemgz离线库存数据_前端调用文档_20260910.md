# item.gz 离线库存数据 — 前端调用文档

> 日期：2026-09-10 ｜ 生成器：`ark_save_reader.exe`（TransferIdentityFixAPI 配套离线读档工具）
> 本版新增：**蓝图品质判别（rated）** + **泰克专储（DedicatedStorage）条目** + **固定印痕过滤**
> 关联文档：`InvProbe库存扫描命令_前端调用文档.md`（RCON 实时扫描，另一条链路）、`储物箱内容显示与资源体系_方案_20260910.md`（类名→中英→图标体系）

## 1. 这是什么 / 与 InvProbe 的区别

| | **item.gz（本文档）** | InvProbe（RCON） |
|---|---|---|
| 方式 | 离线读存档（exe）→ 生成 `.json.gz` | RCON 实时扫描，直接返回 JSON |
| 时效 | 跟随存档（每次服务器保存后自动重跑） | 即时 |
| 覆盖 | **全服全量**（所有容器/背包/专储） | 单次限容器数（≤5 建议）与容量 |
| 用途 | 前端浏览、统计、地图展示 | 精确查询、按需刷新 |

## 2. 获取方式

1. 服务器插件在每次存档后自动运行 `ark_save_reader.exe`，输出到 `DinoData` 目录：
   - `<Srv>_cryo.json.gz`（龙/低温仓数据，既有）
   - **`<Srv>_item.json.gz`（本文件：库存物品数据）**
2. `DinoDataGzipWatcher.ps1` 负责再压缩，Qsync 同步到 NAS（WebDAV），前端以 `.json.gz` 形式请求（**与 cryo.gz 完全同一链路与地址约定**）。
3. `<Srv>` 为服务器缩写：Isl / Sco / Cen / Abe / Ext / Ast / Rag / Val / Los / Gen。

> 压缩包内是标准 JSON，前端需先解 gzip 再 `JSON.parse`。

## 3. 顶层结构

```json
{
  "serverId": "Ext",
  "arkPath": "...\\Extinction_WP.ark",
  "generatedMs": 17931135,
  "count": 4368,
  "counts": { "blueprint": 1367, "ammo": 687, "resource": 2314 },
  "items": [ ... ]
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `serverId` | string | 服务器缩写（与 cryo.gz 一致） |
| `arkPath` | string | 存档路径（调试用） |
| `generatedMs` | number | 生成时刻的毫秒计数。**⚠️ 当前实现不是 Unix 时间戳**（示例值 17931135），前端不要当日期解析；需要时间请用文件 mtime |
| `count` | number | `items` 数组长度 |
| `counts` | object | 按 `type` 计数：blueprint / ammo / resource |

## 4. 条目字段字典（items[]）

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | string | `blueprint` / `ammo` / `resource`（**粗分类**，规则见 §5.1；判“是不是资源”请用 `kind`） |
| `kind` | string | **细分种类**（推荐用于“资源×N”等统计）：`resource`/`ammo`/`structure`/`consumable`/`saddle`/`armor`/`weapon`/`attachment`/`tek`/`other` |
| `class` | string | 物品类名。普通条目带实例后缀（`PrimalItemResource_Hide_C_2146720689`）；**专储条目为存储的资源类名且无实例后缀**（`PrimalItemResource_Gas`） |
| `key` | string | 物品对象 UUID（hex 32 位）。**专储条目 = 专储柜对象 UUID** |
| `quantity` | number | 普通容器：**该堆数量**；专储：**柜内总量**；图纸类通常为 0 |
| `durability` | number | 耐久（取整）。资源/图纸为 0 |
| `isBlueprint` | 0/1 | 存档内 `bIsBlueprint` 标记（**注意：绝大多数物品为 1，不能单靠它判断"图纸"**） |
| `rated` | 0/1 | **品质标记**（存在 ItemRating / ItemStatValues / ItemQualityIndex 任一）。本版 `blueprint` 类**只保留 rated=1** |
| `rating` | number | **品质评分**（ItemRating，保留 2 位小数）；`-1` = 无（约 2% 蓝图） |
| `qidx` | number | **品质档位 0-5**（0=Primitive … 5=Ascendant）；`-1` = 无 |
| `stats` | number[] | **各属性品质滚动值**（ItemStatValues，0-65535，按属性槽位顺序；护甲 4 项 / 武器·鞍 2 项 / Mek 5 项）；`[]` = 无。**⚠️ 非最终属性数值**（见 §5.6） |
| `dropLoc` | object\|null | **原始掉落位置** `{x,y,z}`（36% 蓝图有；`null` = 无） |
| `customClass` | string | 自定义物品类名（ItemCustomClass，4% 物品有；`""` = 无） |
| `worldTime` | number | 最后耐久衰减时间（世界时钟，相对值，勿当 Unix 时间）；`-1` = 无 |
| `containerId` | string | 容器库存组件 UUID（hex）。**专储条目与 `key` 相同**（柜体自身） |
| `containerType` | string | `player`/`storage`/`fridge`/`display`/**`dedicated`**/`other`/`unknown` |
| `containerClass` | string | 容器库存类名；专储为 `BP_DedicatedStorage_C_<ID>` |
| `containerTribe` | number | 所属部落 ID（0=无部落/野生容器） |
| `containerTribeName` | string | 部落名（随 cryo 部落表解析，可能为空串） |
| `playerName` | string | 玩家背包归属玩家名（仅 player 容器有值） |
| `x` `y` `z` | number | 容器世界坐标（UE 坐标，可直接进地图换算流程） |

## 5. 分类与数据语义（本版重点）

### 5.1 type 粗分类（普通容器与专储**同一规则**）
1. `PrimalItemAmmo*` 或类名含 `C4Ammo` → `ammo`
2. `PrimalItemResource*` → `resource`
3. 其余带 `bIsBlueprint=1` 的 → `blueprint`

> **专储条目同样按上述规则判定**（不再是“非弹药一律 resource”）；专储内的非资源物品（如麻醉药/结构件）会归入其应有分类，并靠 **`kind` 给出准确种类**。专储条目**不参与** §5.3 的蓝图品质过滤（柜内物品永不因无品质而消失）。

### 5.2 kind 字段（细分种类，判“是不是资源”用这个）

按类名前缀归一（优先级从上到下）：

| kind | 判据（类名包含） | 说明 |
|------|-----------------|------|
| `resource` | `PrimalItemResource` | **真正的资源**（金属、兽皮、纤维、元素尘埃…） |
| `ammo` | `PrimalItemAmmo` / `C4Ammo` | 弹药（含 C4 遥控炸药） |
| `structure` | `PrimalItemStructure` | 建筑结构件 |
| `consumable` | `PrimalItemConsumable` | 消耗品（麻醉药、兴奋剂、食物…） |
| `saddle` | `PrimalItemArmor` 且包含 `Saddle` | 鞍具 |
| `armor` | `PrimalItemArmor`（非鞍） | 护甲 |
| `weapon` | `PrimalItem_Weapon` | 武器 |
| `attachment` | `PrimalItemWeaponAttachment` | 武器配件 |
| `tek` | `PrimalItem_Tek` | 泰克装备（未被上述规则先命中时） |
| `other` | 其余 | 其他物品 |

> **前端“资源×N”统计用 `kind === 'resource'`**，不要用 `type==='resource'`。
> `type` 仅作粗分桶（与旧版前端兼容），`kind` 才是物品种类的权威字段。

### 5.3 blueprint 类品质过滤（**仅普通容器**）
- **只保留有品质的物品**（`rated=1`：蓝图带颜色品质，或 Tek 系列带品质数值）。
- **被排除**：制造设施内的**固定印痕配方缓存**（每台设备每个配方一份、无品质）以及普通品质物品。
- 前端拿到 `blueprint` 即等价 `rated=1`，**不需要再过滤**；若历史数据里有 `rated=0` 的蓝图，属于旧版产物，应忽略。

### 5.4 容器粒度（**关键差异，直接影响求和口径**）
| 容器 | 粒度 | 求和口径 |
|------|------|---------|
| 普通容器（箱子/熔炉/背包/龙背包…） | **逐堆明细**：同一容器同一资源可能出现多条（每堆一条），`quantity`=该堆数量 | 需按 `containerId + 资源基名` 自行 **sum()** |
| **泰克专储**（`containerType === 'dedicated'`） | **一柜一条**：`quantity` 直接是柜内该资源**总量** | 直接用，**不要再聚合多条** |

### 5.5 不包含的对象
- 死亡背包 / 掉落物（DeathItemCache / DroppedItem / DeathBag）不输出。
- 空专储（数量为 0）不输出。

### 5.6 蓝图品质详细字段（v5 新增）——展示口径

**品质档位映射**（`qidx` 0-5，与游戏内颜色/前缀一致）：

| qidx | 档名 | 中文 | 建议颜色 |
|:---:|------|------|---------|
| 0 | Primitive | 原始 | 灰白 |
| 1 | Ramshackle | 粗糙 | 绿 |
| 2 | Apprentice | 学徒 | 蓝 |
| 3 | Journeyman | 熟练 | 紫 |
| 4 | Mastercraft | 大师 | 橙黄 |
| 5 | Ascendant | 传说 | 金 |

**关键免责（必须遵守）**：`rating` 与 `stats` 是**品质生成参数**（评分 / 各属性随机品质滚动值），**不是**最终伤害%/护甲%——最终数值 = `IV + IV*MS*DM + IV*MS*RM*RQ`（IV/MS/DM/RM 为游戏内物品模板参数，**不在存档中**）。前端正确用法：
- ✅ 用 `qidx` 显示品质档徽章；用 `rating` 做**排序/筛选**；
- ✅ 用 `stats` 做**同类物品同槽位相对比较**（长条/百分位）；
- ❌ 不要把 `stats` 数值当伤害%/护甲%直接展示。

## 7. 前端消费建议

1. **按容器聚合**：
   - 专储：`containerType==='dedicated'` 直接取 `quantity`；
   - 其他：按 `containerId` 分组后对 `quantity` 求和（同资源多条）。
2. **资源基名归一**：`class` 去掉 `_C_<数字>` 实例后缀 → 得到基名（专储条目本身已是基名），再进类名→中英→图标体系（`item_zh.json` 方案）。
3. **容器识别**：专储 = `containerType==='dedicated'` 或 `containerClass` 含 `BP_DedicatedStorage`；玩家背包 = `containerType==='player'`（可配合 `playerName`）。
4. **地图展示**：`x/y/z` 为容器坐标（专储即柜体坐标）。
5. **部落维度**：`containerTribe` + `containerTribeName` 可直接用；无部落容器为 0 / 空串。
