# RCON 中文名变 `???` —— 根因定位与修复方案

- 日期：2026-11-12
- 现象：`{server}_online.json` 的 `attributes.players[].name` 是字面 `???`
- 受影响：`Isl_online.json`（当前唯一有在线玩家的服）
- 结论：**不是 Python 解码问题、不是网络问题，是 ARK 原生 `ListPlayers` 在生成响应时把 UTF-16 名字转 ANSI 丢失了**；`eosId` 完好，可用存档侧数据回填

---

## 1. 证据链（4 条，逐条可复现）

### 1.1 线上文件实况

`\\SERVER\ARK Server\DinoData\asa-data\Isl_online.json`

```json
{"state":"ok","attributes":{"count":1,
  "players":[{"eosId":"00023cf443714568b5e273e50d6e152b","name":"???"}]}}
```

其余 10 服 `count=0`（当时确实没人）。

### 1.2 RCON 原始字节（决定性）

直连 `work.whiterober.cn:32320` 发 `ListPlayers`，抓到的响应体：

```
b'\n0. ???, 00023cf443714568b5e273e50d6e152b \n '
hex: 0a 30 2e 20  3f 3f 3f  2c 20 30 30 30 32 33 63 66 34 …
                  ^^^^^^^^^ 三个 ASCII 0x3F = '?'
含 UTF-8 中文首字节 (E4–E9)：False
含 GBK 高位字节 (0x81–0xFE)：False
```

**网络上传输的字节本身就是 `3F 3F 3F`**，不存在任何中文编码。

### 1.3 后端解码方式（可排除）

`dino_backend.py:7496`

```python
text = (raw or b'').decode('utf-8', errors='ignore')
```

`errors='ignore'` 的行为是**丢弃**非法字节，绝不产生 `?`。
（若用 `errors='replace'` 产生的是 U+FFFD `\ufffd`，也不是 `?`。）
所以这个 `?` 不可能由 Python 产生。

### 1.4 存档侧真名完好

`\\SERVER\ARK Server\DinoData\Isl_cryo.json.gz` → `players[]`：

```json
{"pid": 233391766,
 "eosId": "00023cf443714568b5e273e50d6e152b",
 "name": "嘎巴菜",
 "characterName": "嘎巴丸",
 "roles": {"233391766": "嘎巴丸"}}
```

同服 `players[]` 里中文名共 5 个，全部完整：
`黄猿4a抓回来你`、`飞翔`、`蒜头`、`JIBBER超`、`嘎巴菜`。

**关键**：`ListPlayers` 里的 **EOS ID 是完整正确的**，只是名字坏了 → 可以 join 回填。

## 2. 排除表

| 嫌疑 | 判定 | 依据 |
|---|---|---|
| Python 解码 | 排除 | `errors='ignore'` 只会丢字节，不造 `?` |
| 网络 / 隧道 / CF | 排除 | TCP 原样收到 0x3F；RCON 不走 HTTP |
| 插件 dll | 排除 | `ListPlayers` 是 ARK 原生命令，不经过插件 |
| 后端 JSON 序列化 | 排除 | `json.dump` 对 `?` 是 ASCII，无转换 |
| **ARK 响应序列化** | **真凶** | 原始字节即 `3f 3f 3f` |

---

## 3. 机制：逐字符 ANSI 转换失败

- `???` 的数量 = 名字的**字符数**（`嘎巴菜` 3 字 → 3 个 `?`），说明是"每个字符独立转换、失败填 `?`"，不是整体编码错乱
- ARK 把 UTF-16 的 `FString` 转 ANSI（`WideCharToMultiByte`/`TCHAR_TO_ANSI`）时使用了一个**表示不了 CJK 的代码页**（如 CP1252/437），默认替换字符就是 `?`
- 若服务器 ACP 是 936(GBK)，中文会变成 GBK 字节（可救）；实测**一个高位字节都没有**，说明转换用的是非中文代码页

> 同类现象：备份文件名把中文变成 `_`（每个字符换一个下划线），也是"逐字符转换失败"，只是替换符不同。

## 4. 修复方案

### 方案 A（推荐）：用 `eosId` 回填真名

**零新增解析** —— `_cryo.json.gz` 本来就有 `players[]`，且已被 `cryo_doc()` 缓存（TTL 30 min）。

在 `dino_backend.py::list_players()`（第 7480 行）里，`players` 列表构造完（7515 行）之后、`write_status_file`（7548 行）之前插入：

```python
    # 2026-11-12：原生 ListPlayers 把非 ASCII 玩家名转成 '?'（实测原始字节 3f 3f 3f），
    #   但 eosId 完好 → 用存档侧 players[] 的 name 回填。
    def _eos_name_map(_srv):
        _p = os.path.join(DINO_DATA, '%s_cryo.json.gz' % _srv)
        try:
            with gzip.open(_p, 'rb') as _f:
                _doc = json.loads(_f.read().decode('utf-8'))
        except Exception:
            return {}
        _m = {}
        for _x in (_doc.get('players') or []):
            _e = (_x.get('eosId') or '').lower()
            _n = (_x.get('name') or '').strip()
            if _e and _n:
                _m[_e] = _n
        return _m

    _e2n = _eos_name_map(server)
    for _p in players:
        _raw = _p.get('name') or ''
        if _raw.strip('?').strip() == '' and _e2n.get(_p['eosId']):
            _p['name'] = _e2n[_p['eosId']]
            _p['nameRcon'] = _raw        # 保留原始值便于诊断
```

前置条件（已确认）：
- `DINO_DATA` 常量存在（`dino_backend.py:736`）
- `gzip` / `json` / `os` 已 import
- `_cryo.json.gz` 的 `players[]` 元素含 `eosId` + `name`

**覆盖度**：实测 Isl 在线玩家 `00023cf4…` 在 `players[]` 里命中，名字 `嘎巴菜`。

**残留边界**：玩家在上次存档**之后**才进服 → `_cryo.json.gz` 里可能还没有他 → 名字仍 `???`。兜底可再用 ArkApi 日志的 `STATE_MACHINE … user=<名字>`（窗口约 30 小时）。

### 方案 B（彻底）：插件提供在线玩家命令

插件侧玩家名来自引擎 UTF-16，且 RCON 响应经 `TifAsciiSafeJson` 转义成 `\uXXXX`，中文可安全穿过 RCON：

- 优点：不依赖存档新鲜度；以后所有含中文的 RCON 输出都稳
- 代价：改 dll + 投 11 服 + 重启

### 方案 C（备选）：离线 EOS→真名映射

用 `SavedArks\Full_Serveur_Backup\PlayerProfile\connect-*.zip` 文件名 + 日志 `user=` 建映射，实测约 98.1% 覆盖（详见 `playerprofile-backup-events` 记录）。比 A 差，且仅在前两者都不可用时才考虑。

## 5. 连带影响（重要）

**所有走向原生 RCON 且含中文的输出都会变 `?`**，不止 `ListPlayers`：

| 命令 | 受影响字段 |
|---|---|
| `ListPlayers` | 玩家名 |
| `ArkTamedDinos` | 恐龙自定义名 |
| 部落/容器相关原生命令 | 部落名、容器名 |

规则：
- 要中文 → 走**插件自定义命令**（JSON + `\uXXXX` 转义，安全），或
- 原生命令只取 **ID/数值**，中文一律**事后用 ID join 回填**

## 7. 附：自行复现抓包

最小 RCON 客户端（Python，标准库即可）：

```python
import socket, struct, time
def pkt(i, t, body): 
    b = body.encode() + b'\x00\x00'
    return struct.pack('<iii', 4 + 4 + len(b), i, t) + b
s = socket.create_connection((host, port), timeout=8)
s.sendall(pkt(1, 3, password))          # SERVERDATA_AUTH
time.sleep(1); s.recv(4096)
s.sendall(pkt(2, 2, 'ListPlayers'))     # SERVERDATA_EXECCOMMAND
raw = b''
s.settimeout(5)
try:
    while True: raw += s.recv(65536)
except socket.timeout: pass
print(raw)                               # 直接看 0x3f
```

判定要点：**响应体里出现 `3f 3f 3f` 且没有任何 ≥0x80 的字节** ⇒ 上游已丢失，客户端无论怎么改解码都救不回来。

## 8. 补充：为什么以前装了 UnicodeRCON 就没这个问题（2026-11-12 追加）

> 依据：`报告_UnicodeRcon整合与GetInGameTime_20261108.md` 中对 `UnicodeRCONASA.dll` 的静态提取结果。

### 8.1 它改的是"发出去之前"那一步

从 dll 内嵌的 hook / NativeCall 键：

```
RCONClientConnection.SendMessage(int,int,FString&)      <- 核心劫持点（所有 RCON 回包唯一出口）
RCONClientConnection.ProcessRCONPacket(RCONPacket&,UWorld*)
FSocketBSD.Send(unsigned char*,int,int&)                <- 绕过游戏转换的出口
FSocketBSD.Recv(unsigned char*,int,int&,ESocketReceiveFlags::Type)
AsaApi::Tools::Utf8Encode / Utf8Decode
```

工作方式：**劫持 `SendMessage`，自己把 `FString` 转成 UTF-8 字节，再用 `FSocketBSD.Send`
直接写 socket** —— 绕开游戏内部那次 `FString -> ANSI(活动代码页)` 的转换。

### 8.2 它覆盖的不只是插件命令

`RCONClientConnection.SendMessage` 是 ARK 发送**所有** RCON 回包的唯一出口，
因此原生 `ListPlayers` 的回包同样被它接管 —— 中文以 UTF-8 真字节出网卡，后端
`.decode('utf-8')` 直接就是正确中文。

### 8.3 现在为什么坏

| 环节 | 有 UnicodeRCON | 现在（dll 已删） |
|---|---|---|
| 我们插件自定义命令 | hook -> UTF-8 直写 | 自有 `TifAsciiSafeJson` 把非 ASCII 转成 `\uXXXX`（全 ASCII 安全穿过） |
| **原生 `ListPlayers`** | **hook -> UTF-8 直写** | **游戏默认 `FString -> ANSI`，逐字符变 `?`** |

结论：删掉 UnicodeRCON 后，我们只补上了"自己命令"的替代方案（`\uXXXX` 转义），
**原生命令没有任何兜底** —— 这正是 `ListPlayers` 中文变 `?` 的直接原因。

### 8.4 现场残留

```
各服 ShooterGame\Binaries\Win64\UnicodeRCONASA.pdb   6,197,248 B   （仅调试符号，无功能）
各服 ArkApi\Plugins\  -> 只剩 Permissions / ServerOpsKitAPI        （dll 已删）
```

### 8.5 与本文方案的关系

- 方案 A（eosId join 回填）：不装回插件，只修 `ListPlayers` 这一处
- 方案 B（插件提供在线玩家命令）：等价于用我们自己的 `\uXXXX` 通道补上原生命令的空缺
- 方案 C（本文 §4 方案 B 所述"装回 UnicodeRCON"）：**一次解决所有原生 RCON 中文**，
  但它 hook 的是进程级 `FSocketBSD`，历史上被判为"风险大"，且为 2023 年构建，
  AsaApi 2.1 下签名可能失配 —— 需单独评估，不建议作为首选

### 8.6 通用判据（写给后续排查）

> RCON 里出现 `?` 或空白，先判断**是"出网卡前就坏了"还是"收到后解错了"**：
> 抓原始字节 —— 若出现 `3f 3f 3f` 且**没有任何 >=0x80 字节**，就是上游（游戏）已丢失，
> 客户端解码怎么改都没用；只有出现高位字节（UTF-8/GBK）才可能是解码问题。

## 9. 方案 A 可行性评估：把 UnicodeRCON 机制搬进我们插件（2026-11-12）

> 目标：不装回 2023 年的 `UnicodeRCONASA.dll`，而是用我们自己的插件 hook 同一处，
> 让 **所有** RCON 回包（含原生命令）都带正确 UTF-8 中文。
> 性质：**仅评估，未改任何代码。**

### 9.1 UnicodeRCON 原做法需要的两个符号

| 符号 | 用途 | 实测（AsaApi.dll ASCII 名字表） |
|---|---|---|
| `RCONClientConnection.SendMessage` | hook 入口 | **1 命中** ✅ |
| `RCONClientConnection.ProcessRCONPacket` | 对照组（我们已在用） | **1 命中** ✅ |
| `RCONClientConnection.Socket` | 取 socket 指针 | 0 命中（字段表另有存储，头文件 `SocketField()` 仍可能可用） |
| **`FSocketBSD.Send`** | **绕过转换的出口** | **0 命中** ❌ |
| `FSocketBSD.Recv` | 入站（可选） | **0 命中** ❌ |
| `FSocketBSD` | 类名本身 | **0 命中** ❌ |

补充证据：

- `ArkAscendedServer.exe`（97.21）里 `FSocketBSD` 的 **ASCII 与 UTF-16LE 都是 0 命中**
  —— UE5.8 下该类名已不存在或被剥离
- `ArkApi\pdbignores.txt` 的忽略前缀里**没有** `FSocketBSD`
  ⇒ 不是被过滤，而是**压根没有导出到名字表**

### 9.2 时间线（决定"靠 PDB 解析地址"是否可靠）

```
ArkAscendedServer.exe   2026-11-11 09:25   215,561,832 B   ← 实际运行的 97.21
ArkAscendedServer.pdb   2026-07-04 14:20  2,054,803,456 B   ← 不是同一个 build
AsaApi.dll              2026-11-09 12:15     7,351,808 B
AsaApi.pdb              2026-06-07 / 2025    49 / 52 MB
UnicodeRCONASA.pdb      2024-05-27           6,197,248 B   ← 2023~2024 时代符号
```

PDB 与 exe 不同 build ⇒ 拿 PDB 里的地址直接用**不可靠**，只能依赖 AsaApi 的名字表。

### 9.3 结论

| 路线 | 可行性 | 理由 |
|---|---|---|
| A-1：原版 UnicodeRCON（hook SendMessage + `FSocketBSD.Send` 直写 UTF-8） | **不可行** | 出口符号 `FSocketBSD.Send` 在现环境不可解析；类名在 97.21 已不存在 |
| **A-2：hook `SendMessage` + 内容转 `\uXXXX` + 调原函数** | **可行** | 只需 `SendMessage`（符号可用）；**不需要** `FSocketBSD`；仍走游戏发送，无分包/keepalive 风险 |

### 9.4 A-2 的做法与代价

```cpp
// 伪代码
static SendMessageFn g_orig = nullptr;
void Hook_SendMessage(RCONClientConnection* self, int id, int type, FString* msg) {
    if (msg) {
        std::string u = Tools::Utf8Encode(*msg);
        if (has_non_ascii(u)) {
            FString tmp(Tools::Utf8Decode(AsciiEscape(u)).c_str());  // 非 ASCII -> \uXXXX
            g_orig(self, id, type, &tmp);
            return;
        }
    }
    g_orig(self, id, type, msg);
}
```

- **收益**：覆盖 `ListPlayers` / `ArkTamedDinos` / 部落名 / 容器名 —— 所有原生 RCON 中文
- **代价 1**：纯文本响应的中文会变成**字面 `\uXXXX`**，消费端需反转义
  （我们后端一行 `re.sub` 就行；ASAM / ASADedicatedManager 等第三方**不兼容**）
- **代价 2**：hook 是**全局**的，写错会让所有 RCON 回包异常 ⇒ 必须先在单台测试服验证：
  hook 命中次数、`FString*` 生命周期、与 `SendRconResponse` 自身转义是否重复（会双重转义）
- **可选折中**：只在"含非 ASCII **且** 形如 JSON"时转义（等于把 `TifAsciiSafeJson` 提升为全局）
  —— 零兼容风险，但**覆盖不到 `ListPlayers`**（它是纯文本）

### 9.5 建议排序

1. **若只解决在线玩家名单** → 走本文 §4 方案 A（`eosId` join 回填）或新增 JSON 命令，零风险
2. **若要一次性覆盖所有原生 RCON 中文** → 走 A-2，但必须先在单台测试服验证后再铺开
3. **不建议**装回 `UnicodeRCONASA.dll`（2023 构建，符号与 97.21 / AsaApi 2.1 均不匹配）
