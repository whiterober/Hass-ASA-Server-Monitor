# 驯服数据「本地化」可行性报告

> 2026-10-28 · 目标：把驯服计算所需的基础数据全部换成项目页面内已有的，尽量脱离 wikily

---

## 0. 结论（一句话）

**8 项基础参数里 7 项可以 100% 用项目自己已有的数据（三物种逐一验证全对）；只剩「食物亲和度表」需要一次性内置；`torpor_rate` 两库覆盖偏低需小表兜底。**
换掉之后，wikily 只用于「概览正文 HTML + 技能演示视频」这类内容，计算部分完全自给自足。

| 类别 | 现状 | 可本地化 | 说明 |
|---|---|---|---|
| 物种驯服参数（7 项） | 抓 wikily `tame_setup` | ✅ **完全可以** | 三物种验证 7/7 全对 |
| 迟钝衰减速率（1 项） | 抓 wikily `torpor_rate` | ⚠️ **大部分可** | 两库覆盖 12%/19%，缺省值 0.3 需确认 |
| 食物亲和度表（affinity/base） | 抓 wikily `tame_food_list` | ❌ **两库都没有** | 需一次性内置（全局常量，约 40~60 种） |
| 图标 | 已换项目 `icons2.json` | ✅ 已完成 | 上一轮已做 |
| 中文名 | `item_zh.json` / ZH_MAP | ✅ 已有 | — |
| 物种属性表（生命/食物/眩晕基础值） | 抓 wikily 页面 | ✅ **完全可以** | `fullStatsRaw` 前端已在用 |

## 3. 覆盖率：两库合并后 98.7%

| 指标 | ASA-values.json | values.json（ARK） | 合并去重 |
|---|---|---|---|
| 条目数 | 1,144 | 1,049 | **636**（按 name 去重） |
| 有 `taming` | 309 | 1,049 | **628** |
| 有 `fullStatsRaw` | 328 | 328+ | **628** |
| **两者都有（可算驯服）** | 295 | 1,049 | **628 / 636 = 98.7%** |
| 带 `torporDepletionPS0` | 36（12%） | 200（19%） | 约 236 |

> 说明：ASA 库条目虽多（1,144），但多数是变体、且其中只有 295 条带驯服数据；ARK 库 1,049 条几乎全带。两者的同名条目数值基本一致（个别老数据有差异，见风险）。

## 4. 缺口清单

### 4.1 食物亲和度表（唯一的硬缺口）

`affinity`（每口亲和度）与 `base`（喂食单位）在**两个库里都没有**（两库只有 `species`，没有食物/物品数值）。

但它是**全局常量**，与物种无关 —— 已跨物种验证：

| 食物 | affinity | base | 验证 |
|---|---|---|---|
| 卓越饲料 | 400 | 85.248 | Rex = Baryonyx 一致 |
| 普通饲料 | 400 | 85.248 | — |
| 生羊肉 | 187.5 | 50 | Rex = Baryonyx 一致 |
| 熟羊肉 | 101.25 | 49.945 | Rex = Baryonyx 一致 |
| 生肉 | 50 | 50 | — |
| 熟肉 | 25 | 25 | — |
| 优质生肉 | 150 | 50 | — |
| 优质熟肉 | 75 | 49.945 | — |
| 生鱼肉 | 20 | 25 | — |
| 熟鱼肉 | 10 | 12.5 | — |
| 优质生鱼肉 | 60 | 25 | — |
| 优质熟鱼肉 | 30 | 25.686 | — |

**⇒ 抓一次全站食物表（一次性），内置成静态 JSON 即可，之后永久不依赖 wikily。**

### 4.2 `torpor_rate` 覆盖不足

- 两库只覆盖约 236 个物种；`Baryonyx` / `Dodo` 实测缺省值应为 **0.3**（wikily 值一致）
- `Rex` = **0.725**（非默认，且两库都没导出）
- **⇒ 需要一张「非默认值小表」兜底**（估计只有几十条），或退一步：只对缺省物种标「眩晕衰减按默认 0.3 估算」

> 影响面：只影响「多久会醒 / 需补多少麻醉药」两处显示，不影响口数、时间、效率、等级。

### 4.3 无需替换的东西（已本地化）

| 项 | 来源 |
|---|---|
| 图标 | `icons2.json`（`img.whiterober.ccwu.cc/ASA/...`）✅ |
| 中文名 | `item_zh.json` / 物种 `ZH_MAP` ✅ |
| 服务器倍率 | `cfg_rules` 缓存（孤岛 6× 等）✅ |
| 玩家库存 | `lbItemOwnCnt()` / `lbMatServerIdx()`（玩家层级）✅ |

## 5. 风险与对策

| 风险 | 说明 | 对策 |
|---|---|---|
| **同物种多条数据源、数值不同** | `Baryonyx_Character_BP_Escort`（400/2250）vs `_Gauntlet`（100/100）；`Dodo_Aggressive`（ARK 老库 100/100）vs `Dodo_Gen_Outpost_Market`（ASA 30/450） | 按优先级取：**ASA 库优先 → ARK 库兜底**；同一库内优先「名字精确 + fullStatsRaw[2][0] > 50」的主条目 |
| ARK 老库数据可能过时 | 如 Dodo 的 Torpor 在 ARK 库是 100、ASA 库是 30（wikily 是 30，ASA 对） | 同上：ASA 优先级高于 ARK |
| `torpor_rate` 缺省 | 覆盖仅 12%~19% | 缺省用 0.3 + 非默认值小表；UI 标注估算 |
| 物种名对不上 | 存档 `dinoClass` 与 ASB `name` 可能不一致 | 复用现成 `findSpeciesByClass()`（已有 4 级兜底匹配） |

## 6. 建议实施路线

| 阶段 | 动作 | 产出 |
|---|---|---|
| **P0-1** | 写 `lbTameSetup(cls)`：从 `ASB_DB` 取 7 个字段（含 `rate` 相乘），**不再请求 wikily** | 驯服参数 100% 本地 |
| **P0-2** | 一次性抓全站食物表 → 内置 `tame_foods.json`（约 40~60 条，`{en, zh, affinity, base, icon}`） | 食物表 100% 本地 |
| **P0-3** | `torpor_rate` 非默认值小表（从两库导出现有 236 条 + 少量补录） | 眩晕衰减可用 |
| **P0-4** | 用三物种黄金值回归验证（Rex/Baryonyx/Dodo 的 ×17/57m59s/98.69% 等） | 保证与 wikily 一致 |
| **P1** | wikily 只保留「概览正文 / 技能视频」的内容抓取（与计算完全解耦） | 计算零外部依赖 |

**换完之后 wikily 的剩余用途**：概览正文 HTML、技能演示视频、繁殖/收割/建筑等其它 tab 的内容 —— 全是「内容展示」，与驯服计算无关。

## 7. 一句话给决策者

驯服算数要用的「龙的数值」页面里**本来就有**（前端早就在加载 3.7 MB 的物种库），只有「每种食物的亲和度」这张小表需要补一次；补齐后驯服计算器可以**完全离线算**，wikily 只剩看图看字的作用。
