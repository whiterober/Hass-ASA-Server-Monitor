## 二、📖 「C 类 = 公共设施」定义（**重点章节**）

### 1. 定义

**C 类（公共设施）**：由**地图 / 系统生成**、**不属于任何玩家或部落建造**，但仍需出现在 `facilities[]` 中供前端归类展示的可交互物件。

### 2. 判定口径（源码事实）

```
命中 FACILITY_PUBLIC_NAMES[]（源码中集中存放的前缀名单）  →  isPublic = 1
```

采用**前缀匹配**：同一设施的实体类名常带变体后缀，例如
`ArtifactCrate_SE_C`、`ArtifactCrate_2_AB_C`、`ArtifactCrate_ForestKaiju_EX_C`、
`PrimalStructurePowerNode_2951`、`PrimalStructurePowerNode_Damaged_22`。

### 3. ⚠️ 优先级：**玩家设施优先**

判定顺序为 `FACILITY_DICT_NAMES[]`（玩家设施，114 条）**先于** `FACILITY_PUBLIC_NAMES[]`（6 条）：

> **只要命中玩家设施字典，一律不算公共。**

**实例**：`BeeHive_PlayerOwned` 类名里含 `BeeHive`，但它在**玩家设施字典**中 →
输出 `isPublic = 0`（玩家设施），**不会**被前缀误标成公共。

## 三、📖 「A 类 = 玩家设施」定义

**A 类（玩家设施）**：玩家可建造 / 可拥有 / 属于某部落的设施，输出 `isPublic = 0`。

- 名单：源码 `FACILITY_DICT_NAMES[]`，当前 **114** 条（含今日新增的耕地、船体、蜂巢等）
- 与 C 类**互斥**：命中 A 类即**绝不会**被标为 C 类

## 四、🚨 前端最容易踩的坑：**不要用 `isPlayerStructure` 反推公共性**

| 字段 | 真正含义 | 反例 |
|---|---|---|
| **`isPublic`** | **是否公共设施（C 类）** | — |
| `isPlayerStructure` | 是否**玩家建造**（另一套语义） | `BeaverDam`（河狸坝，**自然生成物**）→ `isPlayerStructure = 0`，但 **`isPublic = 0`** |

> `isPlayerStructure = 0` 有**两种**可能：① 公共设施；② **自然生成物**。
> **只有 `isPublic = 1` 才是公共设施。**
>
> 组合关系：
> | `isPublic` | `isPlayerStructure` | 含义 |
> |:---:|:---:|---|
> | 1 | 0 | 公共设施（地图/系统物件） |
> | 0 | 1 | 玩家设施 |
> | 0 | 0 | **自然生成物**（目前仅 `BeaverDam` 河狸坝） |

## 八、前端示例代码

```js
// 读取一张图的设施清单（gz 解压后）
const facilities = data.facilities || [];

const playerFacilities = [];   // A 类：玩家设施
const publicFacilities = [];   // C 类：公共设施
const naturalFacilities = [];  // 自然生成物（目前仅 BeaverDam 河狸坝）

for (const f of facilities) {
  const isPublic = (f.isPublic === 1) ? 1 : 0;            // 旧数据兜底
  const isPlayer = (f.isPlayerStructure === 1) ? 1 : 0;
  if (isPublic)        publicFacilities.push(f);
  else if (isPlayer)   playerFacilities.push(f);
  else                 naturalFacilities.push(f);          // isPublic=0 且 isPlayer=0
}

// class → 显示名：取类名主体（去掉实例号）再查中文映射表
const baseClass = (f) => (f.class || "").split("_C_")[0];
```

> ⚠️ 切勿用 `isPlayerStructure === 0` 判断公共设施 —— 会把 BeaverDam 等自然物算进去。
