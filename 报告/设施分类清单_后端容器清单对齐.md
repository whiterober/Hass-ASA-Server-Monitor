# 设施分类清单 — 后端容器清单对齐（空容器显示）

> 2026-08-15 产出。用途：后端 exe 在 cryo.json 增加 `containers` 容器清单（含空容器），前端据此显示"空的球容器"（与基因设施孤儿容器对齐）。前端唯一事实来源：`LB_CONTAINER_DISP`（dino-import-new.html）。

## 1. 背景

- **球容器**（低温冰箱等）当前只能从 `cryopod`（球）反推——完全空容器（0 球）后端无条目 → 前端不可见
- **基因设施**（基因台/枪）来自 `geneDevices` 独立扫描 → 空容器只要有设备就显示（孤儿容器逻辑）
- 目标：后端输出 `containers` 容器清单（含空容器），前端聚落显示空球容器，与基因设施对齐

## 2. 位置态（非容器，容器清单**不需要**输出）

|------|------|------|
| `released` | 野外放养 | 无容器，按生物坐标 |
| `player` | 玩家背包 | PrimalInventory1，单独 tab |

## 5. 基因设施（geneDevices，独立字段，**不属于** containers 清单）

| type | 中文 | 说明 |
|------|------|------|
| `geneInfuser` | 基因台 | 设备，非容器 |
| `geneScanner` | 基因枪 | 设备，非容器；isBlueprint=1 蓝图在前端已过滤 |

> 基因设施所在容器由 `containerClass`/`containerId` 标注，前端孤儿容器逻辑显示空容器。

## 6. 后端 `containers` 数组建议结构

```json
// cryo.json 顶层新增
"containers": [
  {
    "id": "ba554e66abbf8f4a8500f9c4c1e81f2d",
    "class": "PrimalInventoryBP_CryoFridge_C1",
    "type": "fridge",              // 对齐 §3/§4 类型（前端 lbContainerTypeOf）
    "name": "",                    // 自定义名（无则空）
    "x": -30133.47, "y": 353523.93, "z": -36943.98,
    "tribeId": 1228031745,
    "tribeName": "鱼人族",
    "cryoCount": 0,                // 球数（含空球；0=完全空容器）
    "geneDeviceCount": 0           // 容器内基因设备数（可选）
  }
]
```

- 输出**全部容器**（有球 + 完全空），`cryoCount=0` 即空容器
- `type` 对齐 §3/§4，前端可直接 `lbContainerDisp(type, class)` 显示
- 排除：玩家背包（PrimalInventory1）、野外放养（无容器）

## 7. 前端接入（后端输出后）

1. `lbLoad` 读取 `cryo.containers` → 归一化为 `containers[]`（或并入 recs 作为空容器占位）
2. 聚落详情：空容器（cryoCount=0）参与容器分组显示（空态：◯0 或无数字）
3. `_schemaVer` bump 强制重拉
4. 空容器参与聚落（有床/坐标 → byContainer 归属）

## 8. 边界

- **床/棺材/睡眠舱**：属 structures（非 containers），已参与聚落中心/命名
- **墓碑/广告牌**：属 structures，仅命名来源
- **恐龙背包**（DinoTamedInventoryComponent_*）：特殊容器，走 lbDtcDinoClass 显示，可不在 containers 清单（或输出供对齐）
