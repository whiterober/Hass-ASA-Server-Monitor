# 玩家背包（「玩家携带」TAB）改造方案（dino-import）

> 日期：2026-09-20　范围：**方案文档（不改代码）**
> 目标 TAB（用户指的"背包 TAB"，已定位）：`div#lbTabs` 里的
> `<span class="server-tab" onclick="lbSetTab('player')" title="玩家携带 (N)">`（图标 `HubInventoryIcon`）
> 需求原话：「完全复用其他 TAB 的呈现方式：① 只是聚落列表改成显示玩家当前所有在位置　② 聚落里面的呈现方式完全和其他聚落的一致　③ 同时要显示背包里所有可显示的物品」

---

## 一、需求映射（对齐到「玩家携带」TAB）

| 需求 | 现状（玩家携带 TAB） | 目标 |
|---|---|---|
| ① 列表改为「玩家当前位置」 | 现在**没有列表层**：进来直接铺**生物卡瀑布流**（`playerCarried` 全部） | 第一层 = **玩家位置卡列表**（每位玩家一张卡：角色名/服/坐标/在线态），与服务器 TAB 的**聚落卡网格**同款外壳 |
| ② 内部呈现与聚落一致 | 现在没有"点进去"的层级 | 第二层 = **复用聚落详情外壳**（`#lbSettleDetail` / `#lbSettleBody` + 返回按钮 + 区域 chip + 容器手风琴） |
| ③ 显示背包所有可显示物品 | 现有仅在**物品模式**（`LB.pickItem`）下显示"该物品的实例卡"（`lbPickPlayerItems()`） | 详情主体新增**物品总览**：列出背包内全部物品（按类型聚合 ×N 或按容器/网格），过滤"不可显示"项 |
| 总纲「完全复用其他 TAB」 | — | 复用的对象 = **服务器 TAB（聚落视图）** 的两层结构与其渲染函数，不新造 UI |

## 二、现状调研（源码事实 + 实服实测）

### 2.1 Tab 与渲染管线

| 环节 | 位置 | 说明 |
|---|---|---|
| Tab 渲染 | `dino-import.html` **L9940** | `LB.tab==='player'` 时高亮；图标 `HubInventoryIcon`；`title="玩家携带 (N)"`；仅当 `playerCarried.length` 或基因枪存在时出现 |
| Tab 切换 | **L13329** `lbSetTab(tab)` | 只做 `LB.tab = tab; lbView();`（无独立路由） |
| 视图分支 | **L9970-10010** `if(LB.tab==='player'){…}` | ① 玩家基因枪卡（`myScanners`）② 携带生物卡瀑布流（`lbPushPlan('', peArr, peCnt, scnHtml)`）③ 物品模式实例卡（`lbPickPlayerItems()`）；`tabLabel='🎒 玩家携带'` |
| 携带数据 | **L9877-9882** | 遍历各服 recs，`lbContainerTypeOf(r)==='player'` 的容器（背包）内的生物 → `playerCarried` |
| 背包物品通道 | **L9409** `lbPickPlayerItems()` | 走物品索引 `D.itemsByServer[sv].byCid[cid]`，`ix.playerCids[sv][cid]` 已标出"玩家背包容器"（L9375） |
| 背包容器识别 | **L4123-4124** | `containerClass` 含 `PrimalInventory1` ⇒ 类型 `player` |

### 2.2 要被"复用"的对照物（服务器 TAB = 聚落视图）

```
lbClusterSettles(settleGroups)     ← 聚落聚合/拆组（聚合框 / 单聚落 / 离散）
   └─ 聚落卡（小地图 + 右侧按钮列）
        └─ lbOpenSettle(btn)  (L10530)
             └─ #lbSettleDetail / #lbSettleBody   (模板 L10081，含「返回」按钮)
                  ├─ lbFacAreasBuild()  (L12686)  分层 + DBSCAN 建区
                  ├─ _mkAreaChips()     (L11955)  区域内 chip（无名按类型 ×N 聚合）
                  └─ 容器手风琴 / 放出组 / 区域命名牌子
```

### 2.3 数据源（玩家位置 & 背包）

| 数据 | 来源 | 实测/备注 |
|---|---|---|
| 玩家身份 | cryo `players[]`：`{pid, eosId, name, characterName, roles}` | Isl **46 条**；**无坐标字段** |
| 位置（在线） | `LB.SVC_PLAYER_POS` → 逐服 `script.player_pos`；新架构读 `LB_STATUS + '/player_pos_status_<abbr>.json'` + 免认证 `/api/player_pos` | 现有「追踪野生龙」已在用（L16716+），可直接复用 |

| 背包物品 | `lbPickPlayerItems()` / `D.itemsByServer` | 已可用 |
| 物品显示元数据 | `item_zh.json` + `itemstats.json` + `icons2.json`/`webp_map.json` | 三表已随 CF 本地供给 |

## 三、方案对比

| 方案 | 做法 | 优点 | 代价 / 风险 | 评价 |
|---|---|---|---|---|
| **A 两层化改造（推荐）** | 「玩家携带」分支改为**两层**：第一层玩家位置卡列表（复用聚落卡外壳与网格）、第二层复用聚落详情外壳（把 `lbOpenSettle` 的外壳段抽成 `lbOpenEntityDetail(opts)`，聚落/玩家共用）；详情主体 = ①背包物品总览（新增）②按需保留现有生物卡/基因枪块 | 完全满足三条需求；聚落路径零回归（同函数参数化）；后续可扩"恐龙/容器"视图 | 需重构 `lbOpenSettle`（1 处拆壳）；玩家列表需新增位置数据源与排序 | ✅ 推荐 |
| **B 轻度叠加** | 保持现有生物卡瀑布流，只在顶部插入"玩家位置"分组 | 改动最小 | 仍是"一页铺开"，没有"点进去"的第二层 ⇒ 不满足需求② | ⚠️ 备选 |
| **C 新增第 4 个 tab** | 新 tab"玩家位置"，原"玩家携带"保留 | 零风险 | 与"完全复用/改造成一致"的意图不符；tab 数变多 | ❌ 不推荐 |

**推荐 A**：与用户总纲一致 —— 复用 = 用**同一套组件**，而不是抄样式。

## 四、方案 A 实施要点（确认后开工）

1. **抽公共详情外壳**（先做，零行为变化）
   - 把 `lbOpenSettle`（L10530）里「打开 `#lbSettleDetail` + 返回按钮 + 写 `#lbSettleBody`」的片段抽为 `lbOpenEntityDetail({ title, subtitle, bodyHtml, backTo })`；`lbOpenSettle` 改为调用它 ⇒ 聚落行为不变，便于回归对照。
2. **第一层：玩家位置卡列表**（需求①）
   - 数据：`players[]`（全员）× 各服 `PrimalInventory1_*` 容器坐标 × 在线 `player_pos`；
   - 卡片：复用聚落卡外壳（小地图/坐标/右侧按钮列的**简化版**：头像/角色名 + 服 + 坐标 + 在线徽标 + "背包 N 件"）；
   - 排序：在线优先 → 距该服聚落中心由近到远；跨服同名按 `eosId` 聚合、多服分条。
3. **第二层：详情内容**（需求②③）
   - 外壳/返回/chip 布局/容器手风琴 = **复用**；
   - **物品总览（新增）**：`lbPickPlayerItems()` 同源数据 → 按类型聚合（`×N`，复用 `_mkAreaChips` 的 `_grp` 逻辑）→ 点开看实例明细（名称/数量/图标/属性，复用 `lbItemCardsHtml`）；
   - **可显示过滤**：`item_zh` 或 `icons2` 或 `itemstats` 任一命中 ⇒ 可显示；三者皆无 ⇒ 隐藏（并在标题旁标"已隐藏 N 件内部物品"）；
   - 现有**生物卡瀑布流 / 基因枪**保留为详情内的独立分组（不丢功能）。
4. **区域算法不套用**：玩家背包没有"区域/牌子命名"语义 ⇒ 详情内**不做** `lbFacAreasBuild`（如需"按容器分组"，用容器手风琴即可）。
5. **性能**：物品明细按需加载（进入详情才取该玩家 `byCid` 的物品）；玩家列表只读 `player_pos_status_<abbr>.json` 静态文件（沿用现有轮询），不逐服 RCON 直查。

## 六、风险与兼容

- **回归风险**：动 `lbOpenSettle`（聚落主线）⇒ 必须做「改动前后聚落详情对照」（区域数/命名/容器条目）。
- **缓存**：结构调整 ⇒ 递增 `LB_SCHEMA_VER`（当前 17），旧用户强刷自动重建。
- **隐私/权限**：背包属他人 ⇒ 建议沿用现有匿名口径（`我的 / 外部`），必要时用 `lbPlayerTribes` 过滤"只看本部落"。
- **入口可见性**：Tab 仅在 `playerCarried.length || 基因枪 || 物品模式有结果` 时出现（L9940）⇒ 改成"玩家位置列表"后应改为**只要有玩家数据就显示**。
