# ASA 生物属性计算：ASB 食物公式精度问题报告

## 一、背景

### 目标
从 ASA `.ini` 导出文件反推生物的 **野生/家养等级分配**（wild/dom levels），然后导入 Wikily.gg。

### 数据来源
- **物种参数**：`values.json`（ASB / ARK Smart Breeding 格式，1049 个物种）
- **生物实例**：`.ini` 文件（`[Max Character Status Values]` 段）
- **游戏实测**：TEK 望远镜（确认等级分布）

### 公式（ASB / ARK Wiki）
```
V = (B × (1 + Iw × w) + Ta) × (1 + Id × d) × (1 + Tm × TE)
```
- `B`：基础值
- `Iw / Id`：野生/家养每级增幅
- `Ta`：加性驯服加成
- `Tm`：乘性驯服加成
- `TE`：驯服有效性（0~1）
- `w / d`：野生/家养等级

### 总体策略
1. 眩晕反推 `totalW`（总野生等级）——眩晕 = B × (1 + Iw × totalW)
2. 对每个属性枚举所有合法 (w, d) 组合（ASB 公式与 .ini 显示值偏差 < 容差）
3. 动态规划：找 sum(w) = totalW 的组合，最小化总偏差

---

## 二、已解决的：近战公式修正

近战 `fullStatsRaw[8]` 的 ASB 公式最初算出来严重偏高。

### 例子
**Bloodstalker**（ASB `[1, 0.05, 0.1, 0.5, 0.2]`，TE=97.5%）
- 实测：37w / 0d → 317.7%
- ASB 公式：`(1×2.85 + 0.5) × 1.195 = 400.3%` ❌

### 修正
根据 ARK Wiki 和实测推导，近战需要两个**通用常量**（对所有生物适用）：

```
近战值 = (B × (1 + Iw×w) + Ta × 0.14) × (1 + Id×d) × (1 + Tm × 0.44 × TE)
```

- `0.14`：近战加性驯服系数
- `0.44`：近战乘性驯服系数

验证 Bloodstalker：`(2.85+0.07) × 1.0858 = 317.1%`（TE 取整后 317.7%）✅  
验证 Oviraptor：`(3.05+0.14) × 1.176 = 375.1%` ✅

**近战问题已解决。**

## 三、未解决的：食物公式精度问题

### 问题描述

近战修正后，健康/耐力/氧气/负重/近战已全部正确，但**食物（food）的 (w, d) 分配持续出错**。

### 具体例子

**Oviraptor（"切工"，等级 243）**

| 来源 | .ini 值 | ASB fullStatsRaw |
|------|---------|------------------|
| 食物 | `食物=16765.7344` | 未知（Iw/Id 约 0.1） |

```json
{
  "blueprintPath": "/Game/PrimalEarth/Dinos/Oviraptor/Oviraptor_Character_BP.Oviraptor_Character_BP",
  "fullStatsRaw": [ /* 食物在索引 4，具体值未知 */ ]
}
```

游戏实测（TEK 望远镜）：
- 食物：**35 野生 + 26 家养**（共计 61 级）

### 偏差

ASB 公式对 Oviraptor 食物计算：
- `(35, 26)`：公式值偏离 .ini 显示值约 **50+**（绝对偏差）——超出容差，**被排除**
- `(15, 55)`：恰好匹配，**进入候选池**

结果：DP 选 (15, 55) 而非 (35, 26)。

### 根因分析

食物显示值 **16765** 是一个大数，而 ASB 公式中的 `Iw`/`Id` 是小数（约 0.1）。

对 (35, 26) 和 (15, 55)：
```
(35,26): B × (1+3.5) × (1×2.6) × tameMult = B × 16.2 × tameMult
(15,55): B × (1+1.5) × (1×5.5) × tameMult = B × 16.25 × tameMult
```

两式的计算结果相差约 **0.3%**（16.25/16.2 = 1.003）。但在 16765 这个基数上，0.3% = **约 50 的绝对偏差**。

ASB 的 `B`/`Iw`/`Id` 数据只要与游戏实际值有 **0.1%~0.3% 的误差**，就会在食物这种大值属性上产生巨大绝对偏差（50~150），远超容差（5~16）。

而健康（1064）、耐力（648）等小值属性受同样误差的影响较小（偏差仅 1~5），仍在容差内。

### 已尝试的方案（均未根治）

| 方案 | 结果 |
|------|------|
| 扩大绝对容差（1.0 → 5.0 → 8.4） | (35,26) 进候选但 (115,3) 等也进入，DP 选错 |
| 相对容差（0.01%~0.05%） | 太紧漏选，太松多选 |
| 单属性野生上限（maxW = totalW/4） | 排除 (115,3) 但 (15,55) 仍在，DP 选 (15,55) |
| 排序优先高野生 | 无效——(35,26) 根本没进候选池 |
| 食物不吃 DP，用 totalW − sum(other) | 可行，但 totalW 来自眩晕反推，Oviraptor 的 ASB 眩晕数据也偏低 20 级 |

### 当前最优结果

```
health  33w/0d   ✅
stamina 44w/0d   ✅
oxygen  32w/0d   ✅
food    15w/55d  ❌（应 35w/26d）
weight  31w/0d   ✅
melee   41w/0d   ✅（近战公式修正后）
```

## 四、核心矛盾

**ASB 物种数据（B/Iw/Id/Ta/Tm）存在 0.1%~1% 的微小误差**。

- 对小值属性（健康几百、耐力几百）：偏差 1~5，容差 1~2 可覆盖
- 对大值属性（食物上万）：偏差 50~150，容差不够

这不是代码 bug，是**数据源精度问题**。ASB values.json 提取自 ASE 版本，与 ASA 实测存在系统性细微偏差。

## 五、可能的解决方向

1. **用 ASA 专用数据**替代 ASE 的 values.json（如 `ASA-values.json`，但覆盖不全）
2. **对食物使用独立容差策略**（如更宽的相对容差 + 更强的约束条件）
3. **从 CharacterLevel 反推总等级**替代眩晕反推（CharacterLevel 在 .ini 中直接可用）
4. **接受食物公式近似**——允许 (w,d) 与游戏有 ±2 级偏差

---

## 六、技术栈

- 前端单 HTML 文件（`dino-import.html`，~25KB）
- ASB 公式 + 动态规划（6 属性 × ~300 候选 = ~10^4 状态）
- 数据源：`values.json`（2.5MB, ASE 1049 物种）+ `ASA-values.json`（1.1MB, ASA 新增物种）
- 输入：ASA `.ini` 导出文件（WebDAV NAS）
- 输出：Wikily.gg 导入（Tampermonkey 脚本 POST `wild_levels`/`dom_levels`）
