## 1. 场景与起点

**设定**：单母群（共享 0/0 母池，n 只，母群规模分档见第 4 节）× 全能公（血/攻/负重基础全顶格）。

**现状（已发生）**：某批繁殖孵出三只变异公仔，三属性变异**分散在三个子代**：

| 子代 | 性别 | 变异落点 | 状态 |
|------|------|----------|------|
| 仔甲 | ♂ | 血 +1 | H 候选 |
| 仔乙 | ♂ | 负重 +1 | W 候选 |
| 仔丙 | ♂ | 攻 +1 | M 候选 |

**目标**：后续叠变异效率最高——最终把三属性都叠高（如 5H5W7M 级别）并收敛到成品种公。

## 3. 统一框架与推进形态（v4 重构）

### 3.0 框架统一：没有"分线滚动"，只有「推进形态 × 收拢时机」

- 任何"把若干属性绑一起叠"，都等价于：**先用合体（普通繁殖 55% 继承，不消耗变异机会）把绑定属性收拢成一只种公，再在这只种公上叠**；
- 玩家想让种公带几个高属性（k）、叠哪个属性，随时用合体/换代决定——"手动关闭独立属性" = 换用不带该属性的种公（0/0 母换代或另合一只）；
- 因此**不存在"分线滚动自举"这类独立策略**。候选空间只有两个自由度：**① 推进形态 k（种公同体高属性数）；② 收拢时机（何时把分散变异/低层变异合体）**；
- 玩家实践 = 一种具体的调度：轮 1 先把 H/W 收拢 → 以 **k=2 形态推进 H/W** → M 保持 **k=1 形态**（串行占池）→ 各到目标后**收尾收拢** M 进成品。k=3 只出现在最终成品（收拢产物），不作为推进形态。

### 3.1 推进形态成本：衰减来自同体属性数 k，与层数无关（用户指正）

> ASA 属性继承 = 每个属性独立一次 **55% 取父母较高值**（`thRow` / `lbRouteInhP`）。判定对象是该属性的**数值**，不是逐条变异点 → **叠了多少层不影响继承概率**：+5H 龙与 +1H 龙去合体，成功率相同。

推进一层（变异命中目标 +2，且同体其余 k-1 个高属性保住）的**单蛋成本**（P_mut≈7.6%）：

| 推进形态 k | 推进"任一高属性" | 只推进指定单属性 | 说明 |
|---|---|---|---|
| k=1 单线 | 145 蛋/层 | 145 | 命中 1/11、无额外保留负担；分布完全可控 |
| k=2 两属性同体 | **132 蛋/层** | 263 | 命中池 2/11 × 需保 1 属性(55%) → 净最优 |
| k=3 三属性同体 | 159 蛋/层 | 478 | 3/11 命中增益被 55²≈30% 双保留吃掉 → 比 k=1 还差 |

> **要点**：① k=2 是推进形态中最省的（命中池与保留负担的对消最优）；② **k=3（全能种）只适合做收拢/成品，不适合做推进形态**——这正是玩家实践把 H/W 收成 k=2、M 单独 k=1、而不是一开始就三合一的原因；③ 衰减全部来自"同体属性数 k"，**与层数无关**。

### 3.2 玩家实践在统一框架下的定位

- **轮 1 收拢 H/W（2 属性集中，55²≈30%）** → 之后以 k=2 形态推进（每层 132 蛋档）→ 需要 H/W 同体（成品要同时高血高负重），早收拢早享受 2/11 命中池；
- **M 与 H/W 无互依** → 保持 k=1 单线（每层 145 蛋档）并行推进，不与 H/W 抢合体节奏；
- **兄弟筛留 + 融合配平**：k=2 推进会产生"一侧领先"的兄弟（2H1W / 1H2W），用兄弟融合把落后侧补上——融合不消耗变异机会，只耗母群轮次；
- **收尾**：M 到目标后再收拢 M（最终一次 55² 或 55³，可分步），得 k=3 成品——**k=3 只在成品这一刻出现一次**。

> **粒度结论 = 平衡「绑得越多命中池越大(k/11)」vs「同体越多每轮全保越难(55^k)」**：推进形态 k=2 最优、k=1 次之、k=3 最差；收拢则集中在"成品/切换种公"时机一次性完成。

### 3.3 与主报告结论的关系（重要澄清）

- 主报告「全能公叠变异命中率 n/11 优于单线 1/11」针对的是**变异落点命中**（一只公同叠 n 属性时落点池变大）——那只影响**叠变异期每轮的命中概率**；
- 但**合体/收拢**是另一码事：成功率 = 55%^同时继承的属性数，**与层数无关**，也与"推进时落点池多大"无关；
- **两阶段认知**：推进期应让**同体高属性数 k 尽量小**（k=1 或 2），避免 k=3 时每轮 55³ 全保；收拢期是**一次性继承动作**，层数不构成障碍，失败重试即可、不倒退。

## 4. CD 约束分档模型（v4 新增，用户确认口径）

### 4.1 现实口径

- **一轮 = 一次收蛋 = 1 CD**（母群交配冷却 6-8h，本报告取中值 ~7h；1 天 ≈ 3.4 CD）；
- **严格一 CD 一用途**：一个 CD 只做一个配种组合（一只公种 × 全部母池），不拆群；
- 母群规模 **n 分档**：小 n=10 / 中 n=30 / 大 n=100（一次 CD 收 n 蛋）；
- 推进率以"每 CD 至少产出 1 只可用"计：q(n) = 1-(1-p)^n。

### 4.2 每层所需 CD（期望）

| 推进形态 | 单蛋 p | 每层 CD（n=10 / 30 / 100） |
|---|---|---|
| k=1 单线 | 0.00691 | 14.9 / 5.3 / 2.0 |
| k=2 任一（含双支线配平） | 0.0076 | 13.6 / 4.9 / 1.9 |
| k=3 任一 | 0.00627 | 16.3 / 5.8 / 2.1 |

### 4.3 到 5H5W7M（14 次推进 + 收拢）所需 CD 与天数（单侧口径）

| 策略 | n=10 | n=30 | n=100 |
|---|---|---|---|
| A 轮流单线（k=1 逐属性推到满，再收拢） | ≈219 CD（≈64 天） | ≈84 CD（≈25 天） | ≈38 CD（≈11 天） |
| B 玩家式（H/W k=2 双支线 ×1.3 配平 + M k=1 + 收拢） | ≈234 CD（≈69 天） | ≈86 CD（≈25 天） | ≈34 CD（≈10 天） |
| C 融合 AB（轮流推进 + 顺带合体收拢 ≈10 CD） | ≈225 CD（≈66 天） | ≈85 CD（≈25 天） | ≈36 CD（≈10.5 天） |

> 若按**双侧变异 14.6%** 口径，p 翻倍、q 提高，以上天数约**减半**（大 n 档 ~5 天量级），才与"11 轮数天完成"的实践量级接近。

### 4.4 结论（CD 视角）

1. **小母群（n≈10）任何策略都要 2 个多月** → 现实不可行。玩家能短期完成，说明母群规模必须大（n≥几十、每窝多蛋）或存在多批母群；
2. **大母群下三策略所需 CD 数几乎相同（差异 <20%）** → 窝内 n 蛋并行把策略差异基本抹平；**真正决定天数的变量是 n（母群规模），其次才是策略与变异口径**；
3. CD 约束不改变第 3 节结论：推进形态仍是 k=2 / k=1 最优，k=3 只做收拢。

## 5. 融合 AB 方案验证（v4 新增，用户提出）

### 5.1 方案原述

> 出现变异分散就**轮流做公种**（每只 k=1，落点 1/11 相对低）；同时用**本体或产出的非变异子代**进行**并行**与**全能公种**（顺带合成全能体）；**合出全能种即退出轮流**；叠变异流程**全程不断**。

### 5.2 验证：成立的部分 ✅

- **合体/收拢不消耗变异机会**（普通繁殖 55% 继承，不触发变异计数）→ "顺带合成、全程不断"成立；
- **材料顺带可得**：轮流推进每窝都大量产出"继承了自己 +1 属性但无新变异的仔"（10 蛋窝 ≈5 只/窝），攒齐带 H/W/M 的公母材料只需几窝；三合一全能体期望 ~11 次尝试（每次一窝 ≈10 CD 当量），相对总 CD 是小头；
- **避免"叠满再集中"的停机断流**：把收拢摊进推进滚动，是该方案的真实价值（与玩家轮 1 收拢 H/W 同理，只是推广到全属性）。

### 5.3 验证：不成立 / 需校正的部分 ⚠️

- **"合出全能种(k=3)即退出轮流、切换 3/11 高命中推进更快"不成立**：k=3 推进任一属性 159 蛋/层（n=100 时 q≈47%），比 k=2（q≈54%）与 k=1（q=50%）都差；只推进指定单属性更是 478 蛋/层。3/11 命中池被 55² 双保留吃掉；
- 因此**全能种(k=3)的正确角色是收拢/成品，不是推进主形态**；若"退出轮流"指切换成 k=3 推进，CD 与蛋耗都更差；
- 若把"关闭独立属性"理解为"推进时把全能种拆回低 k（换不带它的种公）"→ 那又回到 k=2/k=1 推进 + 收拢时机问题，与玩家实践等价；
- 单母群 + 一 CD 一用途下，"并行"不能同 CD 双配种组合，只能串行轮流（见 4.1）；材料"并行"攒取是副产品，不占额外 CD，但**执行合体配种本身仍占 CD**。

### 5.4 结论

融合 AB 方案的**工程机制**（顺带合体、全程不断、不浪费分散变异、避免末尾停机集中）成立且有价值，是玩家实践的合理解释之一；但"合出全能即更快推进"不成立。**最优调度 = 分散期轮流/并行推进（k=1）→ 尽早把互依属性收成 k=2 推进 → 独立属性保持 k=1 → 收尾收拢成 k=3 成品**；CD 约束下策略差异被大母群抹平，母群规模 n 才是时间主变量。

## 6. 结论（v4）

1. **概念口径（用户指正后）**：全合体/收拢 = 把已分别叠好的属性集中到一只；成功率 = 55%^同时继承的属性数，**与已变异层数无关**。
2. **框架统一（v4）**：没有"分线滚动 vs 集中后叠"之分——所有路线 = **推进形态 k（种公同体高属性数）× 收拢时机**；玩家可随时用合体/换代决定种公属性集（=手动关闭不叠的属性）。
3. **推进形态效率**：k=2 ≈132 蛋/层 最优、k=1 ≈145 次之、k=3 ≈159 最差；**k=3（全能）只做收拢/成品，不做推进**。衰减来自同体属性数 k，与层数无关。
4. **CD 约束（v4）**：成本 = CD 数 × 6-8h；一 CD 一用途；小母群（n≈10）任何策略 2 个月+ 不可行；大母群下策略差异被抹平（<20%），**n 才是时间主变量**；按双侧口径天数约减半。
5. **融合 AB 方案（用户提出）**：工程机制成立（顺带合体、全程不断、不耗变异机会）；"k=3 全能推进更快"不成立。玩家实践（先收 H/W 成 k=2、M 保 k=1、收尾收拢 M）仍是实证最优调度。

> 一句话：**别把分散变异作废重赌——收拢只是 55% 一次判定，层数不影响。也别把 3 属性从 +1 就绑一只龙当推进形态（每轮全保太低）——把注定同体的 H/W 收成 k=2 推进、独立 M 保 k=1 并行，收拢/合体顺带在滚动里做（不耗变异机会、全程不断），母群够大才谈得上速度。这是实践验证的高效叠法。**

# 🍚 通俗易懂版（给没空看专业表的你）

> 以下完全用大白话，不打术语、不摆公式。先看这节，能懂就不用回去啃上面了。

## 你在干什么（先对齐一下场景）

- 你手里有：**一群"干净的母龙"**（0/0，不带变异），外加**三只刚孵出来的变异公仔**：
  - 仔甲 = 血多（+1 血）
  - 仔乙 = 负重好（+1 负重）
  - 仔丙 = 攻击高（+1 攻）
- 你想干的事：把这三样**都越养越高**（养到 血5层、负重5层、攻7层 那种级别），最后攒成一只"三样全都要"的超级种公。
- 报告想回答的问题：**三样分开在不同龙身上，怎么叠最快、最不容易白干？**

## 打个比方：三兄弟搬砖摞高塔

把"叠变异"想成**三兄弟各自往塔上摞砖**：

- 每只公仔手里已经各有 **1 块变异砖**（仔甲是血砖、仔乙是负重砖、仔丙是攻砖）。
- 母群 = 一台**不停免费出蛋的机器**。每颗蛋都有点概率"带回来一块新砖"（你想要的属性砖）。
- 想让血到 5 层，叠变异时就要**5 次都拿到血砖**——每拿到一层，就从这窝蛋里挑出"血数值更高"的继续当种（单属性继承 55%，不是每层都单独赌一次）。

难点分两处（注意：**不是"层数越多越难"**）：

1. **叠变异期——一只龙"同时带的属性种类"越多，每轮越难**：每孵一颗蛋，每种高属性都是 55% 概率保住。只带 1 种高属性 → 55%；同时带 2 种 → 约 30%；同时带 3 种 → 约 17%。某一属性没保住，这颗蛋就只能当"缺一层"的次品（属性间连座，这一层重来）。**但每种属性的层数（+1、+5…）不影响概率**——判定是按"这个属性的数值高不高"一次定的，不是按层数一条条算。
2. **收拢/合体是另一回事，而且不难**：把已经分别叠好的属性集中到一只龙，每个属性也只是一次 55% 判定。叠了 5 层再集中，和只叠 1 层再集中，**成功率一模一样**——层数只决定集中后数值高不高，不决定集中容不容易。真正要想的只是：**最后集中那一刻要同时继承几个属性**（3 个一把赌 ≈17%；分两步 ≈30%×55%）。

## 那到底怎么叠最快？（一句话版）

- **"合体"是免费的**：它只是普通配种按 55% 继承，不烧变异次数、不打断你叠变异的节奏——所以**合体可以顺路做**，不用专门停下来；
- **叠的时候别让一只龙背太多属性**：一只龙同时带 3 种高属性去滚，每窝要 3 个都保住（约 17%），慢；带 2 种约 30%；只带 1 种 55%。两两绑（血+负重）是效率甜点，攻单独一路；
- **最后把攻也收进来**：那时只是一次 55% 判定的事，失败重试即可；
- **现实提醒**：一次收蛋要等 6-8 小时（交配 CD），而且一次只能让一个公种配整群母。所以**母群要够大**（一窝能出几十颗蛋）才有意义——母群小了，怎么叠都是按月算。

## 玩家是怎么做的（已实战验证）

把属性按"**这辈子是不是必须长在同一只龙身上**"来分组：

| 属性 | 为什么这么分 | 怎么叠 |
|------|------------|--------|
| **血(H) + 负重(W)** | 成品要**同时**高血高负重 → 它俩注定同体，早绑早省事 | 先把它俩合到一只龙身上（免费合体），再让它俩一起滚：命中池 2/11，比单属性 1/11 顺手 |
| **攻(M)** | 跟血/负重**没有必须同体**的关系 | 单独一只种龙并行（轮流用母群），每次 +1 攻 |

实战结果：**11 轮干到 5H5W·7M**（血5层、负重5层、攻7层），平均每轮推进 1.5 个属性 +1。

关键心态：合体那一步有大约 30% 概率失败（两种属性都要保住 ≈ 55%×55%），但**失败只浪费一轮出蛋时间，砖不消失、塔不倒，重试就行**——这也是"顺路合体、全程不断"能成立的底气。

## 一句话记住（浓缩版结论）

> **别把散装的三只变异公仔作废重赌——收拢只是 55% 一次判定，层数不影响。也别把 3 种属性从 +1 就绑一只龙当推进（每轮全保太低）——把"必须长在一起的属性"（血+负重）先合体成一条线边滚边融，"能分开的"（攻）单独一路并行，攻到位再收进来（免费合体、失败重试）——这是实践验证最高效、且全程不断的叠法。母群够大（一窝几十蛋）才谈得上快。**

## 三个高频疑问速答

1. **为什么不把血/负重/攻从 +1 就全绑一只龙身上滚？**
   不是"层数越高越难"，而是**同时带的属性种类越多、每轮越难**：3 种高属性同体时每轮要 3 个都保住（约 17%），还互相连座。叠变异期应让"一只龙同体高属性 ≤2"，独立的拆出去单线并行。
2. **为什么血和负重非要绑一起叠？**
   因为你要的种公**必须同时**高血高负重，它俩注定同体。既然注定同体，不如早合体早绑线滚——每轮命中池是 2/11（血或负重都算推进），比分开两条 1/11 各滚还顺手，还能在滚动里顺手完成它俩的合体。
3. **叠到很多层再去收拢，是不是很难？**
   不难。收拢时每个属性只是一次 55% 判定，**跟叠了多少层没关系**（+5 层和 +1 层一样好继承）。"叠得越高越难集中"是误解——难只难在叠变异期别让一只龙背太多属性种类。
