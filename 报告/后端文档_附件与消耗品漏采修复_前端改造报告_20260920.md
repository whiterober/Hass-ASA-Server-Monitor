## 二、对我们前端的实际影响（逐条 + 代码定位）

### A. 肥料等"数量未记录"的消耗品 —— ❌ **会被前端全部过滤掉**

| 环节 | 现状代码 | 行为 |
|---|---|---|
| 判空 | `lbIsEmptyItem()`（L7587 起） | 非装备类 ⇒ `return (Number(it.quantity)||0) <= 0;` ⇒ **quantity=0 一律判"空"** |
| 内容判定 | `lbGroupInvHas()`（L7615） | 内含 `if(lbIsEmptyItem(it)) continue;` ⇒ 该容器**判为无内容** |
| 计数 | `lbInvAgg()`（L7638） | 同样 `lbIsEmptyItem` 过滤 ⇒ 徽章不计数 |
| 龙背包并入 | v3456 新增 `_vis` 过滤 | 可见物品为 0 ⇒ **该龙背包组根本不显示** |

> ⇒ 后端新收录的**肥料 1546 条**（Isl）在我们这里**依然不可见**；文档第七节第 4 条明确要求「**不要按数量过滤**」，与我们现在的实现直接冲突。

**连带影响**：肥料主要挂在 `DinoTamedInventoryComponent_Beetle`（蜣螂）×817 ⇒ 修 A 之后，「蜣螂背包」会自动变成**有内容的容器组**（现有 v3448~3457 逻辑自动生效，无需额外开发）。

### B. 无品级的真实装备 —— ❌ **同样被过滤**

`lbIsEmptyItem` 现有豁免（v1197）：

```js
var LB_SP_EQUIP_KINDS = { saddle:1, armor:1, weapon:1, tek:1 };
...
if(LB_SP_EQUIP_KINDS[String(it.kind||'')] && Number(it.rated) > 0) return false;  // 装备类实物（数量无意义）
return (Number(it.quantity) || 0) <= 0;
```

两个缺口：

1. **`attachment` 不在白名单**（文档 2.2 的 kind 全集含 `attachment`；生物附件板车/马达疑似落此类或 `armor`）；
2. **要求 `rated > 0`** —— 后端本次收录的正是「**没有品质属性**」的装备（板车 8 / 马达 5 / 铠护犬鞍 4）⇒ `rated=0` ⇒ 仍判空。

### C. 新增 `kind='geneGun'` —— ⚠️ 前端**零处理**（grep 命中 0）

| 影响点 | 说明 |
|---|---|
| 类型徽章 | `lbTypeBadgeHtml()`（L7698）按 kind 映射，**未知 kind 落 `other` 兜底**（不崩，但语义不准） |
| 双通道重复风险 | 前端既有的基因枪通道来自 `cryo.json.gz → geneDevices[]`（`LB._geneDevices` / `LB._playerScanners` / 「孤儿容器」基因枪卡）。现在 `items[]` 里**同一把枪**也会出现 ⇒ 容器组里可能**同时**出现"物品形态的枪"与"基因枪卡形态的枪" |
| 数量语义 | 文档样例 `quantity=0`、`rated=0`、`qidx=-1` ⇒ 也会被 A/B 的过滤命中（不修则根本不出现，反而"看起来没重复"） |

> ⚠️ 注意：**修完 A/B 之后，C 的重复才会显形**。所以 A/B 与 C 必须一起评估。

### D. 新增物品的**中文名与图标缺失** —— ⚠️ 会显示英文/破图

`lbItemMeta()`（L12669）只有在 `LB_ITEM_ZH` 命中候选键时才返回 `zh`/`icon`；未命中 ⇒ `zh=''`、`icon=''`（英文由类名拆词兜底、图标走破图占位）。

实测（`汉化/item_zh.json` grep）：

| 类名 | 表内是否有键 |
|---|---|
| `PrimalItemConsumable_Fertilizer_Compost` | ❌ 无（仅有 `Re-Fertilizer` 那条无关键） |
| `PrimalItem_WeaponGeneScanner` | ❌ 无 |
| `PrimalItemArmor_SaddleCart` | ❌ 无 |
| `PrimalItemArmor_ZiplineMotor` | ❌ 无 |
| `PrimalItemArmor_DinoCompanionSaddle_Doggo` / `DinoCompanion_Gear*` | ✅ 有（L3902 起一整组） |

### E. 无影响项 ✅

- `blueprint` / `ammo` / `resource` 零变化 ⇒ 我们的蓝图体系（`lbIsBp` / `lbIsFixedRecipeBp` / 书柜去重）**不用动**；
- `geneDevices[]` 不变 ⇒ 现有基因枪槽位/物种展示**不受影响**；
- 容器归属字段（`containerId/Type/Class/Tribe` + 坐标）语义未变 ⇒ 聚落归属（`lbSettlementOf`）与龙背包并入（v3448~3457）**不用动**。

## 三、建议改法（按优先级）

### 🔴 P0-1：`lbIsEmptyItem` 放宽（核心，一行判断逻辑）

**目标**：把"数量未记录"与"空槽残留"区分开 —— 后端已保证**空槽不再收录**（文档 5.1 表：`ItemQuantity` 存在且为 0 ⇒ 不收录）。

两种方案：

| 方案 | 做法 | 优点 | 风险 |
|---|---|---|---|
| **A（保守）** | 只对文档点名的 class 白名单豁免（`Fertilizer_Compost` / `Seed_SBear` / `OwlPellet` / `WaterJarRefill` …） | 影响面最小 | 后端以后每加一类都要改前端；漏采类问题反复出现 |
| **B（推荐）** | `kind==='consumable'` **整体**不再按 quantity 判空（保留 `isBlueprint` / 固定配方 / trait 判定） | 与后端新口径一致，一次到位 | 若后端某天又收录空槽，会出现"数量 0 的消耗品"；**缓解**：这类物品在容器里本来就常是 0 数量（肥料），且数量显示走 `lbFmtQty`（0 不显示数量，不会显示"×0"） |

**建议**：先按 **B** 实现，但**加一条后端契约注释**（引文档 5.1），万一出现噪声再退到 A。

同时 **P0-1b：装备类豁免补齐**
- `LB_SP_EQUIP_KINDS` 补 **`attachment:1`**；
- 去掉 `rated > 0` 前置条件（改为"装备类实物一律算有内容"），理由：后端已把"无品质真实装备"纳入，`rated=0` 是其常态；
- ⚠️ 该改动会让**旧 `.gz`（未重算）**里可能残留的"设施印痕缓存装备"重新出现 —— 上线前需确认后端已部署+重算（见第四章）。

### 🔴 P0-2：基因枪去重（与 P0-1 同批）

| 选项 | 做法 | 说明 |
|---|---|---|
| **推荐** | 保留现有 **geneDevices 专用卡**（有槽位/物种数据），在物品侧按 class 前缀 `PrimalItem_WeaponGeneScanner` **过滤掉** geneGun 条目 | 展示口径单一、无重复；改动点集中 |
| 备选 | 反过来以 items 为准，废弃专用卡 | 会丢槽位/物种信息 ⇒ 不建议 |

**注意**：`kind='geneGun'` 仍需在 `lbTypeBadgeHtml` 里给个合理映射（否则徽章显示"其它"）。

### 🟡 P1：汉化表与图标刷新（数据驱动，不凭猜）

1. 等后端**重算后**，用真实数据统计"`item_zh` 未命中率"；
2. 按清单补 `汉化/item_zh.json`（中文 + icon 键）：肥料 / 雪鸮种子 / 猫头鹰颗粒 / 水壶水袋 / 蜂蜜 / 腐肉 / 板车 / 马达 / 基因枪 等；
3. 图标走既有 `tmp/_icons2_sync.py` **增量合并**（只增不删）→ `_webp_incremental.py` 压图；
4. 补表流程见 `报告/静态表与图标库刷新流程_20260920.md`。
