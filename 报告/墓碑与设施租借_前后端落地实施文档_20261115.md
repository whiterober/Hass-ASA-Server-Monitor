## 1. 方案文档 vs 线上实测：6 处必须纠正

> 这些不是文档笔误，是**照文档写代码会直接崩/白跑**的地方。全部 2026-11-15 实测。

| # | 方案文档写法 | 实测结果 | 影响 |
|---|---|---|---|
| **C1** | `lm['Cen_tomb_history.tsv']`（§15.2.4，把 `_lm.json` 当扁平字典） | 实际结构 **`{ok:true, files:{文件名: HTTP-date}}`** ⇒ 必须写 `lm.files[...]` | 照抄即 `undefined`，增量刷新永远不触发 |
| **C2** | 「增量用 `_lm.json` 判断」（§15.2.4 / §9.4） | `_lm.json` 只收 `.json` / `.json.gz`（`dino_backend.py` L19560-19562），**`.tsv` 不在表内** ⇒ `histKeys = []`（实测） | 台账**拿不到 mtime**，必须后端加 `.tsv` 白名单（B1，一行）或前端改 HEAD |
| **C3** | 台账文件"能读"（假设） | **实测已 200**：`Cen_tomb_history.tsv` 530 B、`Cen_borrow_history.tsv` 1,208 B；**`Isl_tomb_history.tsv` = 404**（该服零事件不建文件） | 前端必须把 **404 当"暂无记录"**，不能当错误弹窗 |
| **C4** | 租借 `structKey` = `class\|x,y`（§15.8.4） | 实测 Cen 老数据 `structKey` = **`CryoFridge_C`**（**无坐标**） | `replayBorrows` 的 `structClass@ts` 兜底**必须有**，否则多台同类冰箱互相覆盖 |
| **C5** | 「P2 需做：墓碑手动转移两个按钮」 | **已存在且在用**：`lbSrvAdminMove()` L5725 / `lbSrvAdminMovePendings()` L5741，后端 `move_death_bag()` L7912 + 路由 L22029 | 不要重复造；本次只补**二次确认**和**结果落到台账提示** |
| **C6** | `move_death_bag` 鉴权 = 管理员 | 后端是 **`username !== 'whiterober'` → 401**（L22031），走 **body**，不走 token | 新接口若走 Bearer token，会与这套并存；**统一口径要想清楚**（见 §4.4） |

> 另：方案文档 §15.8.9 的"前端可推导字段"代码**可直接用**，实测 `tribes` 是 dict、`players` 是数组，与文档一致，无纠正。

## 4. 后端改动（`独立后端\dino_backend.py`）

> 全部按「最小局部替换 + py_compile + 重启后打 5 个既有接口零回归」执行。
> 改前 `shutil.copy2` 备份 `*.bak_<ts>`。

### B1（必做，1 行）：`_lm.json` 收录 `.tsv`

**位置**：L19558-19562

```python
for _fn in os.listdir(DINO_DATA):
    if not (_fn.endswith('.json') or _fn.endswith('.json.gz')):
        continue
```

改为：

```python
for _fn in os.listdir(DINO_DATA):
    if not (_fn.endswith('.json') or _fn.endswith('.json.gz') or _fn.endswith('.tsv')):
        continue
```

- 风险：极低（只是多枚举一种后缀，返回体多几个键）
- 验收：`GET /dino-data/_lm.json` 的 `files` 里出现 `Cen_tomb_history.tsv`

### B2（必做）：租借实时列表透传

**新增路由**（放在 `/api/srvctl/rcon` 同级，POST 区）：

```
GET /api/plugins/borrow-list?server=<Abbr>[&tribe=<id>][&limit=<n>][&offset=<n>]
Authorization: Bearer <token>  （或 ?tk=，沿用 _srvctl_tk_of）
```

- 行为：拼 `TransferIdentityFix.BorrowList [tribe] [limit] [offset]` 投该服 RCON → **原样透传 JSON**（解析失败则 `{ok:false,err:'bad_json',raw:<前500字符>}`）
- **禁止** `[:300]` 截断
- 超时 10 s；RCON 超时 → 504；回档中 → 409 `arkbackup_busy`（复用现有 gate）
- 新增函数 `plugin_borrow_list(server, tribe='', limit=10, offset=0)`

### B3（必做）：插件配置读写

```
GET   /api/plugins/config?server=<Abbr>          → {ok, server, enabled, items:{...}}  （只返 A 类，路径类脱敏）
PATCH /api/plugins/config                        → body {server, patch:{...}} → 校验+原子写+自动 ReloadConfig
POST  /api/plugins/config/reload                 → body {server} → 投 TransferIdentityFix.ReloadConfig
```

**A 类白名单**（只允许改这些键，其余一律 403 `key_not_allowed`）：
`reconnect.enabled` / `reconnect.whitelist` / `reconnect.max_reconnects_per_session` / `reconnect.cooldown_seconds` /
`auto_parse_enabled` / `auto_parse_settle_ms` / `auto_parse_retry_max` /
`auto_transfer_enabled` / `_window_seconds` / `_interval_seconds` / `_min_remaining_seconds` / `_move_batch_limit` / `_give_pending_enabled` / `_give_pending_interval_seconds` /
`tomb_notify_enabled` / `tomb_notify_min_interval_seconds` /
`auto_keep_alive_enabled` / `_interval_seconds` / `_extra_classes` /
`borrowable_classes` / `language` / `debug.chat_enabled` /
`history_enabled` / `history_flush_interval_seconds` / `history_max_rows` / `history_record_denied`

**写盘四道闸（缺一不可）**：

1. **读原文件 → 正则/文本替换目标键值**（插件是正则解析，不是 JSON 库；**禁止** `json.dump` 整文件重写，否则注释与键序全丢、插件可能读不到）
2. `json.loads` 自检整文件 → 失败即回滚 `.bak`
3. 原子写（`.tmp` → `os.replace`）+ 备份 `config.json.bak_<ts>`
4. 写完**自动**投 `TransferIdentityFix.ReloadConfig`，回读日志/响应确认生效

**白名单（`reconnect.whitelist`）专项校验**：字符串数组、单条 1–64 字符、去首尾空白、禁 `, " \`、忽略大小写去重、≤200 条；`["*"]` 与空数组**强制前端二次确认**。

### B4（可选，建议做）：`move_death_bag` 支持 token

现状 L22030 只认 `body.username === 'whiterober'`。本次不强制改；若前端要统一用 Bearer，则加：

```python
u = g('username')
tk = _srvctl_tk_of(self, qs)      # 复用现有签名校验
if not (u == 'whiterober' or (tk and _role_level_of(tk) >= 3)):
    ... 401
```

> 保持向后兼容：老的 `username` 路径**不要删**。

## 5. 前端改动（`app_core.js` 为主）

### F1 台账读取与解析（新增函数族 `lbHist*`）

```js
// 1) 拉到文本（404 → 返回 null，不抛错）
async function lbHistFetch(abbr, kind){        // kind: 'tomb' | 'borrow'
  var url = DINO_JSON + abbr + '_' + kind + '_history.tsv?cb=' + Date.now();
  var r = await fetch(url, { cache:'no-store' });
  if (r.status === 404) return null;           // C3：无事件 = 无文件
  if (!r.ok) throw new Error('http_' + r.status);
  return await r.text();
}

// 2) 解析（按 header 取列，禁止硬编码下标；坏行跳过）
function lbHistParse(text){
  var lines = String(text || '').split(/\r?\n/).filter(function(s){ return s.length; });
  if (!lines.length) return { cols:[], rows:[] };
  if (lines[0].charAt(0) !== '#') return { cols:[], rows:[], bad:true };
  var cols = lines[0].replace(/^#v\d+\t/, '').split('\t');
  var rows = [];
  for (var i = 1; i < lines.length; i++){
    var f = lines[i].split('\t');
    if (f.length < 2) continue;
    while (f.length < cols.length) f.push('');
    if (f.length > cols.length) f.length = cols.length;
    var o = {}; for (var k = 0; k < cols.length; k++) o[cols[k]] = f[k];
    ['ts','teamId','movedCount','x','y','z','origTribeId','borrowerTribeId','expireAtMs']
      .forEach(function(n){ if (n in o) o[n] = (o[n] === '' ? null : Number(o[n])); });
    rows.push(o);
  }
  return { cols: cols, rows: rows };
}

// 3) 增量戳（C1 + C2：走 _lm.json 的 files，且要能容忍 tsv 不在表内）
function lbHistStamp(lm, abbr, kind){
  var files = (lm && lm.files) || {};
  return files[abbr + '_' + kind + '_history.tsv'] || '';   // 空串 = 无法判断 → 每次按需拉
}
```

**缓存策略**：`LB._hist = { 'Cen|tomb': {stamp, rows, ts} }`。页面级 60 s 节流；面板打开时强制刷一次。

### F2 墓碑面板（只读）

- 数据源：**优先** `LB._cache.data.structures`（零请求）；`tribeName` 由 `tribesByServer` 反查补全（文档 §15.8.9 代码可直接用，实测 `tribes` 是 dict）

- 禁止：`✓`/`✗` 字符，一律 MDI 图标

### F3 墓碑操作加固（改已有函数）

- `lbSrvAdminMove()` / `lbSrvAdminMovePendings()`：执行前插入**二次确认**（新增通用 `lbAskConfirm(opts)`，复用 `.lb-picker-overlay` + `.lw-head` 样式）

- 成功提示后**清掉该服墓碑台账缓存**（`delete LB._hist[abbr+'|tomb']`），让历史列表下次刷新看到新行

### F4 租借面板

## 8. 风险与回滚

| 风险 | 等级 | 缓解 | 回滚 |
|---|---|---|---|
| 误点「转移死亡包」移动大量实体 | 高 | D2 二次确认 + 显示部落名 | 无（游戏内不可逆），故确认必须在动手前 |
