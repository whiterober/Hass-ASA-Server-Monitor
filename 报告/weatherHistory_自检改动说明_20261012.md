# 天气历史「自检记录」前端改动说明（2026-10-12）

> 对应插件：`TransferIdentityFixAPI`；本次涉及版本 v123 → v124m。
> 背景：前端报的 BUG「无人开前端时段的变天不记录」= UDS 图的历史只由天气 RCON 命令喂数据，
> 所以"上次变天 15 小时前"实际是"上次有人看是 15 小时前"。
> 本文只列**前端可见的变化**，实现细节见插件项目 `进度\020_开发_天气区域查询与Abe适配实施.md` 附录 41~59。

---

## 一、行为变化总览

| # | 变化 | 前端需要做什么 |
|---|---|---|
| 1 | **无人时段也会记录变天**（插件自身每 5 秒自检一次，不再依赖前端轮询） | 无需改动；历史会更"连续"，间隔可能比过去更短更真实 |
| 2 | `atSource` 新增取值 **`"autoScan"`** | 若前端对 `atSource` 做过 switch/枚举，请加上该分支（未知值请按 `observedWindow` 处理） |
| 3 | `atEarliest` 语义细化 | `atEarliest == 0` ⇒ `at` 是**精确戳**（游戏自带过渡起始时间，误差 0）；`atEarliest > 0` ⇒ `at` 是**观测窗口上界**，真实变天时刻落在 `[atEarliest, at]` 内（窗口宽度 = 扫描间隔，默认 5 秒） |
| 4 | `wxId` 开始被填充（原先多为 `-1`） | 见 §三 **重要限制**：**不要把它当持久主键**，优先用名字 |
| 5 | 非天气类对象不再进历史文件（如 `BP_DayWeather_CloudSystem_C` 这类模板/Agent/WeatherEffects/RegionTimeOfDay） | 若前端按"文件名/key"挑选目标类，请以**真天气类**为准（多为一图一个；`weather.target` 仍是权威） |
| 6 | 历史文件新增一行元数据注释 `#ids ...` | 忽略即可（以 `#` 开头，按原有"跳过注释行"逻辑处理） |
| 7 | 扫描间隔可配 | 实服 `config.json` 的 `weather_autoscan_seconds`（默认 **5**，**0 = 关闭自检**）；本次实服未改配置，走默认 5 秒 |
| 8 | **记录延迟最长 5 秒** | 自检每 5 秒一轮 => 变天后最迟 5 秒出现记录（原来要等前端轮询） |
| 9 | **历史窗口上限不变（32 条）** | 无人时段也会记录 => 窗口**更快被填满**、更早的记录会被挤掉；若需要更长历史请告知 |
| 10 | **自检不会写“种子行”** | 自检只写**真实发生**的变天；`seed=1` 的行仍仅由天气命令写（不会伪造“刚变了天”） |
| 11 | **Gen 的 `changes` 会一次性回退** | Gen 曾因缺陷累积 2529 条伪记录；清理后计数会校正为**实际保留条数**（如 2529 → 2）。**这是计数校正、不是数据丢失**；`seq` 仍递增不回退 |

## 二、`atSource` 三种取值（历史记录 `weatherHistory.recent[].atSource`）

| 值 | 含义 | `at` 精度 | `atEarliest` |
|---|---|---|---|
| `"gameStamp"` | 由天气命令记录，且**游戏自带**绝对时间戳 | 精确 | `0` |
| `"observedWindow"` | 由天气命令记录，但**没有**游戏戳，只有观测窗口 | ±（两次轮询之间） | 观测下限 |
| `"autoScan"` | **插件自身后台自检**记录（本次新增，重点） | 有游戏戳时精确（`atEarliest == 0`）；否则 ± 扫描间隔 | 同上 |

> 判据建议：先看 `atEarliest == 0` 决定"精确/区间"，再看 `atSource` 决定"谁记录的"。两者正交，不要混用。

## 三、⚠️ `wxId` 的重要限制（务必注意）

- `wxId` 目前来源有两类（**稳定性完全不同，请分开对待**）：
  - UDS 系图（Sco / Isl / Cen 等）：该图天气**枚举 id**（0~8，与 UDS 枚举一致）—— **稳定**，可持久使用
  - 「名字身份」图（Rag / Gen / Ast / Val / Los 等）：该图**预设表里预设自身的 id**—— **不稳定**（见下）
- **这些 id 是 UE 的 FName 比较索引，同一进程内稳定，但跨重启可能变化**：
  实测同一预设 `WeatherPreset_RAG_ClearSky` 在不同时刻为 `13549232` / `13536891`
- ⇒ **前端不要用 `wxId` 当持久主键或做跨会话比对**；正确用法：
  1. 以 `weatherHistory.recent[].id`（**天气名字**）为主键显示/比较；
  2. 需要 id 时，用**同一次响应**里的 `wxSemantics.presetTable[].id` 实时映射（同一响应内必一致）；
  3. `wxId` 缺失（`-1`）仍会出现于两种情况：该图没有预设表可映射；或**重启后、前端还没轮询过**时（此时表刚从文件恢复，见 §四）

---

## 四、本次为避免"重启后无人时段无 id"做的持久化

- 插件会把「名字 → id」表写进历史文件的一行注释：`#ids\t<预设名>=<id>\t...`
- 重启后**无需前端参与**即可恢复该表，新记录就能带上 `wxId`
- **实测（Rag，2026-10-12 19:11）**：重启后全程**未调用任何天气命令**，仅靠文件里的表，
  新记录即带上 `wxId=5354952`（= 文件中 `WeatherPreset_RAG_Fog=5354952`）
- 前端只需**忽略以 `#` 开头的行**（若前端解析历史文件），或直接忽略（若只看 JSON）

---

## 五、接口形状有无破坏性变化

- **无破坏性变化**：`weatherHistory` 的键、`recent[]` 的字段名均保持不变，只是：新增 `atSource` 取值、`wxId` 开始有值、`atEarliest` 语义更明确
- 旧历史文件（无 `wxId` 列）仍可读：该列缺失时按 `-1`/未知处理
- `weatherState` / `wxSemantics` / `zones` 等其它段落**未改动**

---

## 六、建议前端的处理（最小改动）

1. `atSource` 未知值 → 回退为 `"observedWindow"` 处理（**不要丢弃该条记录**）
2. 显示"上次变天"：取最后一条 `recent[]`，用 `at`（当 `atEarliest == 0` 时可标"精确"，否则标"约"）
3. 天气类型展示：用 `id`（名字）直出；需要图标/枚举时再查 `wxSemantics.presetTable`
4. "本次变天发生于何时"若需要毫秒级，请只在 `atEarliest == 0` 时展示精确值

### ⚠️ 已修复的已知问题（避免误把旧数据当真实现象）

| 图 | 现象 | 说明 |
|---|---|---|
| **Gen** | 历史里出现 `Storm ↔ ClearSky` **每 ~5 秒交替**、自检行占满整个 32 条窗口 | 根因：历史按**类名**归档，而 Gen 有 **5 个** `BP_GEN_DayWeather_WeatherSystem_C` 实例（每小地图一个、天气各自不同），自检逐实例比较把它们轮流写进同一条目。**已在 v124n 修复**（每类只跟踪“下一个要变天的那个实例”），且加载时会自动剔除这类伪记录（`WXHIST prune oscillated rows`）。若前端缓存里有 Gen 的这类旧数据，可丢弃 |
| **Gen（计数）** | `weatherHistory.changes` 会从 **2529 降到 2** | 伪记录被剔除后，计数在**加载时校正**为实际保留条数（`WXHIST counter aligned … changes=2529->2 rows=2`，v124p）。
**请前端不要把它当“数据丢失”**：Gen 真实历史就是 2 条；`seq`（排序用）仍保持递增不变 |

> 如前端对某图结果有疑问，可用 `TransferIdentityFix.WorldProbe weather slim=1` 现场取证（`weatherHistory.lastChange` 即"上次变天"权威值）。

## 八、字段与文件格式对照（前端解析用）

### 8.1 JSON（推荐前端使用）

| 路径 | 说明 |
|---|---|
| `weatherHistory.recent[]` | 最近变天列表（**按 target 类输出**，即一图一类；上限 32 条，最新在最后） |
| `…recent[].id` | 天气名字（**建议作主键**，如 `Fog` / `Sandstorm` / `#id2`） |
| `…recent[].at` / `atEarliest` | 变天时刻 / 观测下限；`atEarliest == 0` 表示 `at` 是精确值 |
| `…recent[].atSource` | `"observedWindow"` / `"gameStamp"` / **`"autoScan"`**（字符串） |
| `…recent[].seq` | 递增序号（自检与天气命令共用同一计数，按其排序即可） |
| `…recent[].seed` | `1` = 仅由天气命令写入的“种子行”，**自检不会写** |
| `…recent[].wxId` | 见 §三（UDS 图稳定 / 名字身份图不稳定；未知或未就绪为 `-1`） |
| `weatherHistory.lastChange` | 与 `recent[]` 末条同构（同样带 `atSource` / `atEarliest`），额外有 `agoSec` |
| `weatherHistory.changes` | **target 类**的累计变天次数 |

### 8.2 TSV（`DinoData\wx_history_<服>.tsv`，仅当前端直接读文件时）

| 要点 | 说明 |
|---|---|
| 表头行 | 以 `#` 开头，忽略 |
| **`#ids` 行** | **紧跟表头**，形如 `#ids\t<预设名>=<id>\t…`；忽略即可 |
| `M` 行 | 每图一行（map 状态）；**非天气对象不再出现** |
| `R` 行 | 变天记录，列：`R / 类名 / seq / 名字 / 上一个名字 / at / atEarliest / at_src / ended_at / seed / wxId` |
| **列数兼容** | `R` 行可能是 **10 列（v123 之前）或 11 列（v123 起，末列 `wxId`）** => 请按前 10 列解析、第 11 列可选 |
| **`at_src` 是数字** | `0` = observedWindow；`1` = gameStamp；**`2` = autoScan（新增）**——与 JSON 的字符串一一对应 |

> 一句话：**JSON 与 TSV 同步更新**，若前端本来只看 JSON，则无需改动任何解析逻辑。
