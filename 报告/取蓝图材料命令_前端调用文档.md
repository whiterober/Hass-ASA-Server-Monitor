# 取蓝图材料命令（CraftingCost） 给前端看的调用文档

> 插件：`TransferIdentityFixAPI` · 构建标记：`curstats_20260826_v2`（2026-09-13 18:14 版，含 `WorldTime` / `CraftingCost`）· 更新：2026-09-13
> 用途：给定物品**类名**，**按需单查**该物品的**制作材料清单**，RCON 直接返回 JSON（不落盘、无副作用）。
>
> ⚠️ **为什么要走命令**：制作材料**不在存档里**（`.ark` 存档与 item.gz 里都验证过没有 `CraftingCost`/`RequiredItems` 字符串），只能在运行时从物品类的 `BaseCraftingResourceRequirements` 读取 ⇒ **必须实时查**，无法离线导出。

## 2. 命令格式

| 项 | 值 |
|----|----|
| 命令 | `TransferIdentityFix.CraftingCost <itemClass>` |
| 参数 | `<itemClass>` **必填**（不传/为空返回 usage 提示） |
| 权限 | **无额外命令级权限校验** —— 仅需 RCON 通道密码认证（对比：`WorldTime` 需 `tif.viewer`） |
| 返回 | **RCON 直接返回 JSON**，不写任何数据文件 |
| 副作用 | **无**（纯只读；无参调用在 usage 检查处直接 return，**不写日志**） |
| 日志 | 命中时会写一行 `CRAFTINGCOST item=<类名> n=<材料数> src=<命中actor类名>` |

### 2.1 匹配口径（重要）

- **大小写敏感的「子串」匹配**：`运行时类名 == itemClass` 或 `运行时类名 包含 itemClass`
- **建议传类名 basename**：`PrimalItem_WeaponMetalPick`（也可传含 `_C` 的 `PrimalItem_WeaponMetalPick_C`）
- ⚠️ **禁止直接传 item.gz 里的 `class` 字段原值**：那是形如 `PrimalItem_WeaponMetalPick_C_2145348708` 的实例名，含 `_C_<8~10位数字>` 后缀，**不是运行时类名**，子串匹配会失败。
  前端清洗规则：`re.sub(r'_C_\d+$', '', cls)`（如需保留 `_C` 则 `re.sub(r'_\d+$', '', cls)`）。
- 扫描范围：遍历世界 actor 的背包 —— **建筑容器**（储物箱/合成台/补给箱等）、**玩家角色**、**恐龙**；每类依次查 `InventoryItemsField` 与 `EquippedItemsField`。
- **只返回第一个命中的实例**（不聚合、不排序），命中位置见 `foundIn`。
- **蓝图与实物同类**：品质蓝图（item.gz 里 `type=blueprint`）与成品**共用同一个 UClass** ⇒ 无论命中哪一类，返回的**都是该物品的配方**（配方是类默认值，与具体实例无关）。
- 目标类必须在**当前已加载**的 actor 里存在实例，否则返回 `item instance not found`；查**宽泛的基类名**（如 `PrimalItem_Weapon`）命中率更高。

## 3. 返回 JSON 结构

### 3.1 成功

```json
{
  "ok": true,
  "itemClass": "PrimalItem_WeaponMetalPick_C",
  "foundIn": "StorageBox_AnvilBench_C",
  "costs": [
    { "item": "PrimalItemResource_MetalIngot_C", "count": 1,  "exact": 0 },
    { "item": "PrimalItemResource_Wood_C",       "count": 1,  "exact": 0 },
    { "item": "PrimalItemResource_Hide_C",       "count": 10, "exact": 0 }
  ],
  "count": 3
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `ok` | bool | 是否成功 |
| `itemClass` | string | **实际命中的运行时类名**（可用于校验前端传的类名是否正确） |
| `foundIn` | string | 命中实例所在 actor 的类名（如 `StorageBox_AnvilBench_C`、`StructureBP_LibraryStorage_C`、`Basilisk_Character_BP_C`、`PlayerPawnTest_Male_C`） |
| `costs[]` | array | 材料清单，逐项见下表 |
| `count` | int | `costs` 元素个数；`-1` 表示读取异常（见 §5.1） |

`costs[]` 单项：

| 字段 | 类型 | 说明 |
|------|------|------|
| `item` | string | 材料**类名**（如 `PrimalItemResource_MetalIngot_C`）；空串表示该项资源类未解析出 |
| `count` | number(float) | 需要数量（游戏内为浮点，资源类通常为整数） |
| `exact` | int | `1` = **必须精确该资源类型**（如 `PrimalItem_WeaponClimbPick` 的「肥沃宝石」）；`0` = 可用同类替代（如任意金属锭来源） |

### 3.2 失败

见 §5。

## 5. 错误返回

| 场景 | 返回 JSON |
|------|-----------|
| 未传参 | `{"ok":false,"error":"usage: CraftingCost <itemClass>"}` |
| 世界未就绪 | `{"ok":false,"error":"world not ready"}` |
| 关卡未就绪 | `{"ok":false,"error":"level not ready"}` |
| 找不到该类实例 | `{"ok":false,"error":"item instance not found","itemClass":"<你传的类名>"}` |

### 5.1 `count = -1` 与 `costs = []` 的区别

| 现象 | 含义 | 处理建议 |
|------|------|----------|
| `count: -1` | 读取 `BaseCraftingResourceRequirements` 抛异常（字段不可用） | 视为查询失败，前端展示"暂无数据"；截至 2026-09-13 实测未出现 |
| `count: 0` + `costs: []` | 该物品**确实没有制作配方**（资源、弹药模板等非制作品） | 正常结果，显示"该物品无配方" |

## 6. 前端集成建议

1. **类名清洗**：`item.gz` 的 `class` 字段先去掉 `_C_<数字>` 再传（见 §2.1）。
2. **可长期缓存**：配方来自**类默认值**，与服务器上的具体实例、部落、时间**无关** ⇒ 同一 `itemClass` 的结果可持久缓存（建议缓存到后端 DB/JSON，避免重复 RCON）。
3. **串行 + 间隔**：逐类调用，建议间隔 ≥ 0.2s（26 类实测约 10 秒完成）；RCON 单次响应 0.1~1 秒。
4. **命中依赖实例存在**：若某物品在服务器上**没有存活实例**（只存在于离线存档、或该区域未加载），会返回 `item instance not found`。想提高命中率可查更宽泛的基类名。
5. **RCON 报文上限**：单条响应受 RCON 包长限制（约 8KB）。本命令单物品响应通常 <1KB，正常使用不会触发；但不要传超宽泛的子串（如 `PrimalItem`）以免内容膨胀。
6. **安全**：RCON 密码只放服务端配置；本命令**无命令级权限校验**，拿到通道密码即可调用，故**不要**把端口/密码暴露给浏览器端。
