# Gen 天气概率（权重）数据交付说明（2026-10-13）

> 面向：前端（dino-import）｜ 插件版本：**v125j**（Gen 已部署）
> 一句话：**Gen 的天气权重已从「探针通道」提升为正式输出字段**，前端可直接归一化成百分比，口径与 Ext 完全一致。

---

## 一、背景：为什么以前没有 Gen 的概率

- 插件提供的**是权重**、前端**现场归一化**成百分比 —— 两端口径一致，**不是 bug**
- Ext 的权重（`WeatherChances`，7 槽）此前一直通过**探针通道（`probe=`）**读出，所以前端能算
- Gen 的权重同样在实体上（`BP_GEN_DayWeather_WeatherSystem_C`，**5 个实例 = 5 个生态圈**），但**从未被读出来交付** ⇒ 前端拿不到
- 根因：这些槽在常规属性转储里是 **`unreadable`**（不是标量），且 Gen/Ext 用的字段名（`WeatherChances` / `PossibleWeatherChances`）与 UDS 族（`WeatherWeights_Day` / `_Night`）**不同**

---

## 二、新增字段（v125j）：`wxSystems[]` 的每一项

```json
"wxSystems": [
  {
    "idx": 13,
    "class": "BP_GEN_DayWeather_WeatherSystem_C",
    "miniMapType": "bog",
    "currentWeather": "Rain",
    "nextWeather": "Rain",
    "prevWeather": "ClearSky",
    "secondsUntilChange": 456.878,
    "live": 1,

    "weatherChances": [1.0, 1.0],
    "possibleWeatherChances": [1.0, 0.0],
    "presetTable": [
      {"id": 13695925, "name": "WeatherPreset_GEN_Bog_ClearSky"},
      {"id": 9249644,  "name": "WeatherPreset_GEN_Bog_Rain"}
    ]
  }
]
```

| 字段 | 含义 |
|---|---|
| `weatherChances` | 该生态圈的**权重数组**（double；已按数组自身的 `num` 截断） |
| `possibleWeatherChances` | 该区「可能天气」的权重数组（同上） |
| `presetTable` | **该实例自己的**天气预设表（`id` + 预设资产名）⇒ 用于把权重槽位对应到天气名 |

⭐ **`weatherChances[i]` 与 `presetTable[i]` 一一对应**（同索引 = 同一天气）。

---

## 三、前端接入方式（与 Ext 完全一致，无需新逻辑）

```
某天气概率 = weatherChances[i] / sum(weatherChances)
天气名     = presetTable[i].name      // 也可用 id 与 wxSemantics.idNames 对照
```

- `presetTable` 为空或项数少于权重项数 ⇒ 退化为「按槽位顺序 + 你的 id 映射」
- `weatherChances` 全为 `1.0` 时，归一化即「等概率」
- **请用存在性判断**：字段不存在就不展示，不要报错

## 四、Gen 五区实测值（2026-10-13，供回归对照）

| 区域（`miniMapType`） | `weatherChances` | `possibleWeatherChances` |
|---|---|---|
| arctic | num=1 `[1.0]` | num=7 `[0, 1, 1, 1, 0, 1, 1]` |
| **bog** | num=2 `[1.0, 1.0]` | num=2 `[1.0, 0.0]` |
| **ocean** | num=7 `[1.0, 0.2, 0.2, 0.2, 0.1, 0.1, 0.1]` | num=7 `[0, 0.2, 0.2, 0.2, 0.1, 0.1, 0.1]` |
| volcanic | num=2 `[1.0, 1.0]` | num=7 `[0, 1, 1, 1, 0, 1, 1]` |
| （无 `miniMapType`） | num=2 `[1.0, 1.0]` | num=7 `[0, 1, 1, 1, 0, 1, 1]` |

> ⚠️ 各区**槽数不同**（1 / 2 / 7 / 2 / 2）⇒ 每个生态圈的天气种类数不同，**不能共用一张预设表**，请按区各取 `presetTable`。

## 七、附：UDS 三图权重字段的读法变更（v125i，顺带告知）

`wxSemantics` 的 `weightsDay` / `weightsNight` / `eventLengths` 三个数组真实类型是 **`TArray<double>`**：

- 旧字段 **`asFloat` 已移除**（它是按 4 字节「半读」，会产出 `2.72e+23` 这类垃圾）
- 请改读 **`asDouble`**（三个数组的正确值示例：`weightsDay = [0.0, 0.1, 0.35, 0.15, 0.7, 0.5, 0.25, 0.15]`）
