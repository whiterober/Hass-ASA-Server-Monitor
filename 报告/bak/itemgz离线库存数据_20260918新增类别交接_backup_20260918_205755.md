# item.gz 新增类别交接 — 给前端（2026-09-18）

> 生成器：`ark_save_reader.exe`（新版本 **1,542,656 B**）
> 关联文档：`itemgz离线库存数据_前端调用文档_20260910.md`（字段字典与分类规则总说明，**本文只讲增量**）
> 一句话：**消耗品放开了、战利品/神器/祭品放开了、电锯拿到了、自定义料理连中文菜名一起拿到了；`type` 和 `kind` 的取值域扩大了，前端枚举要跟着加。**

---

## 1. 前端必须做的改动（就 3 处）

### ① `type` 值域从 3 个扩到 5 个

| 旧版 | 本版 |
|---|---|
| `blueprint` / `ammo` / `resource` | `blueprint` / `ammo` / `resource` / **`item`** / **`consumable`** |

> 前端若用 `switch(type)` 或字典映射图标，**必须补 `item` 和 `consumable` 两个分支**，否则新数据会掉进 `default`（显示空白/未知）。

### ② `kind` 值域新增 2 个

新增 `trophy`（战利品，含神器）、`tribute`（Boss 祭品）。
（`trait` 是上一版就有的。）

完整值域：`resource` / `ammo` / `structure` / `consumable` / `saddle` / `armor` / `weapon` / `attachment` / `tek` / **`trophy`** / **`tribute`** / `trait` / `other`

### ③ `items[]` 新增字段 `customName`

| 字段 | 类型 | 说明 |
|---|---|---|
| `customName` | string | 玩家自己起的物品名（**中文菜名就在这**）；`""` = 无自定义名 |

> 位置在 `customClass` 之后。前端**显示优先级建议**：`customName` 非空则显示 `customName`，否则用类名映射表。

## 2. 逐项说明

### 2.1 消耗品放开（`type: "consumable"`）

- 判据：`PrimalItemConsumable*`，以及 **`PrimalItemCustomFoodRecipe*` / `PrimalItemCustomDrinkRecipe*`**（自定义料理）
- **排除**：受精蛋（`Fertilized`）、胚胎（`PrimalItemConsumable_Embryo*`）
- **排除**：`quantity == 0` 的消耗品（空堆/残留记录）
- Isl 实测：`consumable = 3390` 条

### 2.2 自定义料理 —— 本轮重点 ⭐

前端之前反馈"冰箱里有自定义料理但取不到"，本轮已解决：

- 类名：`PrimalItemCustomFoodRecipe_Type1_C` / `Type2` / `Type3`、`PrimalItemCustomDrinkRecipe_Type1` / `Type2`
- 归入 `type: "consumable"`，`kind: "consumable"`
- **`quantity > 0`**（真实堆叠数，20/19/18…），`isBlueprint: 0`
- **菜名在 `customName`**，中文正常

Isl 实测样本：

```json
{"type":"consumable","kind":"consumable",
 "class":"PrimalItemCustomFoodRecipe_Type3_C_2146888762",
 "quantity":20,"customName":"鲜肉刺身",
 "containerType":"other","containerClass":"PrimalInventoryBP_Refridgerator_C1"}
```

> 说明：虽然类名里带 `Recipe`，**它存的就是成品料理**（数量>0、非蓝图、名字是菜名），不是合成配方。

### 2.3 战利品 / 神器 / Boss 祭品放开

| 类名特征 | `kind` | 说明 |
|---|---|---|
| `PrimalItemTrophy*` | `trophy` | 战利品奖励 |
| `PrimalItemArtifact*` | `trophy` | **神器按战利品归类** |
| `PrimalItem_BossTribute*` | `tribute` | Boss 祭品/召唤物 |

- 这三类**豁免品质过滤**（无品质也一样入列），`type` 为 `item`
- Isl 实测：Trophy **64** 条、Boss 祭品 **45** 条

### 2.4 电锯修复

- `PrimalItem_ChainSaw_C` **不含** `PrimalItem_Weapon` 子串，旧版被判为 `other` 直接丢弃
- 本版显式归入 `kind: "weapon"` → Isl 实测 **42** 条（含传说品质）

### 2.5 容器/设施取色 `colorRegions`

`structures[]` 与 `facilities[]` 条目可能新增：

```json
"colorRegions": [-1, -1, -1, -1, 67]
```

- 类型：`number[]`（有符号 16 位，**索引 = 染色区域槽位**，`-1` = 该槽未染色）
- **仅当非空时才出现**该字段 → 前端读取请用 `entry.colorRegions || []`
- 实测：Isl 某箱"随身" = `[-1,-1,-1,-1,67]`；冰箱 `CryoFridge_C_2145689931` = `[12,-1,-1,-1,12]`

### 2.6 壁挂牌白名单补齐（影响 `structures[]` 数量）

`Sign_Wall_Metal` / `Sign_Wall_Wood` / `Sign_Wall_Stocking` 已补入白名单。
Isl 实测 `structures` 条数：**87 → 124 → 128**（壁挂牌 + 圣诞袜）

> 若前端发现某图 `structures` 数量突增，这是**修复**不是异常。

### 2.7 诊断字段（前端**可忽略**）

顶层新增 `signDiag[]`（所有牌类对象诊断）与 `colorTags[]`（含 `Color` 的属性 tag），仅排障用，**前端不必消费**。
