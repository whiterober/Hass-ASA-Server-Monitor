## 一、一句话说明

新增命令 `WorldProbe zones`：列出**一张图上每个天气覆盖区域（`Weather_Override_Volume`）的具体天气与气温**。
只有 **Isl（4 区）/ Cen（6 区）** 有区域；其余图返回 `count: 0`（前端隐藏入口）。

## 二、命令契约

| 项 | 内容 |
|---|---|
| 命令 | `TransferIdentityFix.WorldProbe zones` |
| 参数 | `fresh=1`（强制重建区域名单）；`probe=1`（附带原始探针块，**日常不用**） |
| 权限 | `tif.viewer`（与 `weather` / `query` 同口径） |
| 通道 | RCON（与既有 WorldProbe 命令一致） |
| 触发时机 | **仅面板打开 / 切图**，无 tick、无逐玩家遍历 |

## 三、响应结构（完整字段表）

### 3.1 顶层

| 字段 | 类型 | 含义 |
|---|---|---|
| `ok` | bool | 成功标志（无区域也是 `true`） |
| `sub` | string | 固定 `"zones"` |
| `worldTime` | number | 服务器世界时钟（秒） |
| `count` | int | **区域数量：Isl 4 / Cen 6 / 其余 0** |
| `cached` | 0/1 | `1` = 本轮**复用**已缓存的区域名单（**数据仍是实时重读的**，见 §六） |
| `scanAge` | number | 距上次「扫图建名单」的秒数（实时数据，非响应缓存年龄） |
| `live` | 1 | 固定 `1`，表示天气/温度字段本轮**实时重读** |
| `probeTraced` / `probeFails` | int | 指针追踪成功/失败数（实测 `20 / 0`） |
| `probeTruncated` | 0/1 | `1` = 有区域因体积预算未带 `probe`/`state`/`settings`（仅 6 区图且旧预算时出现） |
| `zones` | array | 区域数组，见 3.2 |
| `note` | string | 说明文本 |

### 3.2 `zones[]` 每项

| 字段 | 含义 | Isl 实测 |
|---|---|---|
| `idx` | 序号（0 起） | 0~3 |
| `class` | 类名 | 均为 `Weather_Override_Volume_C` |
| `weather.typeIndex` | 区域天气类型（`LastFrameWeatherType`） | 0（**原始枚举索引，见 §九**） |
| `weather.transitioning` / `transitionTimeRemaining` | 是否在过渡 / 剩余过渡时间 | 0 / 0 |
| `temperature.offset` | 温度偏移（`Temperature Offset`，f64） | 0 |
| `wind.direction` / `wind.apply` | 风向 / 是否生效 | 180 / 1 或 0 |
| `meta.priority` / `volumeAlpha` / `transitionWidth` / `scaledTransitionWidth` / `mode` / `globalRainInfluenceOnClouds` / `started` | 体积元数据 | `transitionWidth` = **20000 / 2500 / 5000 / 20000**（4 区各不相同） |
| **`bounds`** | **区域位置与范围（球形近似）**：中心 + 半径，见 §3.4 | 4 区各不相同 |
| `probed` | 13 个目标字段命中数 | **13 / 13** |
| `probe` | 原始探针（**默认 `null`**，仅 `probe=1` 时是对象） | `null` |

### 3.4 `bounds`（区域位置与范围，2026-10-03 新增）

前端**用它把区域对应到地图上**（画圆 / 判断某个点属于哪个区域）。

| 字段 | 含义 |
|---|---|
| `x` / `y` / `z` | 区域中心（体积的 `Spline Bounds Center`，24 B = 3×double；`z` 实测恒 ≈0） |
| `radius` | 包围球值（体积的 `Total Sphere Bounds`） |
| `centerField` / `radiusField` | **原始字段名回显**，便于日后校准 `radius` 语义（半径 / 直径**待证实**） |

## 四、`state` / `settings`（**核心数据，前端主要读这两个**）

两者均为 **`UDS_Weather_Settings_C`** 实例的属性转储，结构统一：

| 字段 | 含义 |
|---|---|
| `class` | 实际类名（`UDS_Weather_Settings_C`） |
| `propsTotal` | 属性总数（实测 23） |
| `nonZero` | **非零**属性个数 |
| `props` | `[{name, value}]`，**只列非零项**（上限 24 条） |

> ⚠️ **`props` 只列非零项 ⇒ 某个键缺失即代表它 = 0。** 该对象 23 项里通常有 19~21 项为 0。

## 五、数据质量保证（2026-10-03 起）

| 规则 | 说明 |
|---|---|
| **只列非零项** | 缺键 = 0（见 §四） |
| **非有限数值不输出** | NaN / Inf 一律不出现（修复前 `-nan` 会导致**整个响应无法 `JSON.parse`**，该缺陷在旧版 `weather full=1` 即存在） |
| **次正规值视为不可读** | 4 字节槽若读出次正规 float（`|v| < 1.175e-38`，典型为 int 被当 float 读）、8 字节槽读出次正规 double → 跳过不输出 |
| JSON 合法性 | 本轮 10 图 + Isl/Abe 共 20+ 次响应，非法令牌数 **全部为 0** |

## 六、缓存与实时性（**分层设计，2026-10-03 起**）

| 层 | 行为 |
|---|---|
| **静态层（区域名单）** | 长缓存：**地图切换自动失效**、**15 分钟安全重扫**、**指针复验失败自动重扫**、`fresh=1` 强制重扫。只在**首次**调用时付一次全图扫描成本 |
| **动态层（天气/温度/风向/`state`/`settings`）** | **每次调用都实时重读**（微秒级）⇒ **不存在"5 分钟前的旧天气"** |
| 后端建议 | `worldprobe_zones` 路由 **TTL 60 s**（与 `worldprobe_weather` 同模式） |
| 前端建议 | 60 s 复用 + 切图/重开面板时重取 |

> 佐证（Isl 实测）：调用 A 带 `probe=1`（响应含 `probe` 对象）→ 调用 B 不带（`cached:1` 却为 `probe:null`）⇒ **B 的数据是当场重拼的，不是回放 A 的冻结包**。

## 九、前端接入要点（**必读**）

1. **`count === 0` ⇒ 隐藏「区域」分组**（8 张图都是 0）。
2. **只渲染非零项**：`props` 里没有的键就当 0；不要遍历固定键表。
3. **优先只渲染 `settings`**（`state` 实测是其子集，见 §四）。
4. ⚠️ **`weather.typeIndex` 是原始枚举索引，没有 id→名称映射**（游戏侧 `WeatherPresetList` 是 80 B 结构体，读不出）。**不要**直接把它当天气名展示。
5. **`probe` 默认是 `null`，不要渲染**（它是 `probe=1` 才附带的原始字节，仅供排障）。
6. `cached` 只表示"名单是否复用"，**不影响数据新鲜度**（`scanAge` 说明名单多久前建的）。
7. `weather` 命令（全局天气 + 变天倒计时 `secondsUntilChange`）**始终无缓存**，看"变天时间"用它。

## 十一、分图专属说明（Abe / Gen）

### Abe（畸变）

- Abe **没有天气覆盖区域**（`zones.count = 0`，前端隐藏入口）——这是**预期行为**。
- Abe 的天气数据在 `BP_AB_WeatherAgent_C`，现已适配：`weather` 响应 `family = "ab"`、`weatherState` **18 键非空**、新增 `semSource = BP_AB_WeatherAgent_C`（语义实际来源类名）。

### Gen（创世纪）天气逻辑

Gen **完全没有“局部天气覆盖体积”这一层**（`zones.count = 0`），它的天气是**按生物区分片的全局天气系统**：

| # | 事实 | 前端含义 |
|---|---|---|
| 1 | 天气类族 = `BP_GEN_DayWeather_WeatherSystem_C`，同族另有 `CloudSystem` / `RegionTimeOfDay` / `Agent`，**共 5 类** | 不要按类名数量推断“几种天气” |
| 2 | 实测 **17 个天气 Actor / 5 类** ⇒ **同一个类重复多份**（按区域各一份） | **不要**把 actor 数（17）当作“17 个天气系统” |
| 3 | `secondsUntilChange = 1000` 是**相对剩余秒数**；Ext 的同名字段是**绝对世界时间戳** | 同一字段名两种语义，**按图区分**：Gen / Rag / Ast / Val / Los 为相对，Ext 为绝对 |
| 4 | ⚠️ **`currentWeatherId` 读不出来**（`null`）：Gen 把天气枚举放在 **8 字节槽**里，按 double 读是次正规垃圾值，插件按不可读处理并计入 `semUnreadable`（实测 3） | **Gen 上看不到“当前是哪种天气”的名称或编号**，只能看倒计时 / 过渡 / 强度 |
| 5 | 无 `Weather_Override_Volume` | `zones` 恒 `count=0`，入口隐藏 |
| 6 | `timeOfDay = 2088.29`（游戏内秒数，递增） | 可直接显示“游戏内时刻” |

**Gen 上可用的天气字段**：`currentWeatherId`(null) / `nextWeatherId`(null) / `secondsUntilChange` / `inTransition` / `transitionBegin` / `transitionElapsed` / `transitionEnd` / `changeIntervalMin` / `changeIntervalMax` / `hasWeatherTimer` / `weatherTimerEnabled` / `nextWeatherAt` / `nextWeatherReplicated` / `temperatureOffset` / `weatherSoundRegionMul` / `timeOfDay` / `semFieldsFound` / `semUnreadable`。

> ⏳ 若前端**必须**拿到 Gen 的天气名：那 5 个类里是否另有可读的天气枚举**尚未验证**，需专项探测（优先 `Agent` / `CloudSystem`）。

## 附-9 ⚠️ 老式地图（UDS 派系）**没有「下一个天气」**（2026-10-04 查证）

### 附-9.1 结论先行
**Sco / Isl / Cen 这三张老图，游戏本身不提供「下一个天气」**。前端若依赖 `nextWeather` 字段，在这三张图上**永远拿不到值** —— 这是**游戏机制差异，不是插件漏读**。

### 附-9.2 根因：两派系的天气生成方式不同

| 派系 | 地图 | 「下一个天气」 | 机制 |
|---|---|---|---|

对 5 个「类型未知」槽位同时给出多种解释，前端**只需看哪一个非空**：

|---|---|---|
