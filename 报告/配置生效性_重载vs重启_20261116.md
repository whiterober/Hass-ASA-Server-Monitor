# Server Ops Kit · 配置生效性对照（重载 vs 重启）

- 适用版本：**ServerOpsKitAPI / ServerOpsKitTomb / ServerOpsKitLease 1.05**
- 代码依据：`TransferIdentityFixAPI.cpp`
  - `Plugin::Load()` L1590-1666（启动时的一次性初始化）
  - `Plugin::LoadConfig()` L1734-1920（配置解析，共 47 个键）
  - `Plugin::CmdReloadConfig()` L4771-4785（命令 `TransferIdentityFix.ReloadConfig`）
  - `Plugin::CmdReload()` L4786-4892（命令 `TransferIdentityFix.Reload`）
- 结论均为读源码逐行核对，不含推测

---

## 0. 一句话结论

**绝大多数配置改完执行重载即可生效；只有 1 个键（`language`）和 2 个台账相关项（`history_max_rows`、台账文件路径）必须重启服务器；另有 3 个键是死配置，改了完全没用。**

---

## 1. 两条「重载」命令的行为差异

| 命令 | 实际做了什么 | 没做什么 |
|---|---|---|
| `TransferIdentityFix.ReloadConfig` | `LoadConfig()` 重读全部键 → `game_access_->SetReconnectHost()` → 打印 `CONFIG_RELOADED` | 不重注册命令、不重挂 hook、**不重跑 `SetLanguage()`**、**不重跑 `HistInitSinks()`** |
| `TransferIdentityFix.Reload` | 先卸载 hook/命令，再 `LoadConfig()` → `SetReconnectHost()` → `RegisterCommands()` → 重挂全部 hook → `TifHookLogSummary("reload")` | **仍然不重跑 `SetLanguage()`**、**仍然不重跑 `HistInitSinks()`** |

- 两条命令都要求权限 `tif.operator`
- 结论：**指望「热重载」解决语言和台账问题是不成立的**，这两块必须重启进程

## 3. B 类 · 必须重启服务器（1 项 + 2 个台账副作用）

| 项 | 为什么 | 代码依据 |
|---|---|---|
| **`language`** | `tif::l10n::SetLanguage(config_.language)` **只在 `Plugin::Load()` 里调用一次**；`ReloadConfig()` 和 `Reload()` 都没有调用它 | 调用点 L1596；两条重载命令 L4771-4892 全文无 `SetLanguage` |
| **`history_max_rows`** | 只在 `HistInitSinks()` 里调 `HistTrimFile()` 裁剪一次；运行期 `HistFlush()` 不检查行数上限 | 赋值 L1914；裁剪 L2006-2007；`HistFlush()` L1938-1974 无 max_rows 判断 |
| **台账文件路径**（`<abbr>_tomb_history.tsv` / `<abbr>_borrow_history.tsv`） | 路径在 `HistInitSinks()` 里一次性拼好并缓存到 `tomb_hist_.path` / `borrow_hist_.path`，之后只用缓存值 | L2000-2001 |

> 关于 `language` 的实际体验：改完执行 `ReloadConfig` 或 `Reload`，游戏内文案**仍然是旧的**，但 `config_.language` 值已经变了 —— 日志 `i18n language=` 那一行不会再打印，容易被误判成"生效了"。必须重启才能看到文案切换。

## 4. C 类 · 有条件生效（2 项）

| 配置键 | 生效方向 | 说明 |
|---|---|---|
| `history_enabled` | **`true` → `false` 立即生效** | `TombHist()` L1905 / `BorrowHist()` L1911 每次都判断 `config_.history.enabled`，关掉后立刻停止入队 |
| `history_enabled` | **`false` → `true` 不生效，需重启** | `tomb_hist_.disabled` / `borrow_hist_.disabled` 只在 `HistInitSinks()` L1997-1998 赋值；**全代码没有任何地方把它置回 `false`**；而 `HistFlush()` L1939 遇到 `s.disabled` 直接返回 |
| `dino_data_dir` | **部分生效** | 其它所有通过 `ResolveDataDir()`（L22704）取目录的写入点会读新值；但**台账 sink 的路径不会更新**（见 B 类第 3 条），台账继续写旧目录 |

## 5. D 类 · 死配置（改了完全没用，3 项）

| 配置键 | 现状 | 依据 |
|---|---|---|
| `port`（reconnect 段） | 只在 `LoadConfig()` L1785 被赋值，**全代码无任何读取点** | 全文件搜索 `config_.reconnect.port` 仅 1 处（赋值） |
| `sidecar_enabled` | 只在 `LoadConfig()` L1807 赋值；唯一"使用"是 ArkStatus JSON 里回显 `sidecarEnabled` | L22943；L25205 注释明确写 "M3 plan item 7: no automatic sidecar on save" |
| `history_record_denied` | 只在 `LoadConfig()` L1915 被赋值，无读取点 | 全文件搜索仅 1 处 |

> 前端建议：这三个不要在运维界面做成"可调开关"，否则用户改了没反应会当成 bug 报。

## 6. 前端实现建议

1. **`language` 字段旁必须显式提示"修改后需重启服务器"**，重载成功后不要提示"已生效"。
2. **`history_enabled` 做成两态不同提示**：关闭 = 即时生效；开启 = 需重启。
3. **`history_max_rows` 修改后提示"下次启动生效"**（不会立刻裁剪现有文件）。
4. **`dino_data_dir` 修改后提示"历史台账仍写原目录"**，避免用户以为搬走了。
5. **重载按钮**调用 `TransferIdentityFix.ReloadConfig`（轻量）即可；只有改了 hook 相关问题时才用 `Reload`。
6. **重载结果校验**：看返回的 `CONFIG_RELOADED ... host=... enabled=... whitelist_count=...`，或直接读日志。
7. **权限**：两条重载命令都需要 `tif.operator`，权限不足会被拒绝且无副作用。

## 7. 自己复核的方法

| 想验证的事 | 怎么做 |
|---|---|
| 重载是否真的执行了 | 日志里搜 `CONFIG_RELOADED`；`Reload` 则是搜 `plugin reloaded` |
| 改 `language` 是否生效 | 看游戏内通知文案语言；不要只看配置文件 |
| 台账是否写去新目录 | 改 `dino_data_dir` → 重载 → 触发一次记录 → 看新目录有没有新的 `_tomb_history.tsv`（预期：没有） |
| 版本号是否换了 | 启动日志 `plugin loaded version=`（只在启动时打印，重载不会重打） |
