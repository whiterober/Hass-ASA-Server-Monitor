### 1.2 协议

标准 Source RCON：认证（Type=3）→ 发命令（Type=2）→ 收响应（Type=0，正文为 JSON）。

实现参考项目内脚本 `TransferIdentityFixAPI/scripts/rcon_client.py`：

```python
from rcon_client import send_rcon_command_sync
ok, payload = send_rcon_command_sync("work.whiterober.cn", 32321, "1219wu1219",
                                     "TransferIdentityFix.Broadcast chat 服务器即将重启")
# ok=True, payload='{"ok":true,"kind":"chat","target":"all","msg":"服务器即将重启"}'
```

命令行：`python rcon_client.py <host> <port> <password> <command>`

## 2. 广播命令总览

| # | RCON 命令 | 参数 | 范围 | 返回 |
|---|-----------|------|------|------|
| 1 | `TransferIdentityFix.Broadcast` | `<banner\|notify\|chat> <消息>` | 全服 | **JSON** |
| 2 | `TransferIdentityFix.BroadcastPlayer` | `<eosid> <banner\|notify\|chat> <消息>` | 单玩家 | **JSON** |

### 2.1 `TransferIdentityFix.Broadcast <kind> <消息>`

向**全服所有玩家**推送通知。kind 取值：

| kind | 显示形态 | 效果 |
|------|---------|------|
| `banner` | 顶部横幅大字（红字） | `SendServerMessageToAll`，最醒目，适合公告 |
| `notify` | 屏幕通知（白字，5 秒） | `SendNotificationToAll`，右上角弹窗 |
| `chat` | 聊天栏消息 | `SendChatMessageToAll`，显示在聊天框（默认） |

**返回 JSON：**

```json
{ "ok": true, "kind": "chat", "target": "all", "msg": "服务器即将重启" }
```

参数错误（如缺少消息）返回：

```json
{ "ok": false, "error": "usage: TransferIdentityFix.Broadcast <banner|notify|chat> <message>" }
```

### 2.2 `TransferIdentityFix.BroadcastPlayer <eosid> <kind> <消息>`

向**指定玩家**（按 EOSID）推送通知。kind 与 2.1 相同，仅作用到单个玩家。

**返回 JSON：**

```json
{ "ok": true, "kind": "banner", "target": "<eosid>", "msg": "你的借用已恢复" }
```

> 玩家不在线 / EOSID 不存在时：插件仅写日志警告，不发送、不报错（`ok` 仍为 true）。前端如需确认送达，可先调用现有查询接口确认玩家在线。

---

## 3. 参数说明

| 参数 | 说明 |
|------|------|
| `kind` | 通知形态：`banner` / `notify` / `chat`（缺省按 `chat` 处理） |
| `eosid` | 玩家 EOSID（跨服唯一标识），获取方式见现有查询接口返回 |
| `消息` | 支持中文与空格；含引号/反斜杠时注意 RCON 与 JSON 转义 |

> ⚠️ 消息长度建议控制在 200 字符以内，避免客户端显示截断。

---

## 4. 前端调用建议

1. **发送全服公告**（如重启通知、活动公告）：`Broadcast banner <消息>`
2. **发送普通提醒**：`Broadcast notify <消息>`
3. **发送聊天栏消息**：`Broadcast chat <消息>`
4. **定向通知单玩家**：`BroadcastPlayer <eosid> notify <消息>`

> 与借建筑功能联动：借用到期自动归还时插件会直接向借用人发单玩家屏幕通知（黄色 5 秒），无需前端调用。

---

## 5. 注意事项

- RCON 密码敏感，勿写入前端代码 / 日志；建议由后端服务（如 HA AppDaemon）统一封装。
- 广播命令走 RCON 通道级认证（密码），命令级不校验额外权限（`tif.operator` 设计，实服以实际为准）。
- 消息含双引号 `"` 或反斜杠 `\` 时，RCON 命令与返回 JSON 均需转义。
- 前端可参考现有「恐龙突变查询」接口的前端→后端→RCON 通路复用连接管理。
