# 基因数据接入报告（前端）

> 日期：2026-08-14 · 对象：前端开发者
> 目的：说明 **三个来源** 的基因数据如何统一接入、如何翻译中文。**核心原则：JSON 不存中文，全部由前端翻译。**

---

## 1. 三个来源的基因数据

| 来源 | 数据文件 | 基因形态 | trait 名形态 | 等级字段 |
|------|---------|---------|-------------|---------|
| **球内基因**（cryopod/低温仓） | exe 输出 JSON → `cryopod[].geneTraits` | `{trait, stacks}` | **PascalCase**（如 `Cold`、`PlantCarrier`、`Sprinter`） | `stacks`（层数 1/2/3） |
| **生物身上基因**（tamed/驯服龙） | 插件 dll `<abbr>_tamed.json` → `geneTraits` | `{trait, stacks}` | **PascalCase**（如 `Athletic`、`CarcassCarrier`） | `stacks`（层数 1/2/3） |
| **基因台/基因枪**（exe 新增） | exe 输出 JSON → `geneDevices[].slots` | `{f52, f84, f88, trait, level}` | **小写**（如 `cold`、`plantcarrier`） | `level`（1/2/3） |

> **球内 + 生物身上** 同属 `{trait, stacks}`（PascalCase）；**基因台/枪** 是新增的 `geneDevices`（小写 trait + level）。

---

## 2. 统一翻译方案（前端职责）

### 2.1 一份中文字典，兼容两种键

字典文件：**`trait_cn_dict.json`**（随本报告附上，51 词条）。

```json
{
  "trait_to_cn": {
    "carcasscarrier": "尸体资源-减重",
    "athletic": "健壮",
    "...": "共 51 项"
  },
  "trait_to_internal": {
    "athletic": "Athletic",
    "inheritfoodfrail": "InheritFoodFrail",
    "...": "PascalCase 内部名映射（球内/生物身上用）"
  }
}
```

### 2.2 前端翻译函数（推荐）

```js
// 字典：trait_to_cn（小写）+ trait_to_internal（小写->PascalCase）
// 统一入口：输入任意来源的 trait 名（小写或 PascalCase），输出中文。
function geneCn(trait) {
    if (!trait) return '未知基因';
    const key = trait.toLowerCase();          // 统一小写
    return DICT.trait_to_cn[key] || trait;    // 命中中文，否则回退原 trait 名
}
```

- **球内/生物身上**：`geneCn("Cold")` → 小写 `cold` → `"寒冷"` ✓
- **基因台/枪**：`geneCn("cold")` → `"寒冷"` ✓
- 未命中（未知 f84）→ 返回原 trait 名，前端可显示"未知"

> 字典内置在前端即可；新增基因只需更新前端字典，**无需重编译 exe / 改 JSON**。

## 3. 各来源字段说明

### 3.1 球内基因（cryopod）—— 原有字段，未变

```json
"geneTraits": [
  {"trait": "Cold", "stacks": 2},
  {"trait": "PlantCarrier", "stacks": 1}
]
```

### 3.2 生物身上基因（tamed）—— 原有字段，未变

```json
"geneTraits": [
  {"trait": "Athletic", "stacks": 1}
]
```

### 3.3 基因台/基因枪（geneDevices）—— 新增字段

```json

    "key": "1b7ad3f6...",
    "class": "StructureBP_GeneInfuser_C_2146927175",

    "class": "PrimalItem_WeaponGeneScanner_C_2146852831",
    "type": "geneScanner",
    "isBlueprint": false,        // 蓝图标记：制造设施固化空模板=true，玩家真实物品=false
    "tribeId": 0, "tribeName": "",

    "containerId": "d75129f376205a4baa03984aa421a1c6",

    "containerOwnerEosId": "00025a2b9cf14195b9714edd4ee38ac5",

    "containerX": 5819.62, "containerY": 10584.83, "containerZ": -20824.75,  // 容器世界坐标

```

| 字段 | 说明 |
|------|------|
| `f52` | 来源物种 id（即 DinoEntry FName id 的 uint32 形式） |
| `f84` | 词条+等级组合 id（唯一标识，稳定） |
| `f88` | 词条 id（1 字节） |
| `trait` | 词条名（小写；未知 f84 则空串） |
| `level` | 等级 1/2/3（未知 = 0） |
| `species` | **来源物种简称**（自动翻译）：exe 从存档 DinoEntry 表把 f52 翻译成图鉴简称（如 `Mantis`/`Baryonyx`/`Wyvern`/`Direbear`）。覆盖该存档内已加载的物种；未命中留空 |
| `dinoClass` | **来源物种 Character_BP 基名**（自动匹配 + 静态兜底）：exe 先把物种简称匹配到该存档 name table 中的 `Character_BP` 基名（如 `Mantis_Character_BP`/`Baryonyx_Character_BP`）；**匹配不到时回退 `gene_map.json` 的 `f52_to_dinoClass` 静态表**，保证该存档未加载的物种也能给出正确 class。特殊物种别名已处理（见下） |
| `containerId` | **仅 geneScanner**：基因枪所在容器（inventory）uuid（玩家背包/箱子等） |
| `containerType` | **仅 geneScanner**：容器类型 `player`/`storage`/`other` |
| `isBlueprint` | 蓝图标记（`geneScanner` 与 `cryopod` 均有）：**true=制造设施固化空模板**（Fabricator/TekReplicator 官方生成的空基因枪/空低温仓，非玩家物品）；false=玩家真实物品（含真空枪）。前端可据此隐藏/标记/检索蓝图（为蓝图检索做基础），**不直接过滤** |
| `containerClass` | **仅 geneScanner**：容器蓝图类（如 `PrimalInventory1`=玩家背包、`PrimalInventoryBP_Fabricator_C1`=工作台、`PrimalInventoryBP_TekReplicator_C1`=泰克复制器等）。前端 `lbOtherContainer` 可直接用它解析孤儿容器具体类别 |
| `containerTribe` | 容器所属部落 id |
| `containerOwnerPid` | **仅 geneScanner**：背包所有者 PlayerDataID（`containerType=player` 时有效） |
| `containerOwnerEosId` | 背包所有者 EOSID |
| `playerName` | 背包所有者玩家名（如 `板板`） |
| `containerX/Y/Z` | **仅 geneScanner**：基因枪所在容器的世界坐标（与 cryopod 同机制：container_id→容器宿主→ActorTransforms）。玩家背包/箱子/建筑均有坐标，前端可直接在地图定位 |

> **物种名说明**：`dinoClass` 优先用存档 name table 自动匹配（覆盖大多数物种），**匹配不到时回退 `gene_map.json` 静态表**（`f52_to_dinoClass`），因此即使某存档未加载某物种（如孤岛有 Bronto 基因但存档无 Bronto 龙），也能正确给出 class。**特殊别名**（已验证，Beacon/ArkIDs/wiki 交叉确认）：
> | DinoEntry 简称 | dinoClass | 中文 |
> |---|---|---|
> | Bronto | `Sauropod_Character_BP` | 雷龙 |
> | SnowOwl | `Owl_Character_BP` | 雪鸮 |
> | CaveCrab | `Crab_Character_BP` | 巨蟹（Karkinos） |
> | LanternPetGoat | `LanternGoat_Character_BP` | 闪角兽（Shinehorn） |
> | Nameless | `Xenomorph_Character_BP` | 无名怪 |
> | Gasbags | `GasBags_Character_BP` | 气囊虫 |
> | Procoptodon | `Procoptodon_Character_BP` | 短面袋鼠 |
> | Camelsaurus | `camelsaurus_Character_BP` | 驼峰龙 |
> **归属展示**：前端可用 `containerOwnerPid`/`playerName` 把基因枪归到具体玩家；`containerType=player` 即玩家背包。基因台（geneInfuser）是建筑，用 `tribeId`/`tribeName`/坐标归属聚落，容器字段为空。

## 4. 前端接入清单

1. 内置 `trait_cn_dict.json`（或合入前端字典模块）
2. 实现 `geneCn(trait)` 统一翻译（见 2.2）
3. 三个来源分别渲染：
   - 球内/生物身上：`geneTraits[]` → `geneCn(t.trait)` + 级数 `t.stacks`
   - 基因台/枪：`geneDevices[].slots[]` → `geneCn(s.trait)` + 级数 `s.level`
4. 可选：`geneDevices` 用 `type` 区分基因台/基因枪，`tribeName`/坐标做归属展示

## 7. 设施清单 facilities（2026-08-15 新增）

**目的**：前端要显示"完全空的低温冰箱"等**任何设施**（包括无球/无 Inventory 的），必须知道设施存在及其元信息。

### 判定规则（反向法）
除以下类别外，存档中带坐标的设施对象全部输出：
- **建筑构件**：墙/地板/柱子/门/栅栏/屋顶/楼梯/地基/窗/梯/平台/斜坡/转角等
- **非设施**：物品/武器/资源/弹药/护甲/皮肤/画作/蓝图/AI控制器/种植盆/耕地等
- **已单独输出**：基因台/基因枪（geneDevices）、床/棺材（structures）、低温球（cryopod）

### 输出字段（顶层 `facilities`）
```json
"facilities": [
  {
    "key": "b05cf16a...",       // 设施对象 16B key
    "class": "CryoFridge_C_2146483485",  // 完整类名（设施实体形态）
    "name": "",                  // 玩家命名（BoxName）
    "tribeId": 1912594779,       // 所属部落
    "tribeName": "xxx",
    "x": -301883.81, "y": 164395.92, "z": -14483.9   // 世界坐标
  }
]
```

### 关键点
- 设施**实体**类名多为裸设施名（`CryoFridge_C_xxx`/`StorageBox_Large_C_xxx`），带坐标+部落；物品模板形态（`PrimalItemStructure_*`）无坐标
- 前端可用 `class` 匹配图标库 174 个设施图标（`https://img.whiterober.ccwu.cc/ASA/facility/xxx.png`，如 `Cryofridge`）
- 空容器（如无球的低温冰箱）通过 facilities 显示，`cryopod` 只管球
- Isl 实测：facilities 8034（CryoFridge 120 / StorageBox 345 / Fabricator 59 等），全部带坐标+部落
