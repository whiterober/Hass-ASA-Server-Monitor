# 后端补采需求：耕地肥料物品（2026-09-20）

> 提出人：前端（dino-import 玩家/聚落视图）
> 结论一句话：**整服数据里没有肥料** —— `itemsByServer` 搜 `Fertilizer / Deposit_Fertilizer / Feces / Poop` = **0 条**，前端无处显示。

---

## 一、实测证据（线上生产数据）

| 检查项 | 命令/口径 | 结果 |
|--------|-----------|------|
| 耕地 rec（`recs`） | `containerClass` 含 `CropPlot` | **293 条，全部 `empty:true` / `items:0` / `src:'facility'`** |
| 耕地内容物（`itemsByServer`） | `containerClass` 含 `CropPlot` | **284 条**（`kind` = `consumable:283` / `resource:1`），类名全是浆果/蔬菜（Tintoberry 49、Mejoberry 43、Citronal 36…） |
| 肥料（全局） | `itemsByServer` 搜 `Fertilizer` / `Deposit_Fertilizer` / `Feces` / `Poop` | **0 条** ❌ |

> 即：**耕地里的浆果/蔬菜有采（在物品索引里），但肥料一条都没有** ⇒ 不是前端过滤掉，是数据源缺失。

---

## 二、用户口径（需求）

> 原话：「**肥料是属于消耗品，理论上应该当作消耗品显示的，耕地现在本来就能展开**」

⇒ 肥料应按 **`kind = 'consumable'`（消耗品）** 采集，跟着耕地一起进 `itemsByServer`，前端**无需改展示逻辑**（耕地已可展开，容器已有渲染通道）。

---

## 三、请求补采内容

### 1. 采集对象
ASA 中与耕地相关、且属于消耗品的肥料类物品，至少覆盖：

| 游戏内物品 | 类名（典型） | 说明 |
|-----------|--------------|------|
| 化肥 | `PrimalItemConsumable_Fertilizer_Compost` | 基础肥料 |
| 化肥（高级） | `PrimalItemConsumable_Fertilizer_Compost_Advanced` | 高级肥料 |
| 肥料箱内容物 | 同上（容器 `FertilizerBin` / `CompostBin`） | 肥料箱里的存量 |
| 恐龙粪便 | `PrimalItemConsumable_DinoPoop*` | 可作肥料使用（若项目口径包含请一并采） |

> 类名以实际游戏资产为准，**以类名前缀匹配 `Fertilizer` / `Compost` / `Poop` 为准**，不限于上表。

### 2. 采集字段（与现有物品结构对齐）

每条物品需包含现有字段（保持与其它物品同构，前端零改动即可显示）：

| 字段 | 说明 |
|------|------|
| `containerClass` | 所属容器类名（如 `FertilizerBin` / `CropPlot` 等） |
| `containerId` | 容器实例 id |
| `containerX/Y/Z` | 容器坐标（用于就近归属聚落） |
| `containerTribe` | 部落 id |
| `kind` | **`consumable`** ✅ |
| `qidx` | 品质索引（无品质填 0/null） |
| `count` | 数量 |
| `server` | 服务器标识 |

### 3. 容器侧（可选但建议）
若肥料是**放在独立容器**（肥料箱/堆肥箱）里，请**同时补该容器的 `recs` 条目**（`containerClass` / `containerId` / 坐标 / `items`），这样前端容器手风琴会自然成组，无需特殊处理。

---

## 四、前端现状（说明为什么需要后端补）

- 容器组渲染 = **`recs`** 驱动；物品明细 = **`itemsByServer`** 驱动。
- 耕地：`recs` 有 293 条（可展开 ✅），物品有 284 条（浆果/蔬菜 ✅） ⇒ **只差肥料几条**。
- 前端**不会也无法**凭空造出肥料：没有源数据。
- 补充：恐龙背包（`DinoTamedInventoryComponent_*`）存在**反向情况**（物品 8049 条、`recs` 仅 1 条空记录），前端已用 **v3448 虚拟容器组**兜底显示；若后端能把这类容器 `recs` 补全，前端兜底逻辑可保留亦可移除（更准）。

---

## 五、验收标准

1. `itemsByServer` 全局搜 `Fertilizer|Compost` **> 0 条**；
2. 肥料记录 `kind === 'consumable'`；
3. 前端耕地容器展开后，**肥料以消耗品形式出现**（与浆果/蔬菜同一列表）；
4. 肥料箱若被采集为独立容器，容器手风琴中出现对应容器组。
