## 一、需求

1. **泰克专用储物箱**（`Dedicated Storage` / `BP_DedicatedStorage_C`）要显示**当前装的是什么**（物品清单）。
2. **建立"资源"的 类名 → 权威英文 → 中文 → 图标 体系**，且与现有「物种」「设施」体系**同构**。

## 二、调研结论（实测）

### 2.1 数据链路：已具备（无需新增 RCON 能力）

| 层 | 位置 | 说明 |
|----|------|------|
| 插件命令 | `TransferIdentityFix.InvProbe <filter> <tribeId> <maxContainers>` | RCON 直接返回 JSON，不落盘 |
| 后端封装 | `独立后端/dino_backend.py` → `inv_probe()` | 暴露为 `POST /api/inv_probe` |
| 返回结构 | `{ok, filter, tribeId, containers, items, list:[{type,class,id,team,itemCount,items:[{slot,class,qty,dur,name}]}]}` | `type`=structure/dino/player |
| 前端已有消费者 | `dino-import.html`「食物源」（`lbWatchFoodScan` → L7037-7076） | 已在消费 `ct.items`（`lbFoodWl` 白名单 + `lbFoodName` 命名） |

### 2.2 硬约束（必须遵守，来源：官方调用文档 §4）

1. **RCON 响应约 8KB 上限** → 单次 `maxContainers` **建议 ≤5**，或带精确 `filter`/`tribeId`；解析失败必须提示"结果过大，请缩小范围"。
2. **每容器物品上限 250**；`itemCount` 含空槽，**实际数量以 `items.length` 为准**。
3. `tribeId` 是**单部落**过滤（联盟需逐成员部落查）。
4. 洞穴/空投补给箱 `team=0`，空 filter 时会**抢占返回列表**。
5. `dur=-1` 表示读取失败；`{ok:false,error:'world not ready'}` 表示地图未就绪（可稍后重试）。

### 2.3 现有三大体系盘点

| 体系 | 载体 | 结构 | 规模 | 前端函数 |
|------|------|------|:---:|----------|
| **物种** | `汉化/icon_zh_map.json`（键=短名/图标名，值=`中文[English]`）+ 引用目录 `ARKStatsExtractor-dev/ASA-values.json`（`species` 1128 条，`blueprintPath`+英文名）+ `icons2.json`（biology/eggs） | 松散键值 | 5070 / 1128 | `lbSpeciesMatch` / `lbIconForDinoClass` |
| **设施** | `汉化/facility_zh.json` → 服务器 `/config/www/asa-data/facility_zh.json` | `{基名:{icon,en,zh}}` | 180 | `lbSettleFacMeta` / `lbFacilityZhLoad` |
| **资源/物品** | **（缺）** | — | — | 仅有食物专用 `lbFoodName` / `lbFoodWl` |

### 2.4 可用料（实测数据）

- **`icons2.json`（5057 项）目录分布**：GUI 1120 / skins 688 / biology 358 / emote 353 / structures 346 / status 307 / drops 237 / illustrations 218 / misc 207 / facility 174 / saddles 171 / consumables 165 / eggs 135 / **resources 107** / tools 85 / armor 80 / attached 76 / keys 76 / weapons 72 / ammo 49 …
- **`resources` 目录样本（107 项）**：`Metal_Ingot`、`CementPaste_Icon`、`Polymer`、`Organic_Polymer`、`Hardened_Steel_Ingot`、`Black_Pearl`、`Chitin`、`Obsidian`、`Fiber`、`Blue_Gem`、`Charcoal`、`AnglerGel`、`Absorbent_Substrate`、`ScrapMetalIngot_Icon` …
- **`icon_zh_map.json`（5070 键）**：值形如 `"金属锭[Metal Ingot]"`、`"似鸡龙鞍[Gallimimus Saddle]"`；键风格为**小写短名/图标名**（`metal_ingot`、`hardened_steel_ingot`、`gallimimus_saddle`）；`primalitem` 前缀键为 0。
- **`ASA-values.json`**：`species` 1128 条（`{"blueprintPath": "/Game/ASA/Dinos/...", "name": "Acrocanthosaurus"}`）→ **生物权威英文名源**。
- **`facility_zh.json` 生成范式**：`汉化/_build_facility_zh.py`（表在服务器维护、免发版；前端 `authFetch(LB_ASA + '/facility_zh.json?v=' + LB_VERSION)`）。

## 三、资源体系设计（与设施体系同构）

### 3.1 表结构：`汉化/item_zh.json`

```json
{
  "Metal":        {"en": "Metal Ingot",     "zh": "金属锭",   "icon": "Metal_Ingot"},
  "CementPaste":  {"en": "Cementing Paste", "zh": "水泥糊",   "icon": "CementPaste_Icon"},
  "Polymer":      {"en": "Polymer",         "zh": "聚合物",   "icon": "Polymer"},
  "OrganicPolymer": {"en": "Organic Polymer", "zh": "有机聚合物", "icon": "Organic_Polymer"}
}
```

- **键 = 类名基名**：`PrimalItemResource_Metal_C` → `Metal`；`PrimalItemConsumable_CookedLambChop_C` → 去 `PrimalItem*_` 前缀后归一。
- **字段**：`en`（权威英文）/ `zh`（权威中文）/ `icon`（`icons2` 键名，可空）。
- 与 `facility_zh.json` 完全同构（`{基名:{en,zh,icon}}`），复用同一套加载/兜底逻辑思路。

### 3.2 生成流程：`汉化/_build_item_zh.py`

1. **类名采样**：跑一轮 `InvProbe`（按部落分批 + 宽 filter）收集**实际出现的物品 class 清单** → 归一为基名集合（去重、排序）。
2. **匹配优先级**（逐级兜底）：
   1. **中文/英文**：`icon_zh_map.json` 按基名小写 / 去下划线 / 单词连写变体查值 → 拆 `中文[English]`；
   2. **英文补源**：引用目录 `ASA-values.json`（生物/物品名）与 `icons2` 名字；
   3. **图标**：基名归一 → 在 `icons2` 的 `resources` / `consumables` / `drops` / `tools` / `ammo` 目录名中匹配（归一规则同设施：去 `_Icon`/`_C`/数字尾）；歧义项进**特例表** `LB_ITEM_ICON_SPECIAL`（人工钉死，范式同 `LB_FACILITY_ICON_SPECIAL`）。
3. **特例表机制**：与设施体系一致——歧义/无直键项人工校对后写死在生成脚本中（参考 v911 设施特例表经验）。
4. **产物**：`汉化/item_zh.json` → SFTP 传 `/config/www/asa-data/item_zh.json` → CF 打包（`_sync_repack2.py` 已含 asa-data 来源逻辑需确认）。
5. **更新规则**：表更新后**必须递增 `LB_VERSION`** 破浏览器缓存（v95x 教训）。

### 3.3 前端函数（与 `lbSettleFacMeta` 同构）

| 函数 | 职责 |
|------|------|
| `lbItemZhLoad()` | `authFetch(LB_ASA + '/item_zh.json?v=' + LB_VERSION)` → `LB_ITEM_ZH`（缓存；失败置 `{}`） |
| `lbItemMeta(cls)` | 类名 → `{key, zh, en, icon}`（表未加载时走兜底链） |
| `lbItemZh(cls)` / `lbItemEn(cls)` / `lbItemIcon(cls)` | 便捷取单项 |
| `lbItemIconUrl(cls)` | `icon` → `LB_ICON_BY_NAME[icon]` → URL（同设施 `lbSettleFacChip` 图标取法） |

**兜底链**：`item_zh` → `icon_zh_map` → 类名美化（`en.replace(/([a-z0-9])([A-Z])/g,'$1 $2')`，同设施 `lbSettleFacMeta` 尾部规则）。

## 四、储物箱内容显示（功能设计）

### 4.1 交互流程

1. 容器手风琴（`lbBuildSettleContainerHtml` 渲染的 `<details class="acc">`）内新增「📦 查看内容」按钮（**仅对有容器的手风琴项/或统一放设施 chips 弹窗**）。
2. 点按 → `POST /api/inv_probe`，参数：`{server: 当前服, filter: 'StorageBox' 或该类名, tribe_id: 该聚落部落, max: 5}`。
3. **命中容器**：按 `id`（`<class>_<序号>`）或 `class+坐标` 匹配当前容器 → 渲染物品清单。
4. **未命中/超限**：提示"未扫到（可能超出本次范围）"并提供「重试」。

### 4.2 UI 设计

- **物品行**（复用现有卡片风格）：
  `[图标16px] 中文名 <灰小英文> ×数量`（样式对齐 `lbSettleFacChip` / `lbGeneTagHtml`）。
- **多物品**：瀑布流或两列网格（`lbColCount()` 断点逻辑可复用）。
- **状态四态**：加载中（spinner）/ 结果过大解析失败 / `world not ready` / 空箱（"📦 空"）。
- **自定义名**：`items[].name` 非空时优先显示（灰色注示系统名）。

### 4.3 缓存与性能

- `LB._invCache['<server>|<containerId>'] = {ts, items}`，TTL 60s；点「刷新」强制重查。
- 查询串行化（同食物源的 `LB._foodBusy` 队列思路），避免并发打爆 RCON。

### 4.4 范围

- **首期**：**泰克专用储物箱**（用户指定）。
- **架构通用**：filter 参数化 → 冰箱 / 保险柜 / 饲料槽 / 生物背包 / 玩家背包（type 已支持）。

## 四之补充、容器内容体系扩展（v2 需求，2026-09-10 追加）

> 用户补充：① 接入现有容器显示体系（球/基因/蓝图）并新增「资源、弹药」两类；② 不再限于泰克专储——**只要放了资源或弹药的容器都显示**；③ 补全**蓝图**显示逻辑。

### 4B.1 接入方式（现有注册表自动纳入）

- `LB_CONTENT_KINDS`（v822 可扩展注册表，`dino-import.html` L5695）已是设计好的扩展点：**追加一条即自动纳入渲染分流**（容器手风琴 vs 设施 chips），无需改分流代码。
- 现状：`ball`（低温球）、`gene`（基因枪）；预留注释：蓝图示例。
- **本次追加三类**：`resource`（资源）、`ammo`（弹药）、`blueprint`（蓝图）。
- `detect(cg, ctx)` 的 `ctx` **扩展新字段 `ctx.invItems`** = 该容器的库存扫描物品数组（用 `lbSameContainer(cg[0], …)` 按 containerId 或坐标命中）。

### 4B.2 数据源（v3 更新：item.gz 离线全量）

> **重大变更**：后端已提供 `<Srv>_item.json.gz`（`ark_save_reader.exe` 离线读档全量导出），**资源/弹药/蓝图三类物品不再需要 InvProbe 实时扫描**。详见 `报告/itemgz离线库存数据_前端调用文档_20260910.md`。

- **链路**：与 `cryo.json.gz` **完全同源**——`DINO_JSON + <abbr> + '_item.json'`（`.gz` 由既有 HEAD 探测逻辑决定，同 `cryoExt`）。
- **数据结构**：`{serverId, generatedMs, count, counts:{blueprint,ammo,resource}, items:[{type, class, key, quantity, durability, isBlueprint, rated, containerId, containerType, containerClass, containerTribe, containerTribeName, playerName, x,y,z}]}`。
- **容器粒度**（影响求和口径）：
  - 普通容器 = **逐堆明细**（同资源多条）→ 按 `containerId + 资源基名` **sum()**；
  - **泰克专储** = `containerType==='dedicated'`，**一柜一条**，`quantity` 即柜内总量（**直接用，不再聚合**）。
- **前端消费**：下载解压 → 按 `containerId` 建索引 + 坐标宓底索引 → **渲染时同步可查**（无需异步扫描/重渲染）。
- **注意**：`blueprint` 类已只保留 `rated=1`（固定印痕配方已过滤）；`generatedMs` 非 Unix 时间戳（要时间用文件 mtime）。
- **局限**：跟随存档（非实时）；死亡背包/掉落物不含；空专储不输出。

### 4B.3 分类判定规则

- `ammo`：`class.indexOf('PrimalItemAmmo_') === 0`
- `resource`：`class.indexOf('PrimalItemResource_') === 0`
- `blueprint`：**依赖物品 `isBlueprint` 字段**（见 4B.4）
- 容器行计数与标签：`资源×N` / `弹药×N` / `蓝图×N`（风格对齐现有 `✦N` / 圆点计数）。

### 4B.4 蓝图逻辑（补全）与外部依赖

#### 已有实现溯源（v192，全量检索结论）

- **唯一真实消费点**：`cryo.geneDevices` 加载时过滤蓝图态物品 ——
  `// v192：过滤蓝图物品（后端 isBlueprint=1=蓝图，如蓝图基因枪）；真实物品 isBlueprint=0/undefined 保留` → `if(d.isBlueprint===1) return;`
  （位于 cryo 下载回调内，作用面仅限「基因设备（基因台/基因枪）」。）
- **字段语义**：`isBlueprint` = `0/1`（1=蓝图），由 **cryo JSON 透传**（上游采集端产出）；`dino_backend.py` 内无该字段处理（grep 为空）。
- **现状缺口**：
  1. 无通用判定函数（建议新增 `lbIsBlueprintItem(o)` → `!!(o && o.isBlueprint === 1)`）；
  2. **`InvProbe` 未输出该字段**（实测物品项仅 `{slot,class,qty,dur,name}`）→ 容器内容体系 `blueprint` 类**仍需插件侧补字段**；
  3. `LB_CONTENT_KINDS` 中 blueprint 仍为预留注释，未接入。
- **其它 `Blueprint` 命中均为「物种蓝图路径 blueprintPath」语义**（L450/472/503/8567/9055 等），与「物品蓝图」无关，不参与本需求。

#### 依赖与处理（v3 更新：依赖已解除）

- **item.gz 已内置 `isBlueprint` 与 `rated` 字段**（文档 §4），且 `blueprint` 类已按 `rated=1` 过滤固定印痕。
- **因此：`blueprint` 类接入不再需要任何插件改动**——detect 直接用 `type==='blueprint'`（后端已分类）或 `isBlueprint`/`rated` 判定。
- **`InvProbe` 的 `isBlueprint` 补充需求作废**（保留可选，供实时链路用）。

### 4B.5 范围扩展（不限容器类型）

- 任何容器（储物箱/冰箱/保险柜/饲料槽/船坞…）只要命中 `ball` / `gene` / `resource` / `ammo` / `blueprint` 之一 → **进容器手风琴**；全不命中 → 下沉设施 chips（v821/v822 语义不变）。
- 渲染判定依赖「扫描结果」：未扫描容器按旧规则（球/基因）判定；扫描后若含资源/弹药则自动“升级”为容器行。

## 六、风险与约束

1. **RCON 8KB 截断**（已文档化）→ 单容器/小批量查询 + 容错提示；必要时按 itemCount 提示"内容过多，分页后续"。
2. **图标匹配准确率** → 特例表 + 人工校对（设施体系经验：v911 特例表 + 用户指认）。
3. **类名采样成本** → 需一次全服 InvProbe 扫描（依部落分批，注意 8KB 限制）。
4. **表更新破缓存** → 递增 `LB_VERSION` + `pwa/sw.js`（v95x 固化经验）。
5. **联盟场景** → `tribeId` 是单部落，联盟容器需逐部落查（可后续按需扩展）。
