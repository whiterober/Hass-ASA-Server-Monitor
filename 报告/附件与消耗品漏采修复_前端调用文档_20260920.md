## 一、变更概要

本次修复 4 个"物品采集漏采"问题，全部经存档 SQLite 直查证实，非推测：

| # | 现象 | 真根因 |
|---|---|---|
| 1 | 玩家附件「**马达**」（滑索马达）未收录 | 品质门控：该装备不携带任何品质属性，被当作"设施印痕占位"丢弃 |
| 2 | 消耗品「**肥料**」未收录 | **双重**：① 绝大多数肥料实例的 blob 里**根本没有 `ItemQuantity` 属性**（数量记在容器侧）→ 被"数量 ≤ 0 的消耗品"规则全灭；② 少数实例带 `bIsBlueprint` 标记 → 被类型识别成 blueprint → 再被品质门控丢弃 |
| 3 | 生物附件（**板车 / 铠护犬装备+鞍**）未收录 | 同 #1（品质门控） |
| 4 | **基因枪**未出现在普通物品列表 | 基因枪走的是专用分支，只写入 `geneDevices[]`，**从未进入 `items[]`** |

## 二、接口影响（前端必读）

### 2.1 新增 `kind` 取值：`"geneGun"`

基因枪现在**同时**出现在两处（原先只有前者）：

| 输出 | 位置 | 内容 |
|---|---|---|
| `<Abbr>_cryo.json.gz` | `geneDevices[]` | 完整槽位/物种数据（**与以前完全一致，未改动**） |
| `<Abbr>_item.json.gz` | `items[]` | 新增：`type="item"`, `kind="geneGun"`，字段与普通物品**完全同构**（key/class/quantity/durability/isBlueprint/rated/rating/qidx/stats/container*/customName…） |

```json
{
  "type": "item",
  "kind": "geneGun",
  "class": "PrimalItem_WeaponGeneScanner_C_2146337372",
  "key": "c989b3071b35a346b2092b0612178eac",
  "quantity": 0,
  "durability": 0,
  "isBlueprint": 0,
  "rated": 0,
  "rating": -1,
  "qidx": -1,
  "stats": [],
  "containerClass": "PrimalInventoryBP_StorageBox_Large_C",
  "containerType": "storage"
}
```

> **前端建议**：若前端已在用 `geneDevices[]`，**无需改动**；若要统一在物品列表里展示基因枪，按 `kind == "geneGun"` 过滤即可。两处数据不会互相覆盖。
>
> **v1.1 新增**：`geneDevices[]` 条目现已补齐与 `items[]` **同名同型**的品质字段（`quantity`/`durability`/`rated`/`rating`/`qidx`/`stats`），详见**第十章**。

## 四、仍不收录的内容（保持原设计，避免噪声）

**未定级的 `blueprint` 条目仍被排除**，理由是实测它们全部集中在**制造设施的印痕缓存**里：

| 容器 class | Isl 上未定级蓝图条数（示例：鞍类） |
|---|---:|
| `PrimalInventoryBP_AnvilBench` | 2690 |
| `PrimalInventoryBP_LibraryStorage` | 672 |
| `PrimalInventoryBP_TekReplicator` | 276 |
| `PrimalInventoryBP_Fabricator` | 119（武器类） |

这些是设施"我能造什么"的配方缓存表，每个设施对每个可造物品各存 1 份。
**若放宽收录，Isl 单图 blueprint 会从 2303 暴增到 18832（+16.5k 纯噪声）**，故保持排除。

> ⚠️ 因此前端**不要**用"某个类没出现 = 玩家没有该物品"来判断；判断真实持有请看 `containerType`（见第七章）。

## 五、字段语义补充（重要）

### 5.1 `quantity = 0` 的两种含义

部分消耗品（**肥料是典型**）的数量**记录在容器侧**，物品自身 blob 里没有 `ItemQuantity` 属性：

| 场景 | `quantity` | 含义 |
|---|---|---|
| 物品 blob 有 `ItemQuantity` 且为 0 | `0` | 空堆叠（**不收录**，保持旧行为） |
| 物品 blob **没有** `ItemQuantity` 属性 | `0`（导出值） | **数量未记录在物品上**，可堆叠数量需前端按业务处理（**本次开始收录**） |

`hasQuantity` 标志**未导出到 JSON**（避免接口变更扩大）；前端如需区分，可按 `class` 白名单处理肥料等特例。

### 5.2 未改动的字段
`key` / `class` / `type` / `kind` / `isBlueprint` / `rated` / `rating` / `qidx` / `stats` / `durability` / `dropLoc` / `customClass` / `customName` / `craftingSkill` / `worldTime` / `containerId` / `containerType` / `containerClass` / `containerName` / `containerTribe` — **语义与类型均未变化**。

## 七、前端判断建议

1. **判断"玩家真实持有"** → 优先看 `containerType`：`player` / `storage` / `fridge` / `display` / `other`（龙背包），避免把设施缓存误当玩家物品。
2. **生物附件识别** → 按 `kind ∈ {saddle, armor, attachment}` 且 class 命中下列模式：
   - 板车：`PrimalItemArmor_SaddleCart`
   - 滑索马达：`PrimalItemArmor_ZiplineMotor`
   - 铠护犬鞍 / 装备：`PrimalItemArmor_DinoCompanionSaddle*` / `PrimalItemArmor_DinoCompanion_Gear*`
3. **基因枪** → `kind == "geneGun"`；需要槽位/物种数据时仍从 `geneDevices[]` 取。
4. **肥料等消耗品** → 按 class 匹配 `PrimalItemConsumable_Fertilizer_Compost`，`quantity` 恒为 0，不要按数量过滤。

## 十、基因枪品质数据（v1.1 新增）

### 10.1 问题（前端反馈）
前端反馈：`items[]` 与 `geneDevices[]` **两个通道的基因枪都没有品质数据**。

### 10.2 核查结论（存档直查 + 对照实验）
- **`items[]` 通道品质解析本身正常**（Ext 实测有值，见 10.4）
- **`geneDevices[]` 通道结构上从来没有品质字段**（100% 复现）：修复前字段全集为
  `key / class / type / isBlueprint / tribeId / tribeName / x,y,z / containerId / containerType / containerClass / containerTribe / containerOwnerPid / containerOwnerEosId / playerName / containerX,Y,Z / slots[]`

对照实验（同一存档 + 同一解码器，证明“有品质必落盘”）：

| class | 对象数 | 带 `ItemStatValues` | 带 `ItemRating` | 带 `ItemQualityIndex` |
|---|---:|---:|---:|---:|
| `PrimalItem_WeaponMetalPick` | 169 | 105 | 105 | 105 |
| `PrimalItemArmor_MetalHelmet` | 119 | 57 | 57 | 54 |
| `PrimalItem_WeaponCrossbow` | 235 | 157 | 157 | 155 |
| `PrimalItem_WeaponGeneScanner`（Isl） | 52 | **0** | **0** | **0** |
| `PrimalItem_WeaponGeneScanner`（Ast） | 9 | **0** | **0** | **0** |
| `PrimalItem_WeaponGeneScanner`（Ext） | 15 | **2** | **2** | **2** |

> ⚠️ **重要**：Isl / Ast 上的基因枪**确实全部是白板（无品质）**，`rated=0` 是**事实而非故障**；Ext（灭绝）上有 2 把带品质的基因枪，可用作验证样本。

### 10.3 修复内容
`geneDevices[]` 条目新增 6 个字段，**与 `items[]` 同名同型**，便于前端统一处理：

| 字段 | 类型 | 说明 |
|---|---|---|
| `quantity` | int | `ItemQuantity`；0 = 物品自身未记录（数量可能在容器侧） |
| `durability` | int | 耐久（取整） |
| `rated` | 0/1 | 是否有品质 |
| `rating` | number | 品质评分，无则 `-1` |
| `qidx` | int | 品质等级索引，无则 `-1` |
| `stats` | int[] | 品质属性值（与 `items[]` 同一口径） |

### 10.4 实测验证（Ext 图，两通道同 key 比对）

| key | geneDevices `rated` | `rating` | `qidx` | `stats` | items[] 同 key |
|---|---:|---:|---:|---|---|
| `9c646f9937a2…` | **1** | **30.65** | **5** | `[25515, 42783]` | 完全一致 |
| `fc12e940808a…` | **1** | **14.15** | **5** | `[13696, 19777]` | 完全一致 |
| 其余 13 条 | 0 | -1 | -1 | `[]` | 完全一致 |

- 两通道 **15/15 条数值 100% 一致**（脚本逐 key 比对：无一处不一致）
- `geneDevices[]` 中的 `geneInfuser`（基因台·建筑）条目同样带这 6 个字段，值为默认（`rated=0 / rating=-1 / qidx=-1 / stats=[]`）——建筑无品质，属预期

### 10.5 前端建议
- 展示基因枪品质时，两个通道均可直接读 `rated` / `rating` / `qidx` / `stats`
- **不要**把 `rated=0` 当作“后端漏采”：请先确认该物在游戏中是否真的带品质（可用 10.2 对照法验证）
- 基因枪之间的“强弱差异”还体现在 `slots[]`（已装基因数、`level`），可从该字段补充展示
