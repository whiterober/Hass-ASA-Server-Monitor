# Rag 火山：`TimeNextVolcanoEvent`「读」实测反馈 —— 倒计时可用（0.36 秒误差）（2026-10-12）

> 对象：插件侧 · 对《Rag 火山：机制与查询口径说明（2026-10-12）》的实测反馈
> 方式：直连 `WorldProbe VolcanoManager` 每 30s 采样，完整跨过一次自然喷发（用户已在 Rag 配置打开火山事件）

---

## 一、背景

报告 §一.1 结论：「`TimeNextVolcanoEvent` 是镜像字段（写不生效）⇒ **不可当作"下次喷发时间"的可信来源**」。
但「**写**不生效」≠「**读**不准」——本次实验专门验证「读」。

## 二、实测（自然喷发，26 次采样跨过目标点）

| 阶段 | 数据 |
|---|---|
| 等待期（17 分钟，20 发） | `tNext` **钉死 238970594.67**（零变化；若为"每次刷新"的假值，绝对值会随时钟前移） |
| **喷发开始**（`TimeVolcanoEventStarted` 游戏真戳） | **238970595.03** |
| **预测 vs 实际** | **误差 = 0.36 秒** |
| 喷发时长 | 120.00s（= `VolcanoEventLength`） |
| **喷发后自动重排** | `tNext` 刷新 = 238978334.65；**新间隔 7739.62s ≈ 2.15h，落在 (5000,15000) 区间** ✔ |

**结论**：`tNext` 的「读」是**可靠的真倒计时**（0.36s 精度）；且每次喷发后自动重排 ⇒ **连续倒计时成立**。前端已按 `tNext − worldTime` 显示「距下次喷发」。

## 三、请求（文档级，低优先）

1. **建议修正报告 §一.1 / §二 表述**：「不可信」→「**读可信**（实测 0.36s 误差）；**写不生效**（写入不触发喷发）」；
2. **§三「喷发即将开始：无可靠字段」**同样建议修正为：`tNext` 可作预告来源（实测兑现）；
3. （可选）WorldProbe 响应里 `VolcanoIntervalMinMax` **仍返回原始 double（1.67e+31）**——「v102 双 f32 解码」未应用到此路径。若未来供前端使用，字节序参考：f64 hex `466a6000459c4000` → **前 f32 = 15000（Max）、后 f32 = 5000（Min）**；若插件侧直接返回解码值更佳；
4. （低优先）`ProjShotFrequency` 我方解出 f32 = 5.0 + 0.0（raw=2048），与报告 (0.5, 5) 不一致——请核对。

## 四、复现方法

```
POST /api/worldprobe_actor
{"server":"Rag","filter":"VolcanoManager","propsIdx":"0","top":"1","slim":"0"}
```
每 30s 采样 `TimeNextVolcanoEvent` / `VolcanoActive` / `TimeVolcanoEventStarted` + `volcanoHistory.lastEvent.at`，跨过 `tNext` 目标点比对即可复现。
