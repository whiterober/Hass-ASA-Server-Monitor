# 路线浮窗修正方案：冠军权重调度 + 合全能公降优先级

> 日期：2026-09-07
> 对象：路线浮窗（`lbRoutePlanHtml` / `lbRoutePlanHtml` 组生成，dino-import.html L12905 起）
> 类型：设计修正方案（独立报告，未改码）
> 目标口径（用户确认）：**最快速度推进"玩家选中的有效属性"的变异**——不是收敛成"全能冠军成品"，而是单位 CD 内有效变异推进量最大。
> 术语：冠军 = 玩家选中有效属性（`attrs`）里，全库存该属性最高值所在个体（对齐代码 `mxAll[k]` / `lbRoutePoint`）；权重 = 个体身上覆盖的冠军属性数。
> **改名说明（2026-09-07）**：本方案原称“换公代”的组统一更名 **合全能公**（职责 = 把分散的冠军/高基础属性合到目标公身上、补全全能公，与“顺带合体/收拢”同义）；**改名不影响深负公并入目标♂ 等负公合并逻辑**（原样保留）。

---

## 1. 为什么需要修正（现状问题）

### 1.1 现状实现逻辑（基于代码）

| 组 | order | 逻辑 |
|----|-------|------|
| 叠变异（全能公） | 1 主配 | 父本必须**所选属性全部 ≥ 全局最高**（`omni`，全部达 `mxAll` 才存在）→ × 公用 0/0 母群（`usedMothers` 达线优先）→ 变异落点 n/11 归各属性线推进 |
| 合全能公 | 1 主配 | `targetM`（=omni 或最负公或总分最高♂）基础未达 0/0 可及上限 → 用**覆盖属性的高基 0/0 母**提基础（跳过 `usedMothers` 已入池母） |
| 扩母群 | 2 主配 | 0/0 母池 < 目标数（`poolN`）→ 0/0×0/0 扩 0/0 母（`avail0` 充足时叠变异让渡只留 1 只启动） |
| 压垃圾 | 1 并行 | 线代表带未选垃圾点 → 洗剂清 0（≤3 并行） |
| 负变异线 | 4 并行 | 无负公时，闲置 0/0 种子对并行翻倍 → int32 溢出造负公（≤3 线） |
| 多线合并（金） | 可选常驻 | S（单组全覆盖）/ D（≤3 组分赌线最少）自动择优，把各线代表合并到全达顶 |

**统一资源池**：`usedMothers` —— 叠变异/合全能公优先占母，扩母取剩余（v741）。

### 1.2 现状的四个结构性弱点

1. **叠变异卡要求"全部选中属性都达顶"才存在（`omni`）**：只要有一个选中属性还没人达顶，全能公就不存在 → 整组不 push → 主配让位给"合全能公/打造全能公"。但此时**理应每轮都用一个"当前覆盖最多冠军的公种"去 × 母群推进**（哪怕覆盖 1~2 个冠军也比停摆强）——现状把"推进"锁死在"完美全能公"这一个形态上。
2. **合全能公与叠变异同 order 且共享母池**：合全能公（提基础）会跟叠变异（推进）抢 0/0 母与公种时间；但合全能公只是"打地基"，其产物最终仍要回归推进——地基没打完时主配不推进，等于 CD 空转在"准备"而非"推进"。
3. **冠军/权重没有作为"主配公种每轮选择"的显式调度**：现状 `omni` 排序只看"总数低 + 出生早"，没有"覆盖冠军数最多优先"的一般化选择逻辑（多属性全达顶时才等效）。
4. **目标错位**：现状隐含目标是"打造全能公/收敛成品"（叠变异 note 即"全达顶"）；用户目标是**推进速率最大化**——两者在"每轮用谁配、何时合全能公"上调度不同。

## 2. 修正方案核心

### 2.1 每轮主配 = 当前权重最高的公种（冠军贪心调度）

**规则**：
- 维护**库存冠军表**：对每个选中属性 k，冠军 = 全库存 `lbRoutePoint(r,k)` 最高的成年个体（= 现状 `mxAll` 的载体）；
- **主配公种** = 当前库存中**覆盖冠军属性数最多**（权重最大）的成年公；权重并列时，取：
  1. 变异总计数更低的（离 20 父锁更远，可推进更多层）；
  2. 层数总和更高的（账面更优）；
  3. 更早出生/更易得的（工程兜底）；
- **权重最高公种未成年且唯一** → 特例：改用"能补该公种未覆盖冠军属性"的次优公种先配（避免 CD 空转），直到主配长大；
- **主配不是完美全能公也没关系**：覆盖 1 个冠军就推进 1 个属性；覆盖越多，每 CD 的"有效命中转化率"越高（见 3.1）。
- **负公种公优先（2026-09-07 补充）**：一旦获得负变异公（变异计数溢出为负 → 永不触发 20 父锁、可无限叠），**且其至少覆盖 1 条冠军属性**时，**今后的种公必须优先/为负公——包括冠军权重最高的主配选择**；非负公反正会快速锁 20，负公是唯一能持续推进的父本。**负公 0 冠军（刚产出、身上无任何选中属性高值）不能直接作种公**——命中无可刷新的冠军 = 纯浪费 CD；先用顺带合体/收拢（2.3）把至少 1 条冠军并入负公，再作种公。负公未覆盖的其余冠军属性同样用顺带合体/收拢并入即可；**不因此提高合全能公组的执行优先级**（仍寄生空窗）。
- **负公合体冲刺（2026-09-07 补充）**：当已获得负公但 **0 冠军（无法作种公）** 时，**「合全能公」组优先级提到最高**——全力把至少 1 条冠军并入负公，**直到负公覆盖 ≥1 条冠军**（可上岗）；此后负公按上条规则优先作种公，「合全能公」组**恢复寄生空窗的低优先级**。依据：负公是突破 20 锁的稀缺钥匙，到手后应尽快使其可上岗；此冲刺窗口短（并入 1 条冠军即可），短暂让位推进是划算的。

**为什么对（推进速率视角）**：变异落点命中选中集（m/11）后，能否**刷新库存冠军**取决于公种该属性是否接近冠军——公种没带（低值）的属性被命中 +2 追不上库存高冠军 = 浪费。因此**公种覆盖冠军越多 → 命中浪费越少 → 每 CD 有效推进越多**。贪心选"覆盖最多冠军"即单位时间推进速率最大。

**与现状代码的差异**：叠变异组从"omni（全达顶）才存在"放宽为"任意覆盖≥1 冠军的公种都可做主配推进"；`omni` 变成特例（覆盖 = 全部 attrs）。

### 2.2 合全能公组优先级下调到叠变异之下

**规则**：
- **合全能公（提基础）只在"叠变异推进的剩余资源"里运行**：
  - 只用**未被主配占用的 0/0 母**、或叠变异产出的**非目标子代**、或**公种无交配 CD 的空窗**（母群 CD 好后主配可配则先配主配）；
  - 当 0/0 母资源紧张时，合全能公让位——先保证主配推进不空转；
- **触发条件收敛**：只有当"当前无可推进的冠军公种"（如所有选中属性都还没建立冠军、或公种全部在 CD/未成年）才让合全能公占主配位；
- 合全能公的产物（把某属性基础提到与 0/0 可及上限持平）回归库存，可能**提升某属性的冠军载体**，自然被 2.1 的主配调度吸收。

**为什么对**：合全能公本质是"让某属性基础达到可叠基线"的准备动作，产物最终回归推进；让它与推进抢公用母池/CD = 用推进时间换准备时间。母群 CD 6-8h 极贵，**主配推进应永远优先，合全能公寄生在空窗**。

### 2.3 顺带合体/收拢（保留）

在不影响主配推进的前提下，用**多余的 0/0 母 / 非变异子代 / 公种空窗**顺带把分散冠军并到主配身上（合体 = 普通繁殖 55% 继承，不耗变异机会、不打断推进）——作用是提高主配冠军覆盖（见 3.1），本质是 2.1 的自助加速。

## 3. 机制依据

### 3.1 推进速率的两个乘子

1. **命中池**：变异落点 n/11（n = 玩家选中有效属性数），与公种带几个冠军**无关**——玩家选中数决定了命中池上界；
2. **有效转化率**：命中落在"公种带（接近冠军）的属性" → 直接刷新冠军；落在"公种没带的属性" → +2 追不上库存高冠军 → 浪费。转化率 ≈ 公种覆盖冠军数 / n。

> **每 CD 有效推进 ≈ 命中概率 × 覆盖转化率** → 最大化手段 = ①玩家选够想要的有效属性（提高 n）；②公种覆盖尽量多的冠军（收拢/换种，提高转化率）。

### 3.2 早期 vs 后期

- 库存冠军层还低时（如都才 +0~+2），公种没带的选中属性被命中 +2 也可能追平/建立冠军 → 未覆盖浪费小，主配可先宽松；
- 冠军层高了以后，未覆盖命中几乎必浪费 → **越后期越要保证主配全覆盖**（此阶段"顺带合体"价值上升）。

### 3.3 与 20 父锁

- 主配排序把"总变异计数低"提前，因为 ≥20 父侧锁 → 只剩母系侧（≈7.6% 减半）；推进速率与父锁冲突时，优先用低计数公种，锁前尽量多推进。
- **负公解锁（2026-09-07）**：负公变异计数为负 → 永不达 20 锁 → 一旦拥有负公即作为唯一/最高优先种公（见 2.1 负公规则），突破"都会快速超 20"的共同天花板。

## 附：出生等级上限 361/362 提示（附加需求，2026-09-07）

> 状态：判定规则已与用户确认，未改码；落地为路线浮窗 UI 提示（后续版本）。

### 需求
路线浮窗提示：**选中有效属性的基础点合计 B（继承点数、不含变异）为偶数 → 变异后出生等级上限 361；为奇数 → 362**。

### 机制（已验证自洽）
- 出生等级 = B + 1 + 实际变异点总量（每变异 +2 点、每点 1 级）；
- 变异永远 +2（偶数）→ 出生等级与 (B+1) 的奇偶**恒不变**；
- 出生等级被总量截断在 **362**（= 游戏总上限 450 − 手动可点 88）；
- B 为**奇数** → 基础出生 B+1 为**偶** → +2 步进可**恰好到 362**；B 为**偶数** → 基础出生 B+1 为**奇** → 最高停 **361**。

### 术语澄清（用户指正）
- **254 = 单属性变异点数上限**：该属性变异点数到 254（≈127 次变异）即不再 + 该属性变异；与基础奇偶**无关联**；
- **有效基础属性 = 继承到的属性点（不含变异点数）**；
- 非有效属性需洗成 0（压垃圾），故只看有效基础合计。

### 判定公式（实现用）
- B = Σ(选中有效属性继承基础点，不含变异)；
- 上限 = (B 为奇数) ? **362** : **361**；
- 提示文案：有效基础合计 B（奇/偶）→ 变异后出生等级上限 362 / 361。

### 待实现
- 读取"继承基础点（不含变异）"的字段语义（`statPoints` 基础部分 vs `lbRoutePoint` 减变异层），需查数据字段后确定；
- 在路线浮窗叠变异组 / 主配区追加该提示行。

# 🍚 小白通俗版：这方案是啥？凭啥能终结路线之争？

> 下面全部用大白话，不打术语、不摆公式。

## 一、这方案到底在说什么（打个比方）

把"给恐龙叠变异"想成**班级里刷单科成绩**：

- 每个属性（血/负重/攻…）= 一门课；
- **冠军** = 某门课当前全班（全库存）最高分；
- 一只龙 = 一个同学，它可能同时是好几个科目的第一名；
- 母群 = 一台**每 6-8 小时印一张试卷的机器**；变异 = 批改时**随机挑一门课 +2 分**（挑到哪门是随机的，你说了不算）。

这套方案其实是三条很朴素的规矩：

1. **每张卷子都让"霸榜科目最多的成年同学"去考**（用当前覆盖最多冠军的公种配种）。他霸榜的课被 +2，成绩直接刷新纪录；他不行的课被 +2，也超不过真纪录 = 白加。所以他霸榜越多，每次考试的浪费越少。
2. **"凑全科第一到一个人身上"这类杂活，只在印卷机空着的时候顺手干**，不跟正事抢时间（正事就是上面第 1 条，每 6-8 小时一次，贵得很）。
3. **万一造出"变异次数是负数"的稀有龙（负公）——它永远不会被 20 次变异锁死，能一直叠——就优先让它当种**；它刚出炉还没占任何第一时，先花点空窗时间给它合进一门第一，让它能上岗。

## 二、凭啥它能"终结路线之争"？

以前我们纠结的问题是：**该走哪条大路线**？
- 一条龙从头同时叠好几个属性（全能线）？
- 还是分开几条线各叠各的（分线）？
- 还是轮流让几只公各推进一点（轮流）？
- 还是先各叠满再合体（先合再叠）？

每选一条都有取舍（有的开头快、有的后期稳、有的操作简单），**要人拍脑袋选**——这就是"路线之争"。

新方案的厉害之处在于：**它根本不问你走哪条路**。它把"每一步该干嘛"变成了一套**固定查表规则**：

> 看库存里谁霸榜最多 → 派它去考；杂活填空窗；负公优先。

不管开局是什么样的龙、属性散成什么样，这套规则到每个"该配种的时刻"都会**自动给出当前最快的一步**。既然每一步都是当下最快的、又不会空等，整体自然就是最快的——**不存在"哪条大路更优"的选择题了**。

打个比方：以前是争论"从北京去上海该走高速 A、国道 B 还是高铁 C"；现在变成**每个路口都有同一套红绿灯规则**，绿灯就往前走，永远选当前能走的最快那条道，人不用再纠结大方向——只要前提成立（变异次数迟早都会到 20、我们的目标就是让选中的属性尽快变高、母群够大），这就是你能做到的最优打法。

## 三、一句话记住

> **别再选路线了——每次都派"当前最全能（霸榜最多）的成年公"去配种，杂活用空闲顺手做，负公（锁不住的稀有龙）优先上岗。每步都当下最快、又不空等，整体自然最快。这套规则就是你的最优打法。**

> 想回看规则细节与机制依据的，见上面正文 2~4 节。

## 附：冠军判据 BUG 与修复方向（2026-09-07，用户提出，已确认先修报告）

> 状态：修复方向已确认；遗传机制待实测；代码修复待统一落地（v841 已部署为"总点冠军"实现，需随修复再版）。

### BUG（用户发现）
- 冠军/覆盖判据当前用 **总点数（基础+变异）**：`_routeCov` 以 `lbRoutePoint ≥ mxAll`（总点全局最高）判定冠军覆盖；标题栏"有效属性"与 361/362 判断同样基于总点/单只。
- 问题①：**中途加入基础更高但变异为 0 的龙** → 其总点可能压过"基础普通+变异层高"的种线龙 → 被误判为该属性冠军/主配 → 已叠变异层被弃（作废重赌）。
- 问题②：**变异层是沿种线累积、可并入高基础的资产**；基础是独立可替换维度。二者应分离判断——"谁是推进冠军"看变异层，基础通过合全能公并入。

### 修复方向（用户确认）
1. **冠军/覆盖判据改用「变异点数冠军」**：该属性以全库存 `statMutations` 最高者为推进冠军（推进目标 = 变异层）；基础不参与"谁是冠军"判定。
2. **高基础新龙不重做变异**：高基础经合全能公并入变异线（子代取高侧即同时获得最高基础 + 变异层），而不是让高基础无变异龙顶替变异线。
3. **路线浮窗标题栏"有效属性"数据源**：改为显示 **「最高基础 | 最高变异点数」**——各属性在全库存分别取最高基础与最高变异，**即使分散在不同龙身上也拼接展示**（理论最优）。
4. **361/362 判断**：用**全库存最高基础 | 最高变异**综合判断（理论出生 = Σ最高基础 + Σ最高变异 + 1 → 与 362 截断及奇偶比较），不再只按单只基础合计。

### 机制备注（待实测）
- "60|50 拼接遗传"（公 10|50 × 母 60|0 → 55% 出 60|50、45% 出 10|0）依据为**可靠玩家告知**；当前代码/工具口径仍是"总值整体 55% 取高"模型（按该模型推不出 60|50，只能出 10|50 或 60|0）。
- 两条修复方向在"规划 / 理论最优"层面成立；真实遗传是否"基础与变异分离取高"会影响实现细节（一次合体即可拼接 vs 需先提基础再叠）。待实测确认后统一修正实现并再版部署。

### 口径边界：多线合并保持总值（2026-09-07 用户裁决）
- **多线合并（属性集中组）与繁殖线是不同职责，口径不可混用**：
  - 繁殖线（叠变异/冠军主配/thRow/361）→ **变异点数冠军 + 理论拼接**（本次 BUG 修复核心，已实施）。
  - 合全能公（换代）→ **基础通道**（statPoints / mxBaseAll）。
  - **多线合并（属性集中）→ 保持「总值」口径**：其产物是"拿来实用"的成品龙，实用强度 = 总值（出生等级），不是推进变异线的资产，也不要求变异冠军。线目标 `mxA[k]` = 该属性线代表总值最高、覆盖判据 `Math.max(双方总点) ≥ mxA[k]`、行渲染显示总点——**均为正确设计，禁止双通道化**。
- 撤销此前待办方向：多线合并 / 线代表（`lbRouteLineMembers`）/ `mxA` 的"理论顶 mxAll 化 / 变异点化"一律**不执行**，代码保持现值口径（v841 现状）。

### 口径澄清：合全能公 = 变异点数冠军收拢（2026-09-07 用户裁决）
- **合全能公不是"提基础卡"**：此前误实现为"0/0 高基母给目标公提基础（statPoints/mxBaseAll）"，用户纠正——合全能公合成的应是**变异点数全能**（一只覆盖全部选中属性变异点数冠军的公种）。
