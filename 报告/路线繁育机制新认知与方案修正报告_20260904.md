## 二、新认知列表（共 12 条）

### A. 变异计数类（负线/母系相关）

**认知 A1 · int32 双向回绕：负计数会"回正"**
- 变异计数是 32 位有符号整数（闭环 `[-2³¹, 2³¹-1]`）。正方向越过上限 → 回绕成负（负变异来源）；负方向继续越过下限 `-2³¹` → 回绕成大正数。
- 回正后若数值 ≥20 → 重新锁死变异判定（回到"近上限"）。
- 因此**负公是有寿命的资源**：刚溢出（≈`-2³¹`）最稳；正常 `+1~2/代` 的叠加从 `-2³¹` 走到 +20 需约 21 亿代，实际走不完；**只有"翻倍法"继续互配才会快速穿越回正** → 负公要"养而不叠"：够用即停，勿再拿去同源翻倍。

**认知 A2 · 一般玩家只做父系负计数**
- 标准叠变异流程 = **公堆父系、母保 0/0**：父系计数（countM）沿父系逐代累积 → 只有它能稳定溢出；母系计数（countF）恒 0 → 无机会溢出。
- 若养"负母"：母系计数每代由母本传递并继续叠加，越过 `-2³¹` 又会回正成大正数 —— 不可控、窗口不稳定，且大 countF 污染所有后代。
- **负公有用、负母没用**：负计数 <20 → 该侧变异判定完整恢复，可无限出变异；父系变异落在父本侧的高属性对 → 是叠目标属性的引擎；母系变异落母本侧随机属性 → 多为垃圾方向。

**认知 A3 · 母系不看属性、保持 0 变异计数、一直不更新的三重原因**
1. **变异窗口可持续**：母亲 countF>0 会逐代遗传叠加 → 母系最终锁死；保持 0/0 → 母系永远有变异窗口，后代 countF 恒 0，母池可无限自更新。
2. **属性无关是数学必然（见 A4）**：0/0 母只能携带纯基础；线上的高点由父本承担（55% 覆盖）→ 母本属性对叠变异结果无增益。
3. **一直不更新的原因**：从"已叠变异的父本"回繁新母 → 女儿继承父本 countM>0 → 非 0/0 → 污染母池。母池只能来自**父本开始叠变异之前**的纯基础代（Phase A 前置扩群），建好即永久沿用。

**认知 A4 · 0/0 ⇒ 变异分量全为 0（计数与变异绑定）**
- 计数非负且沿对应系累加遗传；某龙两计数均为 0 ⇒ 其全部祖先从未发生变异 ⇒ 该龙所有属性变异分量 = 0（只能携带纯基础）。
- 推论：**"带变异属性的 0/0 母"在数学上不存在**；携带变异分量 >0 的个体，其对应系计数必 >0。

**认知 A5 · 子代变异计数 = 父母双方同侧计数相加（2026-09-04 补充）**
- 机制：宝宝 `countM = 父本 countM + 母本 countM + 本次新父系变异`；`countF = 父本 countF + 母本 countF + 本次新母系变异`（双方各贡献同侧计数）。
- 证实"同源翻倍法"：同一条线公母互配（双方 countM 都 = X）→ 宝宝 countM = X+X = **2X** → 每代翻倍 → ~31 代达 2³¹ 溢出成负（路线负线 note 的 1+1=2→4→8… 由此机制而来 ✅）。
- 强化母本须双侧 0/0：母本 countM 会直接加进宝宝 countM → 来自已叠变异线的母（countM>0，即使 countF=0）让宝宝计数立即跳高（同线互配直接 2X）；只有母本双侧 0/0 才能保证 `宝宝 countM = 父本 countM`（单一可控累加）、`countF = 0`。
- 强化负公"养而不叠"（A1）：负公 × 0/0 母 → 宝宝 countM = 负公 countM（负值稳定传父系）；但同线负系互配 → 相加继续朝 -2³¹ 逼近 → 回正风险。
- 对路线：负线组"0/0 种子♂×种子♀ → 同源子代互配翻倍"指导成立；模块 0/0 判定（`countM+countF===0` 双侧）天然正确 ✅。

### B. 属性继承类（配对/遗传结果相关）

**认知 B1 · 继承机制（正确版，2026-09-04 用户纠正）**
- 单个属性上，子代 **55% 同时继承"较高的基础 + 较高的变异"**，**45% 同时继承"较低的基础 + 较低的变异"**。
- 两个成分**各自取高/低，可来自不同亲本**；不存在"高基础+低变异"或"低基础+高变异"的混搭；当前代新鲜 `+2` 另算。
- 例：公 50+0 × 母 0+100 → 55% = **50+100**（基础取公、变异取母），45% = 0+0；不会出现 50+0 或 0+100。
- ⚠️ **不是"整对打包继承"**（旧认知有误，已废弃）。

**认知 B2 · 跨龙拼接可行 → "换代/刷新基础"是真实提线手段**
- 高基础亲本 × 高变异亲本 → 55% 子代合并出"新高基础 + 已叠变异"。
- 实操：父本（已叠高变异）× 新抓/换来的**更高基础 0/0 母** → 55% 出新高基础 + 父本变异 → 该公留作新父本 → 基础与变异"接力提升"。
- 这是当前路线**完全没有建模**的配对类型。

**认知 B3 · total=base+mut 的适用边界**
- **个体排序/线最高/达线**：total 是正确的（个体携带能力的度量）。
- **不能直接当配对遗传结果**：50+0(total 50) × 0+100(total 100) 的 55% 子代是 150 而非 100；total 高的一方不等于配出更高。换代/刷新基础场景需**按成分（base / mut 分别）**评估。

**认知 B4 · "母系不看属性"= 基础触顶稳态的实践约定**
- 当母本基础已无法高于父本（野生/可获取基础到顶）时，母本贡献不出新东西 → 只看 0/0 → "不看属性"成立。
- 一旦出现更高基础货源，母本基础立刻重要（换代载体）。**并非绝对规律。**

### C. 数据实证（线上真实数据验证）

**认知 C1 · statPoints=基础、statMutations=变异附加**
- 幼体/成人（backend 世界数据）实测：婴儿 `level == 1 + Σ(statPoints + statMutations)`（严格相等）→ 变异点是真实附加在基础之上的。
- host 繁育栏权威口径：`lbBreedPoint = lbBreedBase(statPoints) + lbBreedMut(statMutations)`。

**认知 C2 · 蛋记录（eggprobe）statPoints 语义不同**
- 蛋实测：`level == 1 + ΣstatPoints` 已成立（statPoints 已含全部继承点），而 `statMutations` 是独立大数（如 244=2×122 代，不参与蛋等级）。
- ⇒ 对异常蛋把 sm 加进属性点会虚高；v705 已按用户要求全局 base+mut，与应用其余部分一致。

**认知 C3 · 卡片每属性三数 = (基础 | 变异 | 手点)**
- 手点（dom）不遗传，路线一律不用；路线"属性点"取前两数相加 = 遗传真值。

**认知 C4 · 手动加点上限 = +88（2026-09-04 补充，非 +100）**
- 个体实际终级 = min(450, 出生+88)：出生 <362 永远到不了 450（终级=出生+88）；出生 ≥362 可顶到 450（需手点 450−出生 ≤88）。
- 影响面：仅顶部"手动余量"账本与档位文案（隐含 ~100 手点假设需复核为 +88，关键界 362）；线代表/叠组等遗传比较不受影响。

## 六、效率分析：是否存在比一般玩家更高效的繁育路线（2026-09-04）

> 结论先行：**机制层面无颠覆性捷径；效率差集中在执行策略**——并行化、主线直翻负化、换代时机、负线后的等级容量迭代。一般玩家流程结构上接近最优，但有 4 类可落地效率漏洞。

### 6.1 四层效率瓶颈（由 A1-A5/B1-B4 推导）
1. **单蛋有用变异吞吐**：父系变异低概率 + 目标属性命中约 1/11；母系侧（0/0）闲置 → 一般玩家单引擎。
2. **父系 20 窗口**：A5 计数只加不减（父母同侧相加），无负溢出即无重置 → 20 必锁，唯一出口=负线（~28-31 代成本）。
3. **等级容量 450**：非目标属性 2 点=垃圾占容量 → 目标属性有真实上限，需压缩/洗剂腾容量。
4. **基础天花板**：B1 基础不超父母双方 → 换代（更高基础货源）是唯一提基础路径。

### 6.2 候选提升（四档）
- **A 档·无脑收益**：多属性线并行推进（每线独立父本+独立 0/0 母池）→ 墙钟 ÷N；配套=母池 Phase A 前置且**建足**（母池只出不进：父本叠变异后女儿全带 countM>0，无法补 0/0 母）。
- **B 档·低成本修正**：①**主线直翻负化**——用已叠到 ~19 的主线后代同源翻倍（~28 代）替代独立 0/0 种子另起（1→31 代），省 ~3-4 代+一套工程+不损属性推进；②换代提示（修正候选 #3）。
- **C 档·进阶双引擎**：父系负公+母系负母 → 双侧无限变异，吞吐潜在 ~2×；但第二套翻倍 ~28 代、母系变异受母本携带属性约束、双负相加向 ±2³¹ 逼近（wrap 风险）、失去干净母池 → 仅高手目标，非默认推荐。
- **D 档·负线后上限战场**：解锁后约束=450 容量而非计数 20 → 叠近容量→压垃圾 re-roll 杂点→再叠，循环逼近"目标属性占满容量"（普通玩家把 20 变异当天花板，实际上限高得多）。

### 6.3 对路线模块的启示（新增候选策略，待确认）
- S1 并行叠组数量上限/分组管理（现有 ≤3 已支持）。
- S2 负线卡补"主线直翻"提示：若主线 countM≥N，可直接用主线后代翻倍，比独立种子省 X 代。
- S3 换代（高基础 0/0 母）提示（并入修正候选 #3）。
- S4 等级容量账本：顶部显示"目标属性还可再叠 N 级（450-当前-垃圾）"，接近上限后引导 压缩-再叠 循环。
- S5（可选/进阶）双负双引擎：作为隐藏高级模式，需标注回正风险。

### 6.4 路线重构（2026-09-04 用户硬约束修订，**以本节为准**，取代 6.2/6.3 的并列路线表述）

**两条硬约束**：① 必须能逼近 450 上限；② 全程不更新/更换母本。

**约束→机制推导**
- 约束① ⇒ 必须无限变异引擎 = **深负公**（A5 计数只加不减，20 必锁，唯一出口=负溢出）。
- 约束② ⇒ 母本一次性建成永久沿用；且由 A5"同侧相加"推出唯一稳定构型 = **母本双侧 0/0**（宝宝 countM=负公 countM 每代稳定）。反向：自家负女儿当母会 负+负 二次回绕成正数（A1）废线；外部带变异高母=换母，违反约束②。
- ⇒ 换代 B② 与双负 C 因触碰母本被排除；唯一主线 = **负公 × 永久 0/0 母池**，以多孵筛选消化 45% 掉目标。

**三阶段路线（同时满足两约束）**
- **Phase 0 永久母池（一次性）**：抓目标属性基础最高货源，挑 0/0、目标基础达线、杂点低的一批建足母池（只出不进、永不更新；池目标基础=全程基础天花板，建池时取最好）。
- **Phase 1 线成型 + 主线直翻负化**：线父×母池叠到计数 ~19 → 用线父同源后代互配翻倍（B①）→ 出**深负公**（≈-2³¹ 最稳，自带已叠属性）；翻到即停防二次回正。
- **Phase 2 无限冲顶**：深负公×永久母池，多孵筛选（继承高目标 55% + 新目标变异 + 杂点最少）→ 新父本仍深负，循环无限、永不换母、永不回锁；接近 450 时切"压杂点"筛选腾容量再叠，逼近"目标属性占满可用容量"。

**诚实边界**
1. 逼近上限 = `450 − Σ(其他属性不可清零基础杂点)`（野生基础无法全 0）；不换母 ⇒ 此杂点是固定值，是"不换母"的唯一代价（换来零中断）。
2. 45% 掉目标变异 → 多孵筛选（数量补吞吐）。
3. 深负公"养而不叠"：只×0/0母，绝不拿负系个体互配。

**与旧档关系**：B①=Phase1 ✅；D=并入 Phase2 压杂点玩法（不再单列）；A=可选并行（多属性各跑三阶段）；换代 B②=排除（违反约束②，仅作为未来"重开新池"的另一项目）；双负 C=排除。
