# Gen 月球流星雨：「空服不推进」结论更正

> **交付对象**：前端（Hass ASA Server Monitor）
> **日期**：2026-10-13
> **触发**：用户质疑「Gen 必须有人在线才会激活月球流星雨，但你记录的数据并非如此」

---

## 1. 更正结论

**原结论（作废）**：Gen 月球流星雨 `ETA = Last + Actual − worldClock`「**仅在有玩家时有效；空服不推进**」。
（出处：`接口文档\前端事件对接文档_五服_20261005.md` §0 总览表 Gen 行）

**更正后**：**空服时天气状态机照常推进**，`MeteorShower` 会在无人时段真实发生。**前端无需在空服时暂停倒计时**。

## 3. 需要区分的两层（这也是误解的来源）

| 层次 | 空服时 | 依据 |
|---|---|---|
| **天气状态机 / 计时器**（`currentWeather` / `nextWeather` / `Last` / `Actual`）| ✅ **推进** | 本次铁证 |
| **流星实体 / 危害是否真的落到地面** | ❓ **未知** | 空服无玩家，**无法观察**；ARK 的 stasis 机制确实会让无玩家区域的 actor 暂停，但全局天气 Manager 不属于 stasis 范围 |

⇒ 「必须有人在线」若指**实体危害**，尚无证据可判定；若指**天气/事件本身**，**不成立**。

## 5. 对前端的影响

1. **不必**因空服而暂停/隐藏流星雨倒计时 —— 该倒计时在空服时同样成立
2. 若此前为「空服不推进」做了特殊分支（暂停显示 / 灰显），**建议移除或改为仅提示"无人观看"**
3. `ETA = Last + Actual − worldClock` 公式**不变**
4. 你此前在空服下读到的数据（日志显示 19:03~21:56 有 **238 次** `LunarMeteorController` 查询）**是正确的**，不是异常
