## 0.2 「多配置档」方案（v3 新增；v4 修订：固定游戏档 + 仅创建者可见）

### 0.2.1 谁能看到档位 + 为什么这么设计（v4 修订）

> 用户口径（2026-10-24）：「配置档改成创建者可看（同显示服务器管理入口的逻辑）」＋
> 「配置档固定游戏：第一个方舟生存飞升、第二个洛夫克拉夫特行动：堕落玩偶」

**① 仅创建者可见**
档位行复用 `lbIsAdmin()`（判据 `dinoAuth.user === 'whiterober'`），与「服务器管理」按钮**同一套逻辑**：
- 非创建者：`lbKeymapProfBarHtml()` **直接返回空串** ⇒ 界面里没有任何档位痕迹，且 `lbKeymapProf()` 强制读取第 1 档
- 创建者：渲染两个固定游戏 chip，可自由切换

**② 档位固定为两个游戏（不可增删改）**

| # | 显示名 | id | 定位 |
|---|---|---|---|
| 1 | 方舟生存飞升 | `ark` | 默认档；**所有玩家实际使用的档** |
| 2 | 洛夫克拉夫特行动：堕落玩偶 | `scum` | 仅创建者可见 / 可切 |

- 移除 `＋`（新建）、`⋯`（重命名 / 删除）两个入口 —— 档位只可**切换**
- 键位按玩家存储（`user_prefs`），**他人的档数据彼此不可见**

### 0.2.2 数据模型

```js
{
  v: 2,
  layout: 'xbox',                 // 全局：我这只手柄（切档不变）
  cur: 'ark',                     // 当前档 id：ark / scum
  updatedAt: 1792761976793,
  profiles: [                     // 固定两项，顺序不可变
    { id:'ark',  name:'方舟生存飞升',              map:{ 'interact': { pad:'xbox_button_y' } } },
    { id:'scum', name:'洛夫克拉夫特行动：堕落玩偶', map:{ 'jump': { kbm:'keyboard_v' } } }
  ]
}
```

- `profiles` 由常量 `LB_KEYMAP_GAMES` 生成，**永远是这两项**；玩家数据只改 `map` 与 `cur`
- `layout` 为**全局**字段（切档不变）
- 每档 `map` 结构不变（仍是 `{actionId: {pad, kbm}}`），**所有现有读写/冲突/还原逻辑零改动**
- **旧数据自动迁移（零丢失）**
  | 旧数据 | 迁移结果 |
  |---|---|
  | v1（无 `profiles`，只有 `map`） | 全部并入 `ark` |
  | v2 `profiles[0]`（原「默认」） | 并入 `ark` |
  | v2 第 2 个有改动的档（原「方案 2」等） | 并入 `scum` |
  | v2 其它多余档 | 丢弃（仅创建者环境下产生，无实际损失） |

### 0.2.3 界面（v4）

```text
<-  🎮 手柄键位                                    [x]
[Xbox][PS][Deck][Switch] …        ← 平台 chip（全局，原样）
[搜索动作…]  已改2 冲突1   已同步 12:03  ⚙ 重置  [💾 保存]
[方舟生存飞升 •] [洛夫克拉夫特行动：堕落玩偶 •]   ← 仅创建者渲染；右上角小紫点 = 该档有改动
v 常用 (6) …
```

| 场景 | 表现 |
|---|---|
| 非创建者（普通玩家） | 档位行**完全不渲染**；只看到一套方舟键位 |
| 创建者 | 看到两个固定游戏 chip，点 chip 只重渲染表格（**不改皮肤、不重载面板**） |
| 新建 / 重命名 / 删除 | **不提供**（档位固定） |
| 跨档查看 | 「只看改动」模式**按档分组**列出（`方舟生存飞升`: 2 项 / `洛夫克拉夫特行动：堕落玩偶`: 1 项） |
| 改动标识 | 档 chip **不显示改动数量**（仅创建者自用，数字意义不大）；有改动的档在**右上角显示小紫点** |

### 0.2.4 动作表组织

```js
// 跨档/跨游戏通用骨架（约 80% 动作）
var LB_KEYMAP_ACT_COMMON = [ {g:'常用', id:'interact', zh:'使用/互动', pad:'xbox_button_x', kbm:'keyboard_e'}, ... ];
// 某档需要额外动作时才写（键 = 配置档 id）
var LB_KEYMAP_ACT_PROFILE = {
  p2: [ {g:'额外', id:'throwball', zh:'投掷', pad:'xbox_rt', kbm:'mouse_left'} ]
};
```

### 0.2.5 复杂度增量（实测估算）
| 项 | 增量 |
|---|---|
| 状态 | `LB_KEYMAP.profiles`（固定 2 项）+ `cur` |
| 常量 | `LB_KEYMAP_GAMES`（2 项：ark / scum） |
| 函数 | `lbKeymapGameSwitch(id)`（约 6 行）+ `lbKeymapMigrateV1` 内的旧档合并（约 15 行） |

| 既有逻辑 | **零改动**（`Effective / Set / Reset / Pick / 冲突检测` 全部沿用单档写法） |

## 1. 目标

1. **玩家级键位表**：动作 ↔ 手柄键 ↔ 键盘键 的映射，按玩家存储、跨端同步（与采集流程同等级）。
2. **展示界面**：三列同屏 —— 动作 / 手柄键 / 键盘键（改过的行打紫点标记）。
3. **可改键**：点键位格改键，支持冲突检测、单行还原、分组还原、全部恢复默认。
4. **零后端改动**：复用现有 `/api/user_prefs` 存储通道。

**非目标（本期不做）**
- 不做游戏内实际改键（只做玩家自己的查阅/记录表）
- 不改采集流程的 key token 语义（联动列入期 3，可选）

## 3. 数据模型

### 3.1 默认键位（静态，写在 `dino-import.html` 内）

```js
var LB_KEYMAP_ACTIONS = [
  // id 一旦发布不得改名（玩家 map 以此为主键）；pad/kbm 一律用 Kenney 原名
  { g:'常用', id:'interact', zh:'使用 / 互动', pad:'xbox_button_x', kbm:'keyboard_e', note:'' },
  { g:'移动', id:'jump',     zh:'跳跃',        pad:'xbox_button_a', kbm:'keyboard_space', note:'' }
];
```

> `g` 分组：常用 / 战斗 / 移动 / 界面（UI 按此折叠，默认只展开「常用」）

### 3.2 玩家自定义（增量 diff，按玩家存）

```js
// localStorage['lb_keymap_<user>'] + 云端 user_prefs.keys.lb_keymap
{
  v: 1,
  layout: 'xbox',                 // 平台皮肤（15 选 1，默认 xbox）
  updatedAt: 1792761976793,
  map: {                          // 只存改过的动作
    'interact': { pad: 'xbox_button_y', kbm: 'keyboard_f' }
  }
}
```

**要点**
- 只存 diff ⇒ 以后修正默认值不会覆盖玩家自定义
- `layout` 只影响**手柄列的图标皮肤**；切平台**不迁移**键值，但**不丢数据**（切回还在）
- 加载时忽略未知 action id（防旧数据残留）

### 4.5 改键弹层（**方案 C：搜索 + 折叠，禁止全列**）

```
+-- 改「使用 / 互动」. 手柄键 --------------------------+
| [搜索] 输入键名 / 别名（如 A、RT、空格）...           |
+------------------------------------------------------+
| > 面键 (4)                          <- 全折叠         |
| v 肩键 / 扳机 (4)                   <- 点开才显示     |
|    [LB] [RB] [LT] [RT]                               |
| > 摇杆 / 十字 (9)                                    |
| > 菜单 / 系统 (3)                                    |
| > 背键 (4)                                           |
| > 键盘 / 鼠标 (109)                 <- 默认折叠      |
|                                    [取消]            |
+------------------------------------------------------+
```

**硬性规则**
1. 打开时**所有分组折叠**；仅「当前值所在组」自动展开并对当前键打紫框
2. 输入关键词 → **跨全部组即时过滤**，最多渲染 30 条（超出提示「继续输入以缩小范围」）
3. `col='pad'` 只显示手柄相关组；`col='kbm'` 只显示键盘 / 鼠标组
4. 单组超过 20 个键时，组内自带滚动（不撑高弹层）
5. 不做「最近 / 推荐」（用户选定：极简）；搜索框自动聚焦并全选
6. **一键展开（仅本界面 / 仅单一手柄）**：用户口径（2026-10-23）「一键展开仅限于计划里的按键配置界面，而且只限于单一手柄」
   - 面板右上角固定一组：`[⤢ 展开本手柄]` `[⤡ 收起]`
   - **「展开本手柄」只展开当前 `layout` 对应的**那一组（如 Xbox 的 39 键），**其它组不受影响**
   - 单组标题可点 `▸/▾` 独立折叠；展开状态存 `localStorage.lbKeyGrpOpen`（会话级）
   - **不应用到流程编辑器的键帽面板**（那里的需求是"想看全部"，保持现状）

### 4.6 改键交互

1. 点键位格 → `lbKeymapPick(actionId, col, anchorEl)` 弹 §4.5 面板
2. 选中 → 写 `map[actionId][col]` → 立即重渲染该行 + 800ms 防抖保存
3. **冲突检测**（同列范围）：目标键已被其它动作占用 ⇒ 弹确认
   - 选项：**交换 / 覆盖并清空对方 / 取消**
   - 默认推荐「交换」（不会把别的动作弄成空）
4. **单行还原**：点紫点 → 删 `map[actionId]`
5. **分组还原**：分组标题右侧 `↺`（只影响该组动作）
6. **全部恢复默认**：`⋯` 菜单内，二次确认

### 4.7 同形键治理：**SVG 方案优先**（2026-10-24 v5210 更新；渐变方案降为可选）

> **现状变更**：部分着色键已改为**内联 SVG**（`LB_KEYSVG`，白层 `currentColor` + 红层 `#E73246`），
> 原 mask 体系（26 张 PNG / `keys/redarm/`）已全部删除；Valve Index 的 4 个同形 track 键已用 **SVG 圆润箭头**区分。
> ⇒ 新出现的同形键，**优先用 SVG 自绘方向标记**（可精确控制、零对齐风险），§4.10 的渐变与角标仅作兜底。

#### 原方案（2026-10-23 实测重写，保留备查）

**判定依据（实测）**：把每个字形按真实字体渲染到 64×64 位图，同平台内两两算 **IoU**（交并比），
`IoU ≥ 0.96` 视为"肉眼难分"。实测得到 **32 个相似簇**，结论如下。

#### 4.7.1 必须处理的三类（IoU = 1.000）

| # | 簇 | 成员 | 涉及 |
|---|---|---|---|
| 1 | **十字方向** | `*_dpad` / `_dpad_up` / `_dpad_down` / `_dpad_left` / `_dpad_right` | **10 个平台全中**（xbox / playstation / switch / steamdeck / frame / wii / wiiu / gamecube / playdate …），约 40 个方向键 |
| 2 | **鼠标三键** | `mouse_left` / `mouse_right` / `mouse_scroll` | keymouse |
| 3 | **Valve Index 触控板** | `index_track` / `_track_up` / `_track_down` / `_track_scroll` | valveindex |
| 4 | **摇杆红/黑** | `generic_joystick` ↔ `generic_joystick_red*` | generic（3 组，单色下完全相同）→ **直接剔除 `_red` 变体**，不留重复 |

#### 4.7.2 不需要处理（原方案会误标）

| 簇 | 为什么不用标 |
|---|---|
| `keyboard_0..9` 等 54 键大簇（IoU 0.997） | 键帽外框相同，但**内部字符不同**，已能区分 |
| `keyboard_f2/f3/f4/f6/f9`、`f10/f12`（0.96~0.98） | 键内有 F 号小字 |
| `keyboard_slash_forward` ↔ `keyboard_z`（0.963） | 字符不同，属位图噪声 |
| `wii_stick` ↔ `wii_stick_l`、`gamecube_stick` ↔ `_stick_c`（0.965~0.97） | 有 L / C 字母标记 |
| `steamdeck_trackpad` ↔ `_trackpad_l`（0.964） | 有 L 标记 |
| **`mouse_side`** | 轮廓**本身独特**（侧键），之前误加了角标 → **去掉** |

#### 4.7.3 处理方式优先级

1. **渐变优先**（见 §4.10）：能靠"亮部位置/形态"区分的，一律用渐变，不加文字角标
2. **角标兜底**：渐变无法表达的（同向不同来源且形态也相同）才加短角标（`↑↓←→` / `左` / `右` / `滚`）
3. **直接剔除**：纯装饰变体（`*_color_*`、`*_all`、`*_outline`、`keyboard_arrows_*`、`mouse` 整图、`generic_joystick_red*`）

#### 4.7.4 新增键位时的检查方法

跑 `tmp/_kf_dups.py`（轮廓哈希，找**完全相同**）+ 浏览器侧 64×64 IoU 扫描（找**近似**），
把新出现的 `IoU ≥ 0.96` 簇按 §4.7.3 处理。

### 4.8 字体发版铁律（两次踩坑固化）

1. **文件名固定**：`fonts/lbk-<plat>.woff2`，**不要**按版本重命名 —— wrangler 按内容 hash 去重，内容未变的字体不会以新名字上传 ⇒ 新路径 404
2. **破缓存靠 query**：`@font-face` 运行时拼 `?v=<LB_VERSION>`（`<style id="lbkFontFaces">`）
3. **重建字体后必须跑 `tmp/_kcss_sync.py`**：新字形需要 `.lbk-<glyph>:before{content;font-family}` 规则
4. 新字形还要补进 `LB_KEYFONT`（现做法：`LB_KEYFONT_SETS.forEach(g => { if (g.ic && !LB_KEYFONT[g.ic]) LB_KEYFONT[g.ic] = 1; })`）

### 4.10 方向性渐变（单色字体下表达"方向"）

> 用户口径：「这种标注能直接在该字上上渐变色的方式实现么？毕竟都是有方向性的」
> 结论：**可以**。`::before` 里的 PUA 字符本质就是文字，`background-clip:text` 同样生效。

#### 4.10.1 技术实现

```css
/* 单色字体 + 方向渐变：字形按渐变着色（线性=十字方向，径向=摇杆/滚轮） */
.lbk-xbox_dpad_up:before{
  background: linear-gradient(to top, var(--lbk-g-lo) 0%, var(--lbk-g-hi) 100%);
  -webkit-background-clip: text; background-clip: text;
  -webkit-text-fill-color: transparent;
}
```

- 色标走变量：`--lbk-g-lo:#4c3b7a`（暗）/ `--lbk-g-hi:#c4b5fd`（亮），换主题只改变量
- 必须包在 `@supports (-webkit-background-clip:text)` 里；不支持时**退回单色**（不报错）
- `-webkit-text-fill-color:transparent` 会覆盖 `color` ⇒ 只对需要区分的键加，**不要全局加**
- 规则由构建脚本按语义后缀**自动生成**（不手写几十条）

#### 4.10.2 完整映射表

| 语义 | 键示例 | 渐变 | 理由 |
|---|---|---|---|
| 十字·上/下/左/右 | `*_dpad_up/down/left/right` | 线性 `to top / bottom / left / right` | 方向即亮部方向 |
| 十字·整体 | `*_dpad` | **不加**（基准色） | 参照物 |
| 摇杆·上/下/左/右 | `*_stick_l_up` 等 | **径向偏心** `radial-gradient(circle at 50% 15% / 50% 85% / 15% 50% / 85% 50%)` | 「线性=十字、径向=摇杆」，一眼分来源，**无需角标** |
| 摇杆·按下 / 触控板·整体按下 | `*_stick_l_press` | 径向居中 `circle at 50% 50%` | 中心亮 = 按下 |
| 鼠标·左键 | `mouse_left` | 线性 `to top left`（左上亮） | 左上角亮 = 左键 |
| 鼠标·右键 | `mouse_right` | 线性 `to top right`（右上亮） | 右上角亮 = 右键 |
| **鼠标·滚轮** | `mouse_scroll` | **径向居中** `radial-gradient(circle at 50% 45%, 亮 → 暗 70%)` | **中心亮 = 滚轮居中**，与左右键"角落亮"形成三角区分 |
| 鼠标·滚动上/下 | `mouse_scroll_up/down` | 不加（自身带箭头） | — |
| 鼠标·侧键 | `mouse_side` | **不加**（轮廓独特） | 之前误标，已改 |
| 触控板·上/下/滚动 | `index_track_up/down/scroll` | `to top` / `to bottom` / 径向居中 | 同鼠标逻辑 |
| 键盘字符键 / F 键 / 摇杆 L·C 变体 | — | 不加 | 内部字符已能区分 |

#### 4.10.3 三个限制（必须知道）

1. **渐变是整条线性/径向**，不能"局部高亮某一个箭头"（Kenney 原图靠多色分层；单色字形只有一个轮廓）
2. **同向不同来源**若"形态"也相同（罕见）仍需角标 —— 本方案靠"线性 vs 径向"的形态差异规避了绝大多数
3. **与 `color` 互斥**：设了 `-webkit-text-fill-color:transparent` 的键，`color` 不再生效（只对这些键）

#### 4.10.4 落地时机

- 期 1 不做（先保证功能骨架）
- **期 2.5**：脚本生成渐变规则 + 逐平台视觉验收（重点看 Xbox / PlayStation / keymouse / valveindex 四组的可辨性）
