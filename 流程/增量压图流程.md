# 增量压图流程

> 状态：✅ 已实施（2026-08-28 全量重刷验证）
> 目标：R2 新增/更新生物图标（PNG）后，增量生成 96px WebP 缩略图，供 dino-import 前端省流加载（30KB → 4KB）
> 核心：压图在**开发机**执行（物理服务器不压图）；`webp_map.json` + 缩略图随 CF Pages 部署

---

## 架构总览

```
R2 bucket (eagle-img, img.whiterober.ccwu.cc)
   │ 源图 PNG（ASA/biology/*.png 等）
   ▼
开发机 _webp_incremental.py（扫描 R2 → 压 96px WebP）
   │
   ├─ tmp/webp96/*.webp       缩略图（hash 命名 = md5(完整URL)[:12]）
   └─ tmp/webp_map.json       映射 {源PNG URL: thumbs/webp96/xxx.webp}
   ▼
_sync_repack2.py（打包：index.html + 6静态JSON + values + 622缩略图）
   ▼
tmp/dino-flat.zip → 浏览器上传 CF Pages（dino.whiterober.ccwu.cc）
   ▼
前端 lbLoadIconList：tm[it.url] || it.url 用缩略图替换源图
```

---

## 完整执行流程（4 步）

### 第 1 步：增量压图（开发机）

```powershell
python _webp_incremental.py
```

脚本行为：
1. 读现有 `tmp/webp_map.json`（已映射的图跳过）
2. `_r2_list('ASA/')` 扫描 R2 全部对象
3. 过滤出「不在映射 ∩ icons2.json 用到」的**新图**
4. 逐张下载 R2 源图 → Pillow 缩到 96px → WebP quality=70 → 存 `tmp/webp96/<md5>_w96.webp`
5. 更新映射（key = `https://img.whiterober.ccwu.cc/<R2 key>`，value = `thumbs/webp96/<hash>_w96.webp`）
6. 保存 `tmp/webp_map.json`，输出 `tmp/_webp_incremental_out.txt`

> ⚠️ **已知限制**：脚本只处理「不在映射」的新图；**已映射的图即使 R2 源图更新也不重刷**（2026-08-28 用户发现的「老图」根因）。
> **全量重刷**（强制刷新所有已映射图）：运行 `tmp/_refresh_all.py`（逐条下载 R2 + 重压 + 覆盖同名文件，映射不变）。

### 第 2 步：打包

```powershell
python tmp\_sync_repack2.py
```

脚本行为：
1. 复制 `dino-import.html` → `dino-import-new.html` → 打为 `index.html`
2. 拉取 6 个静态 JSON（icon_zh_map / gene_traits_zh / dino_prefix_zh / dino_colors / icon_anti_color / icons2）
3. 拉取 `values.json` + `ASA-values.json`
4. **自动生成 `dino-import.version`**（从 `LB_VERSION` 正则提取）
5. 复制 622 张需要的缩略图（icons2 URL ∩ webp_map）
6. 精简 webp_map.json（只保留 icons2 用到的）→ 打包 `tmp/dino-flat.zip`（~2.95MB）

> 输出验证：`tmp/_zipchk.py` 检查 zip 内含 index.html/version/webp_map/缩略图，且 `?v=LB_VERSION` 参数在位。

### 第 3 步：部署 CF Pages（浏览器）

1. 打开 CF Dashboard → Workers 和 Pages → `dino-import` → Production
2. 上传 `tmp/dino-flat.zip`（等待「解压缩的 N 文件」→ 点「部署」）
3. 等待「共 N 个文件正在上传」完成 → 自动跳回 view 页

### 第 4 步：验证

| 检查项 | 方法 | 期望 |
|--------|------|------|
| 版本文件 | 打开 `https://dino.whiterober.ccwu.cc/dino-import.version` | = LB_VERSION |
| 页面版本 | `dino-import.html` 的 `LB_VERSION` | 与 version 文件一致 |
| 缓存命中 | `fetch(icons2.json?v=LB_VERSION)` 看 `cf-cache-status` | HIT |
| 缩略图可用 | 打开页面选择器网格看图标 | 显示新图无 broken |

## 指定图压图 / 重压指定图（2026-09-21 补充）

> 场景：只新增/更新少量图标（补 1-3 个新 ASA 图标），或需**重压**某几张已映射的图（源图更新、此前用临时脚本压过等）。

**官方唯一姿势：先从映射里删条目，再跑增量脚本（脚本会把它当「新图」重压）**

| 步 | 操作 |
|----|------|
| 1 | 备份映射：`Copy-Item tmp\webp_map.json tmp\webp_map.json.bak_<时间戳>` |
| 2 | 从 `tmp/webp_map.json` **删除**目标条目的 key（**完整 URL**，见下方脚本模板） |
| 3 | 确认 `icons2.json` 已含目标 URL，且**已同步到服务器** `/config/www/asa-data/icons2.json`（脚本从这里读） |
| 4 | 跑 `python _webp_incremental.py`（R2 扫描 → 下载 → 96px WebP q70 → 写回映射） |
| 5 | 校验 `tmp/_webp_incremental_out.txt`：`new (dino used)=N` 应等于待压张数，且 `new_count` 匹配 |
| 6 | `python tmp\_sync_repack2.py` 打包 → 部署 CF |

**第 2 步脚本模板**（`tmp/_drop_map_keys.py`，临时脚本用完即删）：

```python
import io, json
F = r'b:\项目\Hass ASA Server Monitor\tmp\webp_map.json'
DROP = [
    'https://img.whiterober.ccwu.cc/ASA/structures/Metal_Pillar.png',
    # ... 列出全部待重压图的完整 URL
]
mp = json.load(io.open(F, encoding='utf-8'))
n = 0
for u in DROP:
    if u in mp:
        del mp[u]; n += 1
io.open(F, 'w', encoding='utf-8').write(json.dumps(mp, ensure_ascii=False, indent=0))
print('dropped=%d remain=%d' % (n, len(mp)))
```

> 🚫 **禁止自造/定向压图脚本**（历史违规：`_webp_add3.py`、`_webp_two.py`、`_d2_webp.py` 等）
> 虽口径相同（`md5(完整URL)[:12]_w96.webp` + `thumbnail(96,96)` + WebP q70），但：
> 1. **绕过 R2 扫描** → 只处理手动列举的图，**新图容易被漏压**
> 2. 让映射来源**无法审计**（无法判断哪些图出自非官方路径）
>
> 统一走「**删映射条目 + 跑 `_webp_incremental.py`**」。

## 常见问题

### Q1：为什么 R2 图存在但前端显示老图？
- 前端显示的是 `tmp/webp96/` 缩略图 + `webp_map.json` 映射（独立于 R2 存活）
- 增量脚本不重刷已映射图 → R2 源图更新后缩略图仍是老的
- 解决：跑 `tmp/_refresh_all.py` 全量重刷 → 重新打包部署

### Q2：脚本 R2 操作返回 0/失败？
- 检查环境变量：`os.environ['ACCOUNTS_FILE']` 必须指向 `独立后端/accounts.json`
- `cf_config.json` 必须含 r2_bucket/r2_endpoint/r2_s3_access_key/r2_s3_secret_key
- R2 key 前缀用 `ASA/`（如 `ASA/biology/Procoptodon.png`）

### Q3：缩略图文件名怎么算的？
- `md5(R2key)[:12] + '_w96.webp'`（R2key 形如 `ASA/structures/Metal_Pillar.png`）
- ⚠️ **hash 依据是 R2 key（不是完整 URL，也不是本地文件名）**；改 key 结构会改名 → 旧文件成孤儿，需重建映射
- 校验：`python tmp\_e7_hash.py` 会同时算出 `md5(R2key)` 与 `md5(完整URL)` 两种值，与映射值比对即可判定规则

### Q4：R2 文件名含空格/特殊字符 → 新图被漏压（2026-09-21 已修复）
- **症状**：新图标（如 `Metal Door.png`）已进 icons2，但跑 `_webp_incremental.py` 时 `new (dino used)` 不含它，映射里始终缺席
- **根因**：R2 key 是 `ASA/structures/Metal Door.png`（**原始空格**），而 icons2.json 存的是 `.../Metal%20Door.png`（**URL 编码**）→ 旧版脚本直接拼字符串比对 → 不相等 → 误判为「不在 icons2 引用」
- **修复**：比对前双侧统一 `urllib.parse.unquote()` 归一化；写映射时用 `quote(url, safe=':/')` 编码，保证 key 与 icons2 URL 完全一致（修复版备份 `bak/_webp_incremental_20260921_repaired.py`）
- **注意**：`fname` 仍取 `md5(R2 key)`（含原始空格）——前后自洽，不受编码影响
