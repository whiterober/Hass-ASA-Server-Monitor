## 三、数据链

```mermaid
graph LR
  A[蓝图卡片·关注角标] --> B[localStorage lb_bp_follow]
  B --> C[待制作浮窗打开]
  C --> D[串行队列 lbTodoFetchQ]
  D -->|POST /api/crafting_cost| E[dino_backend.py crafting_cost]
  E -->|RCON TransferIdentityFix.CraftingCost| F[Abe :32323]
  F -->|JSON costs[]| E
  E --> G[localStorage lb_bp_cost 永久缓存]
  G --> H[卡片材料行 / 浮窗材料 / 总汇总]
```

**永久缓存依据**：配方来自**类默认值**，与服务器上的实例、部落、时间**无关**（文档 §6.2）⇒ 同一 `itemClass` 结果可持久缓存，不重复 RCON。

### 4.2 函数（加在 L753 `inv_probe()` 旁，仿其结构）

```python
def crafting_cost(server, item_cls):
    """单蓝图制作材料：RCON TransferIdentityFix.CraftingCost <itemClass>。
    2026-09-13 新增：前端蓝图卡「关注 / 待制作」按需单查；返回 costs[] 供材料行与汇总。
    注意：类名须为运行时类名（去 _C_<数字> 后缀）；目标类需在服务器上存在实例才命中。"""
    port = SERVERS.get(server)
    if not port:
        return {'ok': False, 'server': server, 'error': 'unknown server'}
    if server not in CRAFTING_COST_SERVERS:
        return {'ok': False, 'server': server, 'error': 'server not ready (crafting_cost: %s)' % server}
    cls = re.sub(r'_C_\d+$', '', (item_cls or '').strip())
    if not cls:
        return {'ok': False, 'server': server, 'error': 'missing cls'}
    try:
        success, result = _rcon_str(port, '%s %s' % (CMD_CRAFTING_COST, cls))
    except Exception as e:
        return {'ok': False, 'server': server, 'error': str(e)}
    if not success or not result:
        return {'ok': False, 'server': server, 'error': 'rcon empty'}
    try:
        j = json.loads(result)
    except Exception:
        return {'ok': False, 'server': server, 'error': 'bad json', 'raw': str(result)[:200]}
    if not isinstance(j, dict) or not j.get('ok'):
        return {'ok': False, 'server': server, 'cls': cls,
                'error': ((j or {}).get('error')) or 'crafting cost failed'}
    return {'ok': True, 'server': server, 'cls': cls, 'itemClass': j.get('itemClass'),
            'foundIn': j.get('foundIn'), 'costs': j.get('costs') or [], 'count': j.get('count'),
            'ts': str(datetime.now())}
```

### 5.5 取材料时机

1. **加入关注 / 加入待制作**：不立即请求（避免批量卡顿）
2. **打开待制作浮窗**：对**缺缓存**的项串行请求（仿 `lbWatchFoodRunQ` L7721）
3. **卡上手动补**：无缓存时卡片材料行显示「取材料」按钮 → 单查 → 写入缓存并刷新
4. 材料取回后：卡片材料行 / 浮窗材料 / 底部汇总**同步重渲染**

## 八、验收标准

- 蓝图卡片含**关注角标**，样式/交互与「关注未成年」一致（同 class、同尺寸、同金色态、同 `lbToast` 反馈）；
- `#lbTodoBtn` 与 `#lbWatchBtn` **视觉一致**（仅图标与颜色不同）；
- 浮窗内每张蓝图显示**制作材料**，且可**调数量**；
- 底部显示**总材料汇总**，数量随调节器实时更新；
- 非 Abe 服显示「暂未开通」；RCON 密码不出现在前端任何位置；
- 配方结果**永久缓存**，重复开窗不重复 RCON。

## 九、风险与规避

| 风险 | 规避 |
|---|---|
| 目标类在服务器**无存活实例** → `item instance not found`（文档 §6.4） | 卡片显示「未找到实例·无法取配方」+ 重试按钮 |
| RCON 撞车（与关注未成年 5s 轮询 / 食物源扫描并发） | 串行队列 + ≥400ms 间隔；浮窗打开期间不并行发起其他 RCON 任务 |
| 非 Abe 服误调 | 后端白名单 + 前端按 `sv==='Abe'` 才显示取材料 |
| 密码/端口泄露 | 前端**只**调后端；RCON 常量仅存在于后端 |
| 包长截断 | 单类响应 <1KB；禁止传超宽泛类名（如 `PrimalItem`） |
| 蓝图与实物同类同名 | 材料行按**基名**取配方，蓝图/实物共用同一结果（文档 §2.1） |
