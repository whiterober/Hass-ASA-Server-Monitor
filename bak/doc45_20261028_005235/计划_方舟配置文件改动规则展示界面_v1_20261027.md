# 方舟配置文件改动规则展示界面 · 方案 v1

> 日期：2026-10-27　落点：**dino-import（CF 前端内嵌功能面板）**　插件侧：**AsaApi 插件导出 manifest**
> 状态：**方案待审（本文档未改任何代码 / 未动线上数据）**

---

## 0. 一句话

把「方舟服务器配置文件里每个配置项的改动规则」做成一个**只读台账面板**：一条记录说清 **谁在管 / 写在哪里 / 怎么生效 / 边界多大 / 有多危险 / 默认值从哪来**，数据来自「Beacon 元数据（社区来源）+ 本服 ini 实况 + 插件自报 manifest」三层，缺哪层就明说缺哪层。

---

## 1. 需求边界

| 范围内 | 范围外（本方案不做） |
|---|---|
| 展示 `GameUserSettings.ini` / `Game.ini` / `Engine.ini` / 启动命令行参数 的**配置项改动规则** | 前端写 ini（**绝不提供写入**） |
| 展示「当前值 vs 默认值」差异、插件接管关系、生效方式、风险等级 | 改造 ASA 后台「服务器规则」页（那是给人看的说明书，另一条线） |
| 插件侧配合项：manifest 导出、异常上报、校验命令 | 游戏内热改配置 / 在线改倍率 |
| — | 改动留痕（谁改的 / 前后值 / 时间线）—— **本期不做**（2026-10-27 用户明确不需要）|

---

## 2. 名词口径

| 词 | 含义（本项目内统一定义） |
|---|---|
| **改动规则** | 一个配置项的 6 要素：①归属（原生/插件接管/本服覆盖）②位置（文件+段+键）③生效方式（热更/重启/下次生效）④约束（类型/范围/枚举/互斥）⑤风险等级 ⑥异常/缺失提示（插件报错、元数据未收录、默认值无来源） |
| **manifest** | 插件导出的自我声明 JSON（我接管了哪些键、我实际的运行时值、我的约束、我怎么生效） |
| **takeover** | 插件在运行时覆盖/接管某键 ⇒ ini 里写的值**不决定实际行为** |
| **partial** | 后端三层数据未凑齐时的标记，必须显式暴露缺什么 |

## 3. 记录数据模型（一条 = 一个键 × 一个文件）

```json
{
  "file": "GameUserSettings.ini",
  "section": "ServerSettings",
  "key": "TamingSpeedMultiplier",
  "type": "Numeric",
  "default": "1.0",
  "default_source": "community",   // plugin_cdo | factory_baseline | community | wiki | none
  "current": "6.0",
  "changed": true,
  "dup": false,
  "line": 128,
  "owner": "server",          // vanilla | server(本服覆盖) | plugin
  "plugin": null,             // owner=plugin 时填插件名
  "takeover": false,
  "apply": "restart",         // hot | restart | later | undeclared
  "apply_basis": "manifest",  // manifest | builtin | undeclared
  "constraints": { "min": 0, "raw": null },
  "risk": "normal",           // high | normal
  "ui_group": "Taming",
  "desc": "Values greater than 1.0 increase the amount of taming completed by each taming event…",
  "meta_missing": false
}
```

字段来源对照：

| 字段 | 来源层 | 缺失时表现 |
|---|---|---|
| `type/ui_group/desc/constraints` | A 元数据（Beacon，社区来源） | `meta_missing: true`，界面标「元数据缺失」 |
| `default/default_source` | 默认值四档（见 §4.4） | `none` ⇒ **不判已改/未改**，只显示当前值 |
| `current/section/line/dup` | B 本服 ini 解析 | 该项不出现（只在 manifest 里出现 ⇒ 标「仅插件声明」） |
| `owner/plugin/takeover/apply` | C 插件 manifest | 回退内置规则表；再缺 ⇒ `apply: undeclared` |

## 4. 数据来源（A/B/C 三层 + 默认值来源）

### 4.1 A 层 · 配置项元数据（Beacon 表，**社区来源，不是权威默认值**）

> ⚠️ 这里只提供「类型 / 分组 / 描述 / 约束 / 社区参考默认值」，**`default_value` 不是权威默认值**。默认值的可信度分级见 **§4.4**。

本地 `c:\Users\white\AppData\Roaming\The ZAZ\Beacon\Libraries\ArkSA.sqlite` → 表 `ini_options`

实测（2026-10-27，只读查询）：

| 项 | 实测结果 |
|---|---|
| 总条数 | **362** |
| 按文件 | `Game.ini` 143 / `GameUserSettings.ini` 132 / `CommandLineOption` 62 / `CommandLineFlag` 25 |
| value_type | Numeric 172 / Boolean 153 / Structure 19 / Text 17 / Array 1 |
| 描述填充 | description 313、default_value 317、max_allowed 339、constraints 55、nitrado_format 12、uwp_changes 63 |
| 列结构 | `file / header(=段) / key / value_type / default_value / description / ui_group / constraints / max_allowed / nitrado_format …` |
| constraints 形态 | JSON 片段，如 `{"min":1}`、`{"trim_chars":[","],"allowed_chars":"\\d,"}`、`{"other":{...}}` |

**做法**：写一次性导出脚本 `tmp/_cfg_meta_export.py`，把 sqlite → `cfg_meta.json`（构建期生成，**运行时不读 sqlite**，避免后端依赖本机路径）。字段映射：`header→section`、`default_value→default`、`ui_group→ui_group`。

**已知缺口（必须在界面标注，不当 0 处理）**：
- `RCONPort` 等键在 table 里 **0 命中** ⇒ 未收录键一律 `meta_missing`。
- `max_allowed` **语义未验证**（示例里 `TamingSpeedMultiplier` 的 max_allowed=1，显然不是数值上限）⇒ **禁止当作范围上限展示**，存进 `constraints.raw` 原样保留即可。

### 4.2 B 层 · 本服实况（ini 解析）

路径（沿用既有脚本 `tmp/_cmp_servers.py` 已验证的写法）：

```
\\SERVER\ARK Server\Servers\<Abbr>\ShooterGame\Saved\Config\WindowsServer\
    GameUserSettings.ini
    Game.ini
    Engine.ini
```

解析规则（**逐条都是踩过的坑**）：
1. 段栈：`[ServerSettings]` 之类，键归属到最近段。
2. 只按**第一个 `=`** 切分，值原样保留（含 `,`、引号、空格）。
3. **保留行号与原始文本**，便于"去 ini 里定位"。
4. **重复键全部保留**，标 `dup: true`（ini 语义是后者生效，但只取最后一条会吞掉"手滑重复"这种真问题）。
5. `;` / `#` 注释行单独收集为 `commented_keys`，界面上给「曾注释掉的历史值」提示（这是最常被问"我明明改过"的根因）。
6. 编码探测：先读前 2 字节判 BOM（`FF FE` / `FE FF` ⇒ UTF-16LE/BE），否则按 UTF-8 with errors=replace；**Engine.ini 实测更可能带 BOM**。
7. 输出：后端内存缓存（TTL 60s）+ 落盘快照 `<Abbr>_cfg.json`（供离线排查，不供前端直读）。

### 4.3 C 层 · 插件 manifest（见 §5）

### 4.4 默认值从哪来（**2026-10-27 实测结论**）

**结论：本环境拿不到"官方权威"的 ini 默认值；Beacon 的 `default_value` 只能算社区参考。**

实测两条硬事实：

| 探测项 | 结果 |
|---|---|
| 各服 `ShooterGame\Config`（ASE 时代放 `Default*.ini` 的地方） | **11 台全部不存在** |
| `Isl\ShooterGame` 全树（267 个目录）搜 `Default*.ini` | **0 个命中** |
| 运行时 `[ServerSettings]` 段 | 146 条键值、**0 条注释** ⇒ 面板/人工写入的结果，**无法区分"改过"与"默认"** |

⇒ 原本设想的「引擎 `Default*.ini` 作主源」**在本环境作废**（ASA 专用服务器包不带 `ShooterGame\Config`，多数默认值是引擎 CDO 里硬编码的，静态文件根本读不到）。

可用来源与可信度：

| 档 | 来源 | `default_source` | 可信度 | 落地成本 |
|---|---|---|---|---|
| ① | **插件读 CDO**（UE 反射取 UClass 默认对象属性） | `plugin_cdo` | **最高（唯一真权威，连"ini 里没写"的键也有）** | 插件发版 + 键→UProperty 映射表 |
| ② | **出厂基线（`factory_baseline`）**，两种取法：**(a) 客户端清空重生成**（本机 `Saved\Config\Windows`，0 下载）／ **(b) 干净专用服实例首启** | `factory_baseline` | 高（可复现、可随游戏版本重跑） | 一次性 |
| ③ | Beacon `ini_options.default_value`（317/362 有值） | `community` | 中低（社区维护，可能滞后 + 口径不明） | **零成本，已有** |
| ④ | ark.wiki.gg Server configuration | `wiki` | 低中（人工维护） | 抓取核对，仅做交叉校验 |
| — | 都没有 | `none` | — | 界面显示「未收录」 |

**口径（必须遵守）**

1. `default_source` 必须随每条记录返回并在界面显示；`community` / `wiki` 的文案一律写「**参考默认**」，**禁止**写「官方默认」。
2. 服务器 ini **没写这个键** ⇒ 当前值 = 默认值，界面写「未覆盖（取默认）」，不显示空白 / 0。
3. 差异判定只在 `default_source` 有值时计算；`none` 时**不显示已改 / 未改**，只显示当前值。
4. `max_allowed` 语义未验证，**禁止**当数值上限用（见 §4.1 缺口）。

## 5. 插件侧配合（**重点**）

### 5.1 为什么必须插件出数据

ini 文件只能表达「写进去的字面值」，表达不了：
- 这个键**是不是被插件接管**（改 ini 没效果的经典坑）；
- 插件**实际的运行时值**（可能来自自己的 `config.json`）；
- 插件**自己的约束**（范围/枚举/互斥）；
- **怎么生效**（热更 / 重启 / 下次生效）；
- **插件的健康状态**（依赖的键缺失/类型错 ⇒ 功能静默失效）。

这些**只有插件自己知道**，前端和后端都不能靠猜。

### 5.2 `cfg_manifest.json`（schema v1，新增）

写入位置（每台服务器自己的插件目录，天然隔离）：

```
\\SERVER\ARK Server\Servers\<Abbr>\ShooterGame\Binaries\Win64\ArkApi\Plugins\<Plugin>\cfg_manifest.json
```

结构草案：

```json
{
  "schema": 1,
  "plugin": "WorldProbe",
  "plugin_version": "1.2.2",
  "dll_build": "2026-10-07T14:18:22+08:00",
  "written_at": "2026-10-27T10:00:00+08:00",
  "server": "Isl",
  "items": [
    {
      "file": "GameUserSettings.ini",
      "section": "ServerSettings",
      "key": "AllowCryoFridgeOnSaddle",
      "state": "managed",            // managed(接管) | read(只读依赖) | derived(据其推导)
      "manifest_default": "False",   // 插件认为游戏默认
      "runtime_value": "True",       // 插件实际使用值
      "overrides_ini": true,         // true ⇒ 改 ini 无效（本方案最重要的一个字段）
      "apply": "hot",                // hot | restart | later
      "constraints": { "type": "Boolean" },
      "risk": "normal",
      "notes": "改此项会立即影响低温仓停车限制"
    }
  ],
  "errors": [
    { "level": "error", "key": "MaxTamedDinos", "code": "TYPE_MISMATCH", "msg": "期望整数，读到 'abc'" }
  ]
}
```

**硬要求**
- `schema` 版本号必填，后端只认已知版本，未知版本 ⇒ 面板标「插件版本过新，需升级前端解析」，**不硬解析**。
- **原子写**：写 `cfg_manifest.json.tmp` → `os.replace()`，避免后端读到半截 JSON。
- UTF-8 **无 BOM**；单文件建议 ≤ 200KB。
- 插件未实现（老版本）⇒ 文件不存在，后端返回 `manifest_missing: true`，面板降级到内置规则表（不报错、不空白）。
- **P2 可选**：附带 `"defaults": [{"key":"…","value":"…","source":"cdo"}]`，后端据此把这些键的 `default_source` 升为 `plugin_cdo`（§4.4 ① 档）。

### 5.3 写出时机

| 时机 | 必要性 |
|---|---|
| 插件初始化完成（服务器启动） | 必需，保证面板永远有基线 |
| 插件重载自身配置后 | 必需，`runtime_value` 变了 |
| 收到 RCON `CfgManifestDump` | 必需，供人工/后端强制刷新 |
| 检测到 `cfg_errors` 变化 | 推荐，错误能及时冒到面板 |

> **多实例隔离铁律**（沿用 2026-10-11 天气历史事故教训）：即使将来改成写共享目录，也必须**按实例命名**（`<Abbr>_cfg_manifest.json`）+ **保存时保留外来内容**，绝不能让多台服务器整文件互相覆盖。

### 5.4 插件 RCON 能力（分期）

| 命令 | 期 | 作用 | 风险 |
|---|---|---|---|
| `CfgManifestDump` | P1 | 强制重写 manifest | 无（只写文件） |
| `CfgCheck <key>=<value>` | P2 | **dry-run** 校验，返回 ok/reason，**不落盘** | 无 |
| `CfgApply <key>=<value>` | **不做** | 在线改配置 | 高，暂不提供 |

### 5.5 异常上报（插件写、后端读）

> 改动留痕（谁改的 / 前后值 / 时间线）**本期不做**（2026-10-27 用户明确不需要）。

- `cfg_errors.json`：插件发现**自身依赖键**缺失 / 类型错 / 超范围时写；
  面板顶部红条：`⚠️ WorldProbe 报 2 项配置异常（Isl）`，点开看明细。
- 结构：`{"written_at":"…","plugin":"…","server":"Isl","errors":[{"level":"error","key":"…","code":"TYPE_MISMATCH","msg":"…"}]}`
- 与 manifest 同目录、同批原子写；UTF-8 无 BOM；时间带时区 `+08:00`。

### 5.6 生效方式口径（**不许前端猜**）

| 值 | 界面徽章 | 判定来源 |
|---|---|---|
| `hot` | ⚡ 热更 | 只信 manifest |
| `restart` | 🔁 需重启 | manifest → 内置保守表 |
| `later` | ⏳ 下次生效（开服/进图/下次驯服） | manifest → 内置保守表 |
| `undeclared` | ❔ 未声明 | 三层都没有 ⇒ **就这么显示**，不填默认 |

> ⚠️ **待核实项**：AsaApi 是否支持热重载，现有两份文档互相矛盾 ——
> `报告\WorldProbe_本轮改动通告_20261007_v122b16.md`：「AsaApi 不支持热重载，需重启服务器」；
> `报告\WorldProbe_全服事件对接文档_20261006.md`：「覆盖 dll 即生效（AsaApi 5s 自动重载）」。
> **结论：本方案不写死，一律以插件 manifest 的 `apply` 为准**；核清楚后再回填内置表。

## 6. 后端接口（`dino_backend.py`）

现状锚点（已验证）：`_do_GET_body()` 内是 `if path == … elif path == …` 链（`独立后端\dino_backend.py` 约 L2363 起），`/api/harvest_flows`、`/api/user_prefs` 用 `?username=&nick=` 鉴权。

| 路由 | 方法 | 内容 | 缓存 |
|---|---|---|---|
| `/api/cfg_meta` | GET | A 层元数据（或改走 CF 静态文件，零后端改动） | 长（随版本号变） |
| `/api/cfg_rules?server=Isl&file=GUS` | GET | A+B+C 聚合，返回 `{items, partial, missing, manifest_missing, generated_at}` | 60s |

约定：
- **降级必须显式**：`partial:true` + `missing:["manifest","meta"]`，绝不返回"看起来完整其实缺数据"的结果。
- 任一服 ini 读失败（服务器没开机/路径不存在）⇒ `items:[]` + `note:"ini 不可读"`，不抛 500。
- 部署：改的是**真身** `\\SERVER\dino_backend\dino_backend.py`（工作区 `独立后端\` 只是镜像），需用户在物理机上跑 `restart_dino_backend.bat`。
- 路由生效判据（沿用既有经验）：`POST /api/<route>` 不带 username ⇒ **401 = 路由存在**；**404 = 进程未重载**。

## 8. 规则判定口径（"改动规则"怎么算出来）

| 维度 | 判定顺序 |
|---|---|
| **归属 owner** | manifest `overrides_ini:true` ⇒ `plugin` ｜ ini 值 ≠ 默认 ⇒ `server` ｜ 否则 `vanilla` |
| **实际有效值** | `plugin` ⇒ 插件 `runtime_value`（副行显示 ini 值）；其余 ⇒ ini `current` |
| **生效 apply** | manifest.apply → 内置保守表 → `undeclared` |
| **默认值 default** | 见 §4.4：`plugin_cdo` > `factory_baseline` > `community` > `wiki`；都没有 = `none`（**不判已改**） |
| **约束 constraints** | A 层 `constraints` 解析（`{min}`/`{max}`/`allowed_chars`/枚举）→ 无法解析则原样展示 JSON 字符串 |
| **风险 risk** | 高危白名单：`RCONPort` / `ServerPassword` / `AdminPassword` / `ActiveMods` / `MaxTamedDinos` / `Clustering*` / 影响存档的 `*Override*`；其余 normal |

## 11. 风险与坑（都是本项目踩过的）

1. **只取最后一条 = 吞掉问题**：ini 重复键必须全保留 + `dup` 标记。
2. **注释掉的历史值**：`;TamingSpeedMultiplier=10` 这类要单独提示，否则永远解释不清"我明明改过"。
3. **编码**：UTF-16/BOM 探测，禁止 `errors='strict'` 直接崩。
4. **多实例共享目录整文件覆盖**（2026-10-11）：任何"每台写一份状态文件"必须按实例命名 + 保留外来内容。
5. **后端重启是人工步骤**：真身在 `\\SERVER\dino_backend\`，`restart_dino_backend.bat` 只能在物理机跑。
6. **CF 边缘缓存**：数据请求带 `?t=`；版本号 `LB_VERSION` 必须递增才推得动 PWA。
7. **写入禁区**：前端/后端**都不写 ini**；ASA 后台也不接管写入。所有写入仍是人工流程。
8. **未验证不猜**：`max_allowed` 语义、AsaApi 热重载、每台机器是否都有 `Engine.ini`（本方案未逐台核）——界面上明说"未声明/缺失"，不编默认值。
9. **元数据缺口**：Beacon 表只有 362 条且不含 `RCONPort` 等，未收录键必须走 `meta_missing` 分支。
10. **默认值不权威**（§4.4）：`ShooterGame\Config` 在本环境不存在 ⇒ 只能"社区参考 / 出厂基线 / 插件 CDO"三选；界面上必须带来源标签，禁止把社区表说成官方默认。
11. **取基线别碰 Syncthing 目录的隐含风险**：客户端 `Saved\Config\Windows` 在被 Syncthing 同步，改名/删除会外溢到其它设备，操作前先暂停同步并先备份。
