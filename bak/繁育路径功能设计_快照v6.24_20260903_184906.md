## 1. 背景与方法论对齐

ARK 繁育标准路线：**① 种龙盘点（拼底板）→ ② 等级压缩 → ③ 属性变异（多线）→ ④ 多线合并 → ⑤ 收线留档**；颜色繁育为**独立旁路**（随时单独做外观）。核心资产是长期维护的「血统/种龙库」（属性线、颜色线分开管理，不混垃圾变异）。

### 1.1 流程单向性分析（2026-09-03 用户反馈 2 修订）

主线单向：**种龙盘点（拼底板）→ 等级压缩 → 属性变异（多线）→ 多线合并 → 收线**。两点说明：

- **盘点↔压缩存在小回环**：压缩（清氧/食/速）后若发现底板缺属性 → 回盘点补新种龙。主线仍单向，看板允许“压缩中补种龙”操作。
- **负变异 = 祖先计数 int32 溢出（v6.24 对齐）**：父/母同侧计数相加指数翻倍，超 2,147,483,647 溢出为负（垃圾线 1+1=2→4→8…翻倍 ~31 次）；负数 <20 → 游戏判定“未达 20 变异” → **恢复完整变异判定**（不直接加属性，只保效率）。定位：③④ 内嵌计数管理工具 + G 可**特意培养**（垃圾线）后导入主繁殖线。

附件 `报告/繁育方向`（四方向 + 负变异计数说明）→ 功能需求映射：

| 方法论 | 需要工具化能力 | 阶段 |
|---|---|---|
| 种龙盘点（组底板，能力已内嵌各 X 线头部 v6.20） | 每线头部看 ♂/♀ 最高在谁手、缺哪一方（拼底板前摸底） | ①（可回环补种龙） |
| 等级压缩（腾空间） | 氧/食/速应清零——标出待压缩项 + 等级估算 | ② |
| 属性变异 — **多线并行**（用户反馈 1） | **血线/攻线/耐线…各自独立叠变异**（分线防随机属性池污染）；每条线内 ♂/♀ 分开计数 | ③ |
| 变异计数管理（≥20 / **负变异 ∞** / 0 变异母） | 每成员计数实时看：`≥20` 预警、`<0` 金标（int32 溢出，恢复完整判定）；G 出**培养垃圾线**组 | ③④ 内嵌＋G |
| **多线合并**（用户反馈 1） | 各选中属性线代表 → 理论融合看板 + 合并后计数叠加预测 | ④ |
| 颜色繁育（做外观，**独立旁路** 用户反馈 3） | 6 region 色板 + Hex + 纯色/主题色检测；独立 line 类型、可单独实施 | 旁路 |
| 血统库维护 | **路线浮窗自动算线**（当前物种 × 已存选中属性派生；无持久线存储） | 全程 |
| **下一步推荐配种** | 依据**盘点缺口**优先：缺种龙→先补种龙；齐→压缩；可叠→高变异公×0变异母；近 20→续叠（含理由） | ②③④ 输出 |
| **查看生物完整卡** | 所有出现生物处（含盘点 ♂♀ 两列）放大镜小按钮 → 复用搜ID遮罩卡弹完整卡（归属已含容器+聚落） | 全程交互 |

> 负变异计数 ≠ 压垃圾属性：任一侧计数达 20/20 后新变异判定被压制。负变异 = 祖先计数 **int32 溢出**（2,147,483,647+1 → −2,147,483,648），游戏只判“<20”→ 负数被当未达 20 → **恢复完整变异判定**（不直接加属性，只是保住变异效率）。刻意获得：开**垃圾变异线** 1+1=2→4→8…翻倍约 31 次溢出成负 → 导入主繁殖线（v6.24 对齐用户机制分析；主流仍以高变异公 × 0 变异母大队续叠）。

## 3. 总体设计

### 3.1 入口与载体（v6：自动算线，零手动）
繁育栏新增按钮 **「🧬 路线」** → 打开独立浮窗（复用 `#lbBreedOverlay` 交互模式，点遮罩/✕ 关闭）。**打开即自动算线，无任何手动建/存/移出**：

- **范围**：当前选中物种（`LB.curClass`）＋ 我拥有的全部种龙（放出 / 球内 / 蛋 / 胚胎，`lbIsMyRec` 严格同步“我的”筛选规则）；
- **线 = 派生（非存储）**：以繁育栏**持续保存的选中属性**（`LB.breedSel`，per-species 持久于 `lbFilterLoadAll`）为主追属性，**每条选中属性自动成为一条“线”**（血线/攻线/重线/耐线…），浮窗内同时展示各线区块 + 合并视图；
- 未选任何属性时：展示当前物种我的种龙总览 + 提示“先在繁育栏选属性以拆线”。

### 3.2 数据模型（v6：无持久线存储）

- **删除** `lb_breed_lines` localStorage 与线对象（v4/v5 的 `members/exclude/mergeFrom/stage` 全部不需要）；
- 线 = 运行时派生对象：`{ cls: LB.curClass, attrK: <breedSel 之一>, members: <实时过滤> }`；
- 成员实时过滤：`recs` = `lbSpeciesMatch(r, LB.curClass)` ＋ `lbIsMyRec(r, playerSet, curPid)`，形态覆盖 released / 球内 / 蛋 / 胚胎（`source egg/embryo/_isEgg`）；
- 繁育栏属性选择变化 → 浮窗重算（lbBreedPick 后如浮窗开着则重渲染）；
- 唯一保留偏好：无（连浮窗开合状态都即时）。

### 3.3 交互（v6：取消 3.3——无新建、无移出、无手动入库）
- 打开浮窗 = 一切；成员超 20 分页/折叠；每条“线”区块头部显示：该属性线成员数 / ♂♀ 最优代表 / 计数预警。
- 干扰项处理：不做手动剔除（用户确认）；排序把“该属性点数>0 且代数高/等级合理”置前，蛋/胚胎附徽章自然区分。

### 3.4 浮窗自动看板（v6.20：打开即算，区块 = 单向主线 ①-⑤ + 颜色旁路）
**顶部总览条**：当前物种 我有 N 只（放出 X / 球内 Y / 蛋 Z / 胚胎 W）＋ 选中属性数 + 一键“重算”（数据手动刷新后）。文案用「我有 N 只」不写死“龙”（v6.22，物种不都是龙）。

**服务器等级上限约束（v6.23，Lmax=450 固定常量待配置）**
- 全看板按「服务器允许的最高生物等级 Lmax」做硬参考：初始常量 **450**（做成可配置项，按服务器实际值改）；三口径联动判定——
  1. **出生等级估算**：线/成员 Σ12 项点数 → 出生等级（`level` 兜底），显示 `出生 Lv~X`；
  2. **当前总等级**：成员现有 Lv（现状，接近 Lmax 给提示）；
  3. **手动升级余量**：`手动余量 = Lmax − 出生等级`；**逻辑 = 功能保证任何手动点法点到满级都 ≤Lmax（合法不超，非限制玩家操作）**——出生等级越高手动空间越小，压缩 = 归还手动空间；
- 规划动作若估算 `出生等级 + 后续叠变异点数 + 目标手动点 > Lmax(450)` → 该组/该线标 **⛔ 近服务器上限**，提示「先压缩省等级 / 换低底板 / 停叠收线」——**等级上限与计数 20 上限并列，均为硬边界**；
- Lmax 只体现在 📊 等级账本提示条与超限判定，顶部总览条不显示徽章（v6.24 精简）。

**未选属性降级页（v6.20）**：未在繁育栏选任何属性 → 无 X 线可拆，此时显示该物种我的种龙简览（总数/可点代表/提示“先在繁育栏选属性以拆线+盘点”），不显示完整盘点表。

**G. 配种计划（v6.14：多组·每组具体 1 公×N 母）**
- **优先级 = breedSel 序号（v6.24）**：所选属性列表的顺序即优先级（第 1 个 = ① 最高）：
  - **主配 = 叠 ① 属性**（优先级最高的那条线，0 变异母优先）；
  - **并行 = 其余选中属性按序各出叠线组**（②血、③重…），成员**尽量不与主配重种**（公各挑一、母尤其不重用；种不足时母回退蛋/幼崽候选）；
  - **路线标题栏显示当前所选属性与优先级**（如 `所选：攻① · 血② · 重③`），X 线区块按 ①→③ 顺序排列。
- **判定顺序（优先级 = 建议侧重，非硬阻断；各步组可并存/自由执行）**：
  1. **缺种龙（最高优先，v6.18：自动出「补种组」）**：某选中属性 ♂ 或 ♀ 明显低于对方/目标 → 主计划 = **补种组**（组卡，三态）：
     - **态 A · 有可用替代**：先从我的全部种龙（球内/蛋/冰箱…）自动搜出**达标替代**（如 重≥42 的 ♀ 藏在球/冰箱/蛋里）→ 直接列出替代候选（可点卡），组标题 `补重 ♀（球内替代）`，附“用替代补齐后再压缩/叠变异”；
     - **态 B · 叠线期母群跟不上**：出 `自产母群` 组 = ♂ 线代表 × 现有 0 变异母（具体），后续从子代筛 继承高线且 0 变异的 ♀ 扩母群；
     - **态 C · 真外部缺口**（替代无、自产无意义=底板期）→ 组卡显示缺口说明（属性/性别/当前最高/目标值）+ **建议来源**（外部市场/部落/等刷新蛋），无硬凑配对；
     - 补齐（替代/抓回/自产达标）后补种组消失，自动进入下一建议组；
  2. **压缩**（线代表氧/食/速>0，v6.17 为**建议非前置**）：等级余量足时可**直接叠变异**，压缩仅为省等级留更大变异空间（v6.23：等级受 Lmax=450 约束，垃圾点占等级 → 压缩=腾手动升级/变异空间）；
     - **有洗剂**（存在 垃圾全 0 且主属性 ≥ 基线的种，刚抓到的优先）→ 可生成**压缩组**（可多组 压氧/压食）：`♂ 线代表(氧36/食35) × ♀ 垃圾0种(洗剂)`，预期=子代垃圾 50% 清零；后续=筛 主属性达标且垃圾全 0 的新种续线；
     - **无洗剂**：不生成压缩组卡，改顶部**提示条**：“需压缩（建议）：线代表带 氧36/食35，当前无 垃圾=0 种作洗剂 → 先抓/配一只，抓到后自动出压缩组”；提示条仅为建议，不阻断叠变异组；
  3. **叠变异**（种龙齐即可，不必等压缩，v6.17）：公=该属性 ♂ 最高且计数可续（<20 或负变异 ∞）；母=该属性达标的 0 变异母优先、其次低计数；**等级余量检查（v6.23）**：估算子代出生等级＋计划变异点数 ≤ Lmax−目标手动点，超则提示先压缩/换低底板；
  4. **计数近 20/20**：换 0 变异母大队续叠；任一侧 <0 → 负变异（int32 溢出），恢复完整变异判定。
- **输出 = 配种计划（v6.19：全列可执行组，效率为王）**：
  - **负变异 ∞（v6.24 并行组，紫色同款无“培养”标）**：`并行 · 负计数溢出线`——从我的种龙自动挑 **0/0 低计数 1 公×1 母作种子**（如 耐毛鸟A × 攻毛鸟A，可点开卡）：0/0 种子先孵出 **1 次变异**（计数 1/0 起点，变异率约每 4–5 蛋 1 次）→ 同源子代互配计数翻倍（1+1=2 → 4 → 8 … **翻倍 31 次 ≈ 31 代**达 2³¹）→ **int32 溢出成负计数**（预计总计约 32–36 次配种）→ 导入主繁殖线，恢复 <20 完整变异判定（不直接加属性）；
  - **所有当前能同时处理的组尽量全部列出**（不再限 3 组）：叠攻变异、叠血变异、叠重变异、自产母群、压缩组、补种组等各自成卡；互不冲突即可并行开配；
  - 排序：判定命中的主计划（如缺种/叠主属性）置顶，其余按建议权重排序；提示条（压缩建议/无洗剂）始终在顶部但**不阻断任何组**；
  - 上限放宽仅防溢出（如 ≤10 组或按可用公/母组合分页，超限折叠“更多组”）；
  - 每组 = **1 公 × N 母**（N≤10），公/母均为具体种龙（名字/等级/计数，**名字可点开完整卡**（v6.20e））；0 变异母优先、其次低计数；
  - **组卡标题 = 角色标签＋目的（v6.20d，不写“组 N”）**：`主配 · 叠攻变异`（主计划绿）/ `并行 · 自产血 0 变异母` / `并行 · 压氧（洗剂）` / `并行 · 补重 ♀（外部/蛋）` 等；
  - 每组附**预期结果**（子代属性区间/计数走向）与**后续动作**（如：从子代筛 ≥X 的 0 变异 ♀ 扩母群）；
  - 示例组：`主配 · 叠攻变异：公 大盗二(攻44·12/13) × 攻毛鸟A、攻毛鸟B(0/0)`；`并行 · 自产血母群：公 大盗二 × 血毛鸟B → 子代筛 血≥42 且 0/0 ♀`；
- **更优自动顶上（v6.24，零持久化）**：无锚定/无“接班”状态记录——每次数据变化（子代孵出/外部新种/交易导入）浮窗**自动重算**，以当前数据中最优组合出组；只要比现线已达成值更高（无论子代变异还是外部），重算后自然顶替，无需任何人工锁定或记忆；
- 每组可整组“加入配对模拟”（阶段 2 接入）；组内任一成员可点开卡。

**按选中属性自动拆“线”区块（每 breedSel 属性 k 一块 = 一条虚拟线，③ 变异视角；v6.20b：头部仅状态，数值/性别入成员卡）**
- **折叠（v6.24）**：各 X 线区块可折叠；标题左侧**低可视小三角**（▾ 展开 / ▸ 收起，小字号弱灰）；**展开互斥**（accordion——同时只展开一条线，点另一条自动收起当前），默认展开第一条；收起时保留 标题+状态徽章，隐藏成员区；
- **头部（仅状态徽章，不重复数值）**：`血线 · 成员 8` ＋ 状态徽章：`✓ 齐`（绿）／`⚠ 缺♀`（红，缺口侧一眼可见）；**♂/♀ 最高数值不上头部**——性别与属性点已内嵌每张成员卡（见下），对比卡片即知谁最高、差多少；
- **成员范围（v6.20c）= 我的该物种全部种龙**：放出 / **球内（冷冻球，含 CryoFridge 冰箱与“宠物架/公母種”等架子）** / 冰盒蛋 / 胚胎，凡 `containerType≠released` 的非放出成员也全部入列排行——球内藏的高值母（如 F1 血44♀）同样算线内盘点与代表；
- **选材优先成年（v6.24）**：配种组与线排行默认先出**成年龙**（可立即配）；某档（属性×性别×计数）无同等合适的成年龙时，才回退列出 **幼崽 / 蛋 / 胚胎** 候选（🐣/🧊 徽章 + 「孵化/养大后入列」标注，可点开看属性与计数）——不因“非成年”漏掉可用材料；
- **成员小卡片（v6.20b）**：每卡 = **通用性别 SVG**（页面 lbSexSvg 同款）+ 名字 + **该线属性点（金字）** + Lv + 地图 + C 压缩徽章 + D 计数标；**不显示存放位置**（v6.20e：球内/宠物架等点开完整卡可见，顶部统计已区分存放数）；该线内按属性点降序排，点卡查看完整卡；
- 块内首行 = **该属性最优代表**（♀ 最高 / ♂ 最高 各 1）→ 用于配对/合并（卡内数值已示最高，无需再单列头部）。

**C. 等级压缩提示**（逐成员；v6.23 绑定服务器上限 Lmax=450）
- 标出垃圾属性点数：氧(3)/食(4)/速(9)（`statPoints`）；`>0` 橙「待清零」/ 全 0 绿「已压缩」；
- 线级 Σ12 项点数 → 出生等级估算（`level` 兜底）对比压缩差；
- **等级账本（v6.23）**：每成员/线代表显示 `出生 Lv~X · 手动余量 ~(450−X)`；估算 `出生 + 压缩可省点数 + 计划变异点 + 目标手动点 ≤ Lmax(450)`；压缩差=清垃圾（氧+食+速）可省等级数，直接增手动余量；若可手动空间过小（如出生 438 仅余 ~12 级）且仍带垃圾 → 提示“先压线再叠变异（还手动空间）”。

**D. 变异计数管理（③ 内嵌；v4：负变异非独立站）**
- 每成员显示 父/母系计数（`randomMutationsMale/Female`）：任一侧 `≥20` 橙「近上限」、双侧 `≥20` 红「基本报废」；任一侧 `<0` → **金标「负变异血统 ∞」**；
- 续叠策略：高变异公 × 0 变异母大队；负变异成员（<0 = int32 溢出）额外金标，提示恢复完整判定、可持续叠主属性；
- 代数汇总：按每条自动线 ♂/♀ 最大代数；同属性多代数路径 → 提示“断代对齐”。

**E. 多线合并（v6.21：并入 G 配种计划区 = 「可选」固定计划组，随时可执行）**
- 不再做浮窗底部独立展示表；在 **G 配种计划区**生成常驻一组 `可选 · 多线合并` 计划卡（标题如 `多线合并 · 血+攻`），与主配/并行组并列；
- 组内 = 1 公 × N 母各线代表（具体种龙，名字可点开完整卡）；组卡附**理论融合行**（子代每项取父母高值：如血42·攻44·重42）＋ **计数叠加预测**与 20/20 风险提示（换 0 变异母续叠 / 负计数溢出可恢复判定）；
- **常驻可选**：任何时候都可执行，不依赖当前是否缺种/压线，用于把多条线优点合成一条全能龙后再收线留档；
- 阶段 2 接入配对模拟时本组一键进模拟（E 看现状，模拟看期望）。

**F. 颜色繁育（v6.24：可选组 · 逐部位选色 · 按物种记忆，样式同其他组卡）**

- 每部位展示我的种龙该部位出现过的颜色 chips（点选/再点取消，可多部位指定）→ 实时推荐 **♂/♀ 命中最多** 组合（可点卡）；
- **按物种持久化（v6.24）**：选定组合存 localStorage（key 含物种，仿 `breedSel` 机制）——切换物种/重开自动恢复该物种的目标色；纯色检测/主题预置随实施保留；颜色组独立于属性主线（R5 同步）。

## 5. 技术要点 / 风险

- **零持久化（v6）**：无线对象/无 localStorage；线 = 运行时由 `LB.curClass × LB.breedSel` 派生，浮窗打开即算；属性/物种切换即时重算；成员与配种组每次重算取**当前数据全局最优**（v6.24：无锚定状态，更优自动顶上）。
- **成员过滤**：实时 `recs`（`lbSpeciesMatch(LB.curClass)` + `lbIsMyRec`），覆盖放出/球内/蛋/胚胎；随主数据刷新自动增减（数据手动刷新后点“重算”即可）。
- **查看卡（v6.8，同步 v6.2-6.6）**：直接复用 `lbShowIdCard` 同款 = `lbOwnerTag`（我的已含 地图+容器+聚落名）+ `lbDinoHTML` + `#lbBreedOverlay`；**无额外 helper/容器信息行**（v6.2 的 `lbViewCardHtml` 已废弃删除），不侵入 `lbDinoHTML`。
- 全部纯前端，**无后端改动**；离线可用；无存储膨胀问题。
- 浮窗性能：渲染按需（懒渲染 + 分页），成员卡复用 `lbDinoHTML`。
- 与现有繁育栏关系：路线浮窗是“我的种龙分析层”，读取 `breedSel`/`curClass` 但不干扰现有候选筛选。
- **多线（v4 保留）**：自动按 breedSel 拆虚拟线；合并表计数叠加预测为展示型（不做假确定性）。
- **颜色旁路（v4 保留）**：独立 Tab，共享“我的种龙”过滤，单独交付。
