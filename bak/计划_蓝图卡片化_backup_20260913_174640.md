# 计划：蓝图显示改为卡片形式

> 状态：**待评审**（用户确认后再实施）
> 建立：2026-09-13 ｜ 对象：`dino-import.html`（前端）+ 可能的后端导出参数
> 触发需求：**「将蓝图都显示成卡片形式」**

---

## 一、目标

容器/设施展开后，**蓝图类物品**当前以文字行呈现；改为**卡片形式**（图标 + 名称 + 数量），视觉与现有设施 chips / 物品图标风格统一，可快速扫读。

## 二、现状（已调研）

| 项 | 位置 / 结构 | 说明 |
|---|---|---|
| 物品数据 | `LB._cache.data.itemsByServer[abbr] = {byCid, byPos, byTribe, count, counts, ts}` (L3762-3776) | 来自 `item.json.gz`；`byCid[containerId] = [item…]` 逐堆明细（同资源多堆需 sum） |
| 容器查物品 | `lbContItems(...)`（L3782 附近：`byCid[containerId]`） | 容器 → 物品数组 |
| 蓝图标记 | 后端字段 `isBlueprint`（L3655：`if(d.isBlueprint===1) return;` 用于基因设备过滤） | 另有注释「**blueprint 类已按 rated=1 过滤**」(L3763) ⇒ **需先确认蓝图条目是否仍进入物品列表** |
| 书柜蓝图去重 | `lbShelfBpSet(grp)`（L8594 附近） | 本聚落书柜内的蓝图基名集合；制造设施中重复出现的同名蓝图视为「书柜远程分享」→ **不显示**（卡片化后必须保留此规则） |
| 现有卡片样式参考 | 设施 chip：`background:#1a1a24;border:1px solid #2a2a3a;border-radius:6px;padding:3px 8px;font-size:12px` + 16px 图标 + 灰英文小字 | 蓝图卡片沿用此体系，保持整站一致 |

## 二·补 S1 数据核对结果（✅ 2026-09-13 已完成）

**结论：蓝图数据齐全，可直接卡片化，无需后端改动。**

| 项 | 实测值 |
|---|---|
| 数据源 | `LB._cache.data.itemsByServer[abbr].byCid[containerId]` ✅ 10 服均有 |
| **权威分类字段** | **`type === 'blueprint'`**（Isl 2101 条）——另有 `isBlueprint=1`（Isl 3930，**语义偏宽，含普通物品，不可作唯一依据**）与 `rated=1`（Isl 2098，与 `type='blueprint'` 数量近似，可作辅助判定） |
| 全服规模 | `isBlueprint=1` 共 **11908** 条：Isl 3930 / Ext 2272 / Abe 2193 / Ast 1419 / Rag 730 / Val 393 / Cen 302 / Los 290 / Gen 197 / Sco 182 |
| 图纸特性 | **`quantity: 0`**（图纸无堆叠数量）⇒ **卡片不显示 ×N**；`stats`/`rating` 存在（可显示评分）；`kind` 可分组（weapon/saddle/armor/tek/other） |
| 物品字段全集 | `type,kind,class,key,quantity,durability,isBlueprint,rated,rating,qidx,stats,dropLoc,customClass,worldTime,containerId,containerType,containerClass,containerTribe,containerTribeName,playerName,x,y,z` |
| cid 命中规模 | Isl 598 容器 / 10068 物品；Abe 417 / 5814；Ext 322 / 4490 |

⇒ **S1 通过**：`type='blueprint'` 条目已在前端可查，**无需后端放开导出**；卡片判定应使用 `type==='blueprint'`（可用 `rated===1` 作辅助）。

## 三、实施步骤（分步可验证）

| 步骤 | 内容 | 涉及文件 | 验证方式 |
|---|---|---|---|
| **S1** | **数据核对**：取一个已知含蓝图的聚落/容器，用 `page.evaluate` 检查 `itemsByServer.byCid[cid]` 中是否存在 `isBlueprint=1`/`rated` 条目；若被后端过滤 ⇒ 与用户确认是否需要后端放开导出（**后端改动须单独确认**） | 只读排查 | evaluate 输出条目数与字段 |
| **S2** | 新增 `lbItemCard(item, opts)`：图标（`LB_ICON_BY_NAME` → `LB_ITEM_ICON_URL` → MDI 兜底）+ 中文名（`zhName`/`lbZhDeep`）+ 数量角标（`×N`）；样式与设施 chip 对齐 | `dino-import.html` | 本地渲染样例比对 |
| **S3** | 容器物品区改为 `display:flex;flex-wrap:wrap;gap:6px` 的卡片容器；**蓝图单独分组**（如标题「📘 蓝图」）置顶或末尾（见待决策项） | `dino-import.html` | 浏览器渲染核对 |
| **S4** | 性能与分批：大容器（Ext 常 150+ 条）沿用现有 `CH=150` 分批渲染模式，避免一次性 DOM 膨胀；卡片 DOM 复用字符串拼接（勿引入逐条 DOM 操作） | `dino-import.html` | 展开大容器时观察卡顿 |
| **S5** | 部署 CF + 三端验证（PC / 手机 / PWA）：卡片渲染正确、图标不缺失、书柜去重仍生效、滚动流畅 | `tmp/_deploy_cf.py` | 线上 `fetch` 版本 + 浏览器实测；SW 缓存需递增时同步 `pwa/sw.js` VER |

## 四、待用户决策（实施前需 3 项确认）

1. **卡片尺寸**：① 小 pill（与设施 chip 同高，一行可放 8-10 个）；② 中卡（约 96px 宽，图标在上、名字在下，可放 4-5 个）；③ 大卡（120px，含中文+英文+数量）
2. **范围**：仅**蓝图**卡片化，还是**容器内全部物品**统一卡片化（推荐统一，避免两套视觉）
3. **分组**：蓝图是否**单独分组**（如「📘 蓝图 ×N」标题 + 独立卡片区）还是与普通物品混排

## 五、风险与规避

| 风险 | 规避 |
|---|---|
| 蓝图被后端过滤（`rated=1`）⇒ 拿不到数据 | S1 先核对；确需放开则单独走「后端改动确认」流程 |
| 书柜远程分享去重（`lbShelfBpSet`）失效 | S2/S3 调用点保留 `_shelfBp` 过滤，卡片化只改呈现不改筛选 |
| 图标缺失显示空白 | 三级回退：`LB_ICON_BY_NAME` → `LB_ITEM_ICON_URL` → MDI `mdi-cog` |
| 大容器渲染卡顿 | 沿用分批（150/批）+ 字符串拼接，禁止逐条 append |
| 移动端横排溢出 | 卡片容器 `flex-wrap` + 字号 11-12px，与现有 chips 一致 |

## 六、验收标准

- 蓝图以**卡片**呈现（图标 + 名称 + 数量），不再是一行文字；
- 视觉与设施 chips 同一套语言（圆角、描边、底色、字号）；
- 书柜蓝图去重规则**仍然生效**；
- PC/手机/PWA 三端渲染一致，展开大容器无明显卡顿；
- 线上版本号可查、有回滚备份（`bak/dino-import_backup_*.html`）。
