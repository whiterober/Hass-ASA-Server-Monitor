# IP 变化 → 自动重启 → 全局共享进度 —— 落地方案

> 版本：v1（2026-11-05）
> 状态：**方案待评审，未开始编码**
> 范围：`dino_backend.py`（独立后端）+ `app_core.js` / `app_ui.js`（前端）+ ASAM（只调用，不修改）
> 前置结论（已实测）：`-ServerIP` 参数已可关闭，关掉后 ASA 自探测公网 IP 正确，异地列表可正常进入（Bob 已验证）

## 1. 目标

| # | 目标 | 验收标准 |
|---|---|---|
| G1 | **所有耗时操作的任务列表全服共享一份**（不再是每人一份 localStorage） | 两个不同浏览器/不同账号同时打开，看到**完全相同**的任务条、百分比、阶段文案、操作人 |
| G1b | **全项目只保留唯一一份任务列表**，并**同时渲染在「安全回档浮窗」与「服务器控制浮窗」尾部**（样式沿用现有 `.lb-task`） | 两个浮窗尾部内容**逐字一致**（同顺序、同百分比、同操作人）；任一操作后**两处同步刷新**；代码中只有一处渲染函数、一处数据源 |
| G2 | **IP 变化自动重启**，动作链路与「服务器控制」手点完全一致 | `srvctl.log` 里 `user=ipwatch` 的记录与手点记录字段一致；启动走同一 startq（heavy≤2、gap 8s、里程碑） |
| G3 | 只重启**无人在线**的服；有人的服先 **中英文公告 10 分钟**，空服即重启 | 公告每 60s 一轮、中英各一条；空置判定通过后自动进入重启 |
| G4 | 防「传送进行到一半」 | 三重静默（空置采样 + 日志静默 + 集群目录静默）全部满足才动手 |
| G5 | **每一个进度条都标注操作人**（无前缀，直接接在标题后） | 手点显示 `· <玩家名>`（取 `accounts.json[user].nick`，缺失回退 username）；自动显示 `· 自动` |
| G6 | **共享任务列表必须覆盖现有全部进度列表 + 未来新功能** | 强制范围：服务器控制任务条 / **安全回档（回档进度条本身就是列表里的一种任务，`action=rollback`，带 5 步 `steps`，不得丢弃、不得另画一套）** / 刷新数据浮窗进度 / IP 自动重启；架构约束：任何新执行器必须经 `utask_*` |

**非目标**：不改 ASAM；不改游戏参数语义（沿用已关闭 `-ServerIP` 的配置）；不引入新的第三方依赖。

## 3. 总体架构

```mermaid
flowchart TB
  subgraph 触发层 Trigger
    T1[ipwatch 线程<br/>解析 work.whiterober.cn]
    T2[UI 手点 / API 调用]
  end

  subgraph 编排层 Orchestrator
    O1[重启调度器 restart_orchestrator<br/>状态机/公告/三重静默]
  end

  subgraph 执行层 Executors（与手点共用）
    E1["_srvctl_run(user, [srv], 'savekill'|'kill')"]
    E2["_srvctl_startq_new(user, [srv])<br/>heavy≤2 / gap 8s / 里程碑"]
    E3[arkbackup job]
  end

  subgraph 任务总线 TaskBus（新增）
    B1[utask_* 内存表 + tasks_state.json]
    B2["GET /api/tasks?since="]
    B3["POST /api/tasks/dismiss|abort"]
  end

  subgraph 前端
    F1[任务面板（改为读服务端）]
  end

  T1 --> O1 --> E1
  O1 --> E2
  T2 --> E1
  T2 --> E2
  E1 --> B1
  E2 --> B1
  E3 --> B1
  B1 --> B2 --> F1
  F1 --> B3
```

**核心原则**
1. **只有一条写入路径**：所有执行器（startq / srvctl job / arkbackup job / 重启调度器）都通过 `utask_*` 登记，不在别处拼文案。
2. **前端零本地状态**：`LB_TASKS` 退化为服务端数据的只读镜像（保留内存防抖，不再写 localStorage）。
3. **调度器不自建执行器**：它只调用与 UI 相同的入口（`_srvctl_run` / `_srvctl_startq_new`），保证"一模一样"。
4. **共享列表是强制约束，不是可选功能**：现有 4 处进度（服务器控制 / 安全回档 / 刷新数据浮窗 / 自动重启）全部改接任务总线；**今后任何新功能只要产生进度，必须走 `utask_*`**，否则评审不通过。
5. **一份数据、一个渲染函数、多个挂载点**：`lbTaskRender()` 改为遍历所有 `.lb-task-slot` 容器（当前 2 个：安全回档浮窗尾部、服务器控制浮窗尾部）；新浮窗只需加一个 `div.lb-task-slot` 即自动接入，**禁止再复制一份列表 UI**。

## 4. 任务总线（Task Bus）设计

### 4.1 任务对象

```json
{
  "id": 10231,
  "key": "Isl|restart",            // 同 key 覆盖（与现有 LB_TASKS 语义一致）
  "server": "Isl", "srvName": "孤岛",
  "action": "restart",              // start|kill|savekill|saveworld|destroy|rcon|backup|rollback|restart
  "label": "重启（IP 切换）",
  "phase": "run",                   // queue|run|ok|fail|skip|warn
  "pct": 35,
  "msg": "存档中…",                // 面向玩家的一句话
  "steps": [                        // 可选：分步（回档/重启）
    {"k": "announce", "t": "公告", "s": "ok"},
    {"k": "wait_empty", "t": "等待空服", "s": "run"},
    {"k": "savekill", "t": "存档退出", "s": "todo"},
    {"k": "startq", "t": "队列启动", "s": "todo"},
    {"k": "verify", "t": "确认上线", "s": "todo"}
  ],
  "operator": "ipwatch",            // 谁触发（审计用，username；ipwatch=自动）
  "operatorName": "JaronV5",          // 展示用：手点=accounts.json[user].nick（游戏内玩家名）；自动=“自动”
  "t0": 1762345678.1, "tEnd": null, "hideAt": 0,
  "err": "", "meta": {"ip": "1.2.3.4", "players": 0}
}
```

- **去重**：`key` 唯一；同 key 的新任务替换旧任务（保留 `id`）
- **TTL**：成功 60s 后 `hideAt` 到期自动清理（比现在 10s 更适合多人围观）；失败保留到手动 `dismiss`
- **上限**：最多 200 条，超出丢弃最旧的 ok

### 4.2 接口

| 方法 | 路径 | 说明 | 权限 |
|---|---|---|---|
| GET | `/api/tasks?since=<rev>` | 返回 `{rev, tasks:[...]}`；`since` 命中则返回 `{rev, changed:false}`（省流量） | **无独立权限**：跟随所在浮窗的鉴权（与 `/api/srvctl/*` 同一 guard）；不新增任何权限概念 |
| POST | `/api/tasks/dismiss` | `{ids:[...]}` 或 `{allFail:true}` | 需 token（二级管理员） |
| POST | `/api/tasks/abort` | `{id}` 或 `{server}` —— 中止调度器/取消排队 | 需 token |
| GET | `/api/tasks/stream` | *(可选)* SSE 推送 | 同 GET |

> 前端默认 **2s 轮询 + `since` 增量**（与现有轮询频率一致，避免 CF 隧道下 SSE 缓冲问题）。

### 4.3 持久化

- `tasks_state.json`（后端目录）：仅存 `id/key/phase/t0` 等轻量字段，供后端重启后把 `run/queue` 任务标为 `fail('后端重启导致中断')` —— 与现有 `lbTaskLoad` 的语义对齐
- 写入节流：≥1s 或 `phase` 变化时才落盘

## 7. IP 变化自动重启（业务层）

### 7.1 触发

- ipwatch 判定"连续 2 次解析一致且 ≠ `lastIp`"（现有逻辑，`mode` 由 `notify` 升为 `restart`）
- 触发后**整批**处理 11 台（同一轮 IP 变化只跑一次编排，10 分钟内不重复）

### 7.2 全局调度

```mermaid
flowchart TB
  A[检测到 IP 变化] --> B[为 11 台各建 task<br/>phase=queue, steps=全部 todo]
  B --> C{是否有服 0 人在线}
  C -->|有| D[选锚点服：在线最少 + 有存档]
  D --> E[锚点服走 QUIESCE→重启]
  C -->|无| F[全部进入公告期]
  E --> G[锚点完成 → 刷新"可传送目标"列表]
  F --> G
  G --> H[其余服：空置即按序重启<br/>串行 1 台（含 startq 内部 heavy≤2）]
```

- **串行**：调度器同一时刻只允许 1 台进入 `SAVEKILL/STARTQ`（避免"刚重启的服又被传进来"）
- **锚点服**：**动态选**（在线最少 + 有存档），不固定某台；且必须先跑**完整保存流程**：
  `SaveWorld`（RCON）→ `_dinodata_wait_stable` 落盘屏障通过 → 才允许 `savekill` → `startq`；任一环节不通过则**不进入重启**，回到等待重试
- 顺序：锚点 → 已完成列表逐步扩大 → 其余按"空置就绪时间"先到先启

### 7.3 单台状态机

见前文状态机（`ANNOUNCE → WAIT_EMPTY → QUIESCE → SAVEKILL → STARTQ → VERIFY → DONE`）。
- 任一步失败：`attempts+1`；≤2 次重试，>2 次置 `fail` 并告警
- `VERIFY`：以日志 `Server has completed startup and is now advertising for join` 为准（与 startq 里程碑一致）

### 7.4 三重静默（防传送中断）

| 层 | 判据（默认值，可配） |
|---|---|
| L1 空置采样 | RCON `ListPlayers` 连续 **3** 次为 0，跨度 ≥ **180s** |
| L2 日志静默 | `ShooterGame.log` 最近 **180s** 无 `Join succeeded` / `disconnected` / `transfer` |
| L3 集群目录静默 | `ClutserPath`（`D:\ARK Server`）下跨服数据目录最近 **180s** 无新写入 |

任一不满足 → 回 `QUIESCE`，30s 后重测。
**Bob（俱乐部）特例**：无存档（`存档不落盘`）→ 用 `kill` 而非 `savekill`；调度时排最后。

## 8. 公告设计（中英文）

**通道**：与 UI「📢 重启提醒」相同的 `broadcast`（RCON）。

**节奏（已定）**：**每 10 分钟为一轮；每轮内只公告 1 分钟，每 30s 一条、中英交替，共 2 条**；其余 9 分钟静默；**如此循环直到该服重启完成**。

```
00:00  中文公告
00:30  英文公告
01:00–10:00  静默（同时持续采样空置/静默判据）
10:00  下一轮……直到重启完成
```

### 8.1 模板（有可传送目标时）

```
【网络切换维护】检测到公网 IP 变动，本服将在「无人在线时」自动重启。当前在线 3 人。
可传送至（已完成重启）：核心岛 / 孤岛
[Maintenance] Public IP changed. This server will auto-restart once empty. Players online: 3.
Transfer targets (already restarted): Cen / Isl
```

### 8.2 模板（暂无可用目标）

```
【网络切换维护】检测到公网 IP 变动，本服将在「无人在线时」自动重启。当前在线 3 人。
暂无已重启的服务器，建议先下线等待，重启完成后即刻恢复。
[Maintenance] Public IP changed. Auto-restart when empty. Players online: 3.
No restarted target available yet — please log off and wait; we will be back shortly.
```

### 8.3 变量与约束
- `{在线人数}`：`ListPlayers` 实时值；`{目标}`：已完成重启的服中文名（`SERVER_THEMES[srv].name`）
- 单条长度 ≤ 200 字符（避免客户端截断），中英文分两条发送
- 最后一轮追加：`即将重启 / restarting soon`

## 10. 测试清单

1. **并发一致性**：6 个客户端同时打开，比对任务 JSON 的 `rev` 与渲染结果
2. **去重**：同一服连续两次点「启动」，只出现一条
3. **中断恢复**：`restart_dino_backend.bat` 重启后端，进行中任务变 `fail(后端重启导致中断)`
4. **公告**：抓 `ShooterGame.log` 的 RCON 回显确认真实下发；中英各 10 条
5. **传送保护**：模拟"空置 2 次后有人进"→ 状态机必须回到 `WAIT_EMPTY`，不重启
6. **Bob 特例**：确认使用 `kill`，且不发生存档等待
7. **失败路径**：ASAM 停机 → 单台重试 2 次后 `fail`，其余服继续
8. **回滚演练**：`mode=notify` 生效后，编排器不再动作

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 前端仍有本地缓存导致"看起来不一致" | F2 彻底移除 localStorage 写入；首屏强制 `since=0` 全量拉 |

### 13.2 归类原则（已定）

- **A 类（服务器操作）→ 唯一任务列表**：`1 / 2 / 7 / 8`
  - 特征：对服务器做了动作、需要全服共享、需要操作人标注、需要审计
  - 同时渲染在**安全回档浮窗尾部**与**服务器控制浮窗尾部**（同一份数据、同一个渲染函数）
- **B 类（数据搬运/查询）→ 保持各自独立浮窗**：`3 / 4 / 5 / 6 / 9`
  - 原因：高频、量大（如 5000+ 文件下载），塞进统一列表会淹没运维任务；且天然"因人而异"

### 13.3 由此产生的强制约束

1. A 类**只有一份数据源**（Task Bus）、**只有一个渲染函数**（`lbTaskRender` 遍历 `.lb-task-slot`）
2. B 类**不得**再写 `LB_TASKS`，也不得出现在两个浮窗的列表里
3. 新增功能若属 A 类（有服务器动作），必须走 `utask_*`；若属 B 类（纯数据），沿用分段条并保持独立
