## 收尾风险分析（v6105~v6112 优化链，只读，未改代码）

- 状态：✅ 分析完成（不改代码，风险清单待用户决定是否处理）

### 结构性风险（最高）
1. **immutable + 版本号强耦合**：`_headers` 对 `/app.css` `/app_data.js` `/app_core.min.js` `/app_ui.min.js` 设 `max-age=31536000, immutable`，唯一生效前提是 URL 带新 `?v=`。而源文件 `dino-import.html` 的 ?v= 仍是陈旧值（app_data=6101、app_core=6104），全靠打包脚本正则改写（`asset ?v= -> ...（改写 4 处）` 只 print 不断言）。若漏跑打包 / 正则失配 / LB_VERSION 未找到（脚本仅 WARN 跳过）⇒ 旧 URL + immutable = 修复一年到不了用户。
2. **terser 依赖「默认不混淆顶层名」**：`onclick="lbXxx()"`、stub 覆盖、跨文件调用全依赖全局函数名原样保留。当前未传 `--mangle`/`--compress`，靠 terser 默认 `toplevel:false` 才安全；一旦显式 `--mangle toplevel` 或默认变更 ⇒ 全站交互静默失效。实测当前产物保留 `function lbRenderFuncBar` / `function lbWikiOpen` ✔。

4. **失败重试堆 script**：`lbUIEnsure` onerror 置 `__lbUI=null` 但不清理已注入的 `<script>`；反复失败后再成功，可能同时执行多份 app_ui.js ⇒ 顶层 var（`LB_WI`/`LB_MW` 等）被重新初始化。
