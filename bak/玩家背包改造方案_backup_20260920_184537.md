# 玩家背包改造方案（dino-import）

> 日期：2026-09-20　范围：**方案文档（不改代码）**
> 需求（用户原话）：「在工作区生成一个方案，改造玩家背包的呈现方式：完全复用其他 TAB 的呈现方式：
> ① 只是聚落列表改成显示玩家当前所有在位置　② 聚落里面的呈现方式完全和其他聚落的一致　③ 同时要显示背包里所有可显示的物品」

---

## 一、需求映射（我的理解）

| 需求条目 | 落点 | 说明 |
|---|---|---|
| ① 列表改为「玩家当前位置」 | 现有**聚落列表**（`lbRenderServers()`）的**数据源与条目文案**改为玩家 | 每条 = 一位玩家（角色名 + 所在服 + 坐标 / 距最近聚落），而非一个聚落 |
| ② 内部呈现与聚落一致 | 详情外壳与渲染管线**完全复用** | 复用 `#lbSettleDetail` / `#lbSettleBody`、返回按钮、容器手风琴、chip 布局 |
| ③ 显示背包内所有可显示物品 | 详情主体内容 | 取玩家背包容器的 items → 过滤「可显示」→ 以 chip/网格呈现 |
| 总纲「完全复用其他 TAB 的呈现方式」 | 复用而非重写 | 不新增第二套 UI，把聚落详情抽成**公共详情组件**，聚落/玩家两个数据源共用 |

## 二、现状调研（源码事实 + 实服实测）

### 2.1 数据源

| 数据 | 来源 | 实测／备注 |
|---|---|---|
| **玩家身份** | cryo `players[]`：`{pid, eosId, name, characterName, roles}` | Isl 实测 **46 条**；**不含坐标** ⇒ 位置需另取 |
| **玩家位置（在线）** | `LB.SVC_PLAYER_POS` → `lbPlayerPosAll()`：逐服查 `script.player_pos`；新架构直读 `LB_STATUS + '/player_pos_status_<abbr>.json'` + 免认证 `/api/player_pos` | 现有「追踪野生龙」功能已在用 ⇒ 可直接复用（dino-import.html L16716+） |
| **玩家位置（离线/静态）** | cryo `structures[]` 中的 **`PrimalInventory1_*`** 容器坐标 | Isl 实测 `PrimalInventory1` 出现 **108 次**（玩家背包容器本身带 x/y/z）⇒ 离线也能给"最后所在位置" |
| **背包内容物** | `lbItemsOfContainer(server, containerId, containerClass, x, y)` | 现有容器手风琴读物品的同款通道 |
| **物品显示元数据** | `item_zh.json`（中文）· `itemstats.json`（属性）· `icons2.json` + `webp_map.json`（图标/缩略图） | 三表均已随 CF 打包（本地供给） |
| **部落/聚落** | cryo `tribes[]` + 现有聚落管线 | 用于"背包主人属于哪个部落/距哪个聚落最近"的副标题 |

### 2.2 现有渲染管线（要复用的对象）

```
lbRenderServers()            ← 列表（当前：聚落）
   └─ lbOpenSettle(btn)      ← 打开详情（L10530）
        └─ #lbSettleDetail / #lbSettleBody   ← 详情外壳（模板 L10081，含"返回"按钮）
             ├─ lbFacAreasBuild(fList, efList, signList, signPts)   ← 分层 + DBSCAN 建区（L12686）
             ├─ _mkAreaChips(list)                                  ← 区域内 chip（无名按类型 ×N 聚合，L11955）
             └─ 容器手风琴 / 放出组 / 命名牌子                        ← 聚落专有
```

### 2.3 现有"背包"痕迹（说明为何用户会觉得"已经有背包"）

| 位置 | 事实 |
|---|---|
| `lbContainerTypeOf(r)` | `containerClass` 含 `PrimalInventory1` ⇒ 类型判定为 **`player`**（L4123-4124） |
| 聚落算法 | `if(lbContainerTypeOf(r)==='player') return;` ⇒ **玩家背包被显式排除**，不算聚落、不进容器聚合（L4545 等 4 处） |
| 容器渲染 | `var tzh = sub==='player' ? '背包' : …` ⇒ 背包容器在容器手风琴里**以"背包"标签出现**（L9225） |

⇒ 也就是说：**"背包"目前只是容器手风琴里的一个普通条目**；用户要的是把它**升格成一个与聚落并列的"视图"**（列表 + 详情）。

## 三、方案对比

| 方案 | 做法 | 优点 | 代价 / 风险 | 评价 |
|---|---|---|---|---|
| **A 新增「玩家」视图（推荐）** | 抽出公共详情组件 `lbOpenEntityDetail({kind, title, subtitle, items, ctx})`；列表新增"玩家"数据源（位置 + 背包容器）；聚落与玩家共用同一详情外壳与 chip/手风琴渲染 | 满足"完全复用"；聚落路径零回归（同一函数，参数化）；后续可扩"恐龙/容器"视图 | 需重构 `lbOpenSettle`（约 1 处拆壳，改动集中）；列表需新增数据源与排序 | ✅ 推荐 |
| **B 改造聚落列表（在列表里混入玩家）** | 同一列表里既列聚落又列玩家（分组或 Tab 切换） | 改动最小（只改列表渲染） | "聚落列表"语义被污染；排序/筛选/搜索逻辑要兼容两类实体；用户明确要"改成显示玩家位置"⇒ 与需求半冲突 | ⚠️ 备选 |
| **C 仅局部对齐样式** | 只把容器手风琴里的"背包"条目样式对齐聚落风格 | 几行改动 | 达不到"完全复用"与"显示所有物品"的目标 | ❌ 不推荐 |

**推荐 A**：与用户"完全复用其他 TAB 的呈现方式"的总纲一致 —— 复用是"用同一组件"，而不是"抄一套样式"。

## 四、方案 A 实施要点（供确认后开工）

1. **抽公共详情组件**（先做，零行为变化）
   - 把 `lbOpenSettle` 中「打开详情外壳 + 返回按钮 + 内容容器」的片段抽为 `lbOpenEntityDetail(opts)`；`lbOpenSettle` 改为调用它（同一传入参数 ⇒ 聚落行为不变，便于回归对照）。
2. **列表数据源切换**（需求①）
   - 新增 `lbPlayersList()`：合并「cryo `players[]`（全员）」×「各服 `PrimalInventory1_*` 容器坐标」×「在线 `player_pos`（若可得）」。
   - 条目文案：`角色名` + 副标题 `服 · 坐标`；在线者加「在线」标记，离线显示"最后位置 + 采集时间"。
   - 排序：在线优先 → 距本服聚落中心由近到远。
3. **详情内容（需求②③）**
   - **外壳/返回/chip 布局/容器手风琴 = 复用**；
   - **区域算法不套用**（背包没有"区域/牌子命名"语义）⇒ 详情主体改为：`背包容量摘要` + `按类型聚合的 chip（×N）` + `可展开的物品明细（名称/数量/图标/属性）`；
   - 物品过滤"可显示"：`item_zh` 有中文 或 `icons2` 有图标 或 `itemstats` 有条目 ⇒ 三者皆无的（内部占位物）不渲染。
4. **跨服与性能**
   - 玩家可能跨服存在 ⇒ 列表按 `eosId` 聚合、多服分别成条（或在副标题标"另有 N 服角色"）；
   - 背包容器 108/服（Isl）量级很小，列表与详情均可即时渲染；物品明细建议**按需加载**（点开某容器再取 items），避免首屏拉全量。

## 六、风险与兼容

- **回归风险**：方案 A 会动 `lbOpenSettle`（聚落主线）⇒ 必须做「改动前后聚落详情对照」（区域数/命名/容器条目一致）。
- **缓存**：新视图若改变数据结构 ⇒ 递增 `LB_SCHEMA_VER`（当前 17）让旧用户强刷自动重建。
- **性能**：物品明细按需加载；列表不要每服轮询 `player_pos`（沿用现有 `player_pos_status_<abbr>.json` 静态文件 + 轮询间隔）。
- **权限**：背包属于其他玩家 ⇒ 是否需要"只看自己部落"的过滤（现有 `lbPlayerTribes` 可判"我的/外部"），建议沿用现有匿名标签口径（`xxx 背包`）。

## 七、验证清单（实施后逐项执行）

- [ ] 列表：玩家条数与实服 `players[]` 一致（Isl 46 ⇒ 去重后条数一致）
- [ ] 位置：在线玩家坐标与 RCON `player_pos` 一致；离线玩家坐标 = 背包容器坐标
- [ ] 详情：外壳/返回按钮/滚动行为与聚落详情一致（同一组件）
- [ ] 物品：抽样 3 名玩家，`lbItemsOfContainer` 条数 = 页面显示条数（含"不可显示"过滤计数说明）
- [ ] 图标：物品图标命中 `icons2` 或回退 MDI（无破图）
- [ ] 回归：聚落详情区域数/命名/容器条目与改动前一致（Isl + Abe 必做）
- [ ] 性能：首屏不因玩家列表变慢；点开玩家详情到渲染 <300ms（本地缓存命中）
