## 二、设计（唯一源原则）

### 2.1 物品→物种判据（分类表法，唯一判据；2026-10-03 v2 修订）
> **v2 修订说明**：原「词干表 → en 名 → zh 名 → 类名词干」四级解析链**已废弃**（用户口径：**不用自建规则，只用分类表**）。
> 判据命中即归物种；未命中（含无族名）一律**保留在模块栏**（不猜）。

**判据链（唯一）**：
1. `fam = lbItemFamByCls(base)` —— 读分类表 `dino_rules.json.itemFamilyCls`（836 有序规则 + ex 排除表），得出**族名**（实测 126 件覆盖 125/126）；
2. 查**映射表** `dino_rules.json` 新键 `attachSpecies`（纯数据、两级结构）：
   - `fams`：**族级默认** `{ 族名: 物种 }`（如 「战车」→ 战车）
   - `items`：**物件级覆盖** `{ 词典键: 物种 }`（用于「未组装」「载具」「皮肤」等**一族多物种**场景；物件级优先于族级）；**值支持数组（1:N）**——一个物件同时归多个物种（如 `Lost_Drakeling_Costume` → 4 种精灵龙、`Wyvern_Bone_Costume` → 4 元素飞龙），数组 ⇒ 在每个目标物种面板**各出一个该物件 TAB**
3. 命中 → 该物品归映射物种（装备榜「模块」TAB）；未命中或不映射 → 保留在模块栏。

- **零代码规则**：所有对应关系只存在于分类表与映射表（数据），后续增删只改 `dino_rules.json`
- 缓存：解析结果按 `base + 数据指纹` 缓存（`LB_ATTACH_SP_CACHE`）
- 映射表初值见 §2.5 表 4（族级）与表 5（物件级）

### 2.2 模块栏移出（浮窗侧）
- 接入点：`lbItemNoHaveByKind()`（line 18940 附近）attachment 分组处理处
- 逻辑：`k==='attachment' && lbItemSpAttachOf(base)` → **占位**（`_seen[lbItemAggKey(base)]=1; _seen[lbCanonBase(base)]=1`，防同物孪生前缀键补位）→ `return`
- 影响：模块栏 126 → **保留 ≈24（移出 ≈102）**（口径见表 6）；其它栏（建筑/资源/消耗/弹药/战利品/染料/蛋/器械其它段）不动
- 说明：本改动**只影响浮窗列表**；物品索引（`lbItemIsPick` 体系）、聚落卡角标、容器组渲染均不受影响

### 2.3 物种装备榜结构（v3「完全统一」：每物品一个 TAB；2026-10-03 用户口径）
> **v3 修订说明**：取消「单一模块 TAB + 目录段」与原「鞍 / 蓝图」两个特殊类目（用户口径：**鞍与附件完全同体系、不做特殊化**；并入 v2 的「合并鞍与蓝图」要求）。

**TAB 结构（完全统一，零特殊化）**：
1. 物种榜 = **每个物品（词典键 base）一个独立 TAB**：标签 = 物品中文名（如「霸王龙鞍」「机甲护盾模块」「幽灵霸王龙套装」）；**角标 = 我的条目数**；**TAB 图标 = 页面既有「类别图标」约定**（`LB_INV_GRP[kind].ic`，细 kind 优先、回退粗 kind、兜底 `IconMiscNoteType`；渲染口径同物品榜 v4211）
2. 每个 TAB 的条目（统一口径；**v4 修订**）：
   - **我的实物（带品质 qidx≥1）**：独立行卡（评分降序）
   - **我的实物（原始 / 未评级 qidx≤0）**：**取消过滤**——按「**物品 + 容器**」合并为一行（**复用带品质行卡样式**、显示 **×数量**、无评分胶囊），排尾（默认按数量降序）
   - **我的图纸**：qidx≥1 的蓝图（`lbIsBp && !lbIsFixedRecipeBp`；**蓝图保持过滤**）
   - **外部图纸**：符合「高于我的最佳」的前 5 条（沿用现有蓝图口径；**外部实物不显示**）
3. **TAB 显示条件**：上述条目任一存在（**含仅有原始品质合并行**）；全空 → **不显示该 TAB**（原「目录段」设计取消）
4. 排序：TAB 内按评分降序（实物与图纸**混排**；未评级排尾）
5. **底部红 tip 行（新增）**：面板底部沿用现有红 tip 样式（`#2a1a1a/#f87171`），列出该物种**被隐藏的 TAB**（= 全库存缺少的附件 / 鞍 / 生物外观等物件），文案示意「全库存缺少：机甲护盾模块、幽灵霸王龙套装 …」。**定义（v7 精确化）**：被隐藏 = 该物种下无任何显示条目（含“仅外部实物、被口径排除”者）；**1:N 物件逐物种分别评估**；文案 S3 定稿
6. 物品归属物种沿用 §2.1 分类表法（映射表 `attachSpecies`）；**物品榜**（`lbRankRenderItemPick`，物品模式）**同步采用 v4 口径**（实物原始合并行；蓝图保持过滤）

### 2.4 与既有口径的关系
- v4158「服装类不属物种绑定」仅作用于 armor/weapon/tek 栏的过滤场景；本次新需求明确「服装一并移出模块栏并专门显示」→ 在 attachment 栏 + 装备榜场景下生效，两者不冲突（不回改 v4158）
- v1368「物种体系已涉及的装备不重复收录」→ 本次是把 attachment 类补进该体系
- v3（2026-10-03）：**鞍取消特殊化**——原「鞍 = 仅我的实物（mineOnly）」口径取消，统一为「我的实物全量 + 我的图纸 + 外部图纸前 5」
- v4（2026-10-03）：**原始品质取消过滤**（两榜）——带品质实物=独立卡行；原始/未评级实物=按「物品+容器」**合并行（×数量）**（复用卡样式）；**蓝图保持过滤**

## 五、风险与备选

| 风险 | 缓解 |
|------|------|
| 分类表漏项 / 族值调整（如新增皮肤未入族表） | 未命中即保留（不猜）；映射表随分类表更新，纯数据零代码 |
| 一族多物种（未组装 / 载具 / 皮肤） | 物件级映射表（表 5），物件级优先于族级；S1 生成初值 → 人工核对 |
| **1:N 映射的重复展示**（同物件在多个物种各出一 TAB） | 显示条件 / 红 tip / 角标**按各物种分别评估**；模块栏仅移出一次（占位防重） |
| **红 tip 语义歧义**（仅“外部实物被排除”的物件也会被列） | tip 口径 = **被隐藏的 TAB**（该物种无任何显示条目）；文案 S3 定稿（示意「缺少：…」） |
| **原始合并行排序 / 归属**（跨容器混合） | 合并行 = 同容器聚合（×数量），归属标签沿用现有解析；排尾按数量降序 |
| 性能：`lbRankEnsure` 增加解析 / 合并成本 | 解析结果按 base 缓存（126 项量级）；合并仅对 qidx≤0 行一次聚合 |

## 六、复核结论与优化建议（2026-10-03）
1. **判据收敛**：改造为「分类表法」后，代码面**零自建规则**（只调既有 `lbItemFamByCls` + 读映射表），维护成本与误配风险同步最低
2. **覆盖已足**：分类表实测 125/126 有族名 → 无需任何自建兜底；`SaddleCart` 无族 → 保留（如需归位，在分类表补族即可）
3. **映射表两级结构**：`fams`（族级默认）+ `items`（物件级覆盖）解决「未组装/载具/皮肤」一族多物种；物件级优先
4. **幽灵皮肤归主物种**（用户口径 2026-10-03）：与骨架/生化皮肤同口径；映射表注释注明，避免日后歧义
5. **条目附计数**：表 4 每族附件数，便于复核与回归比对
6. **显示口径（v3 统一）**：每 TAB = 我的实物（全量）+ 我的图纸 + 外部图纸（前 5）；全空 → 不显示 TAB，名称列底部红 tip（隐藏 TAB 清单）
7. **性能**：`lbItemFamByCls` 为既有函数（836 规则线性扫），单 base 一次 + 缓存；126 项一次性预演无压力
8. **回归面收敛**：仅影响「模块栏列表 + 装备榜（物种 / 物品两榜）」；排序/分块/物品索引/聚落卡/角标不动
9. **TAB 图标（已定）**：用页面「类别图标」约定（`LB_INV_GRP.ic`，细 kind 优先），零新规则
10. **基线差异清单**：S1 必须输出「分类表法 vs 原四级链」移出项差异，供最终口径拍板（验证清单第 14 项）
11. **原始品质呈现（v4）**：取消过滤但**按「物品+容器」合并（×数量）**避免刷屏；合并行复用品质卡样式，同一容器多件合一行
12. **1:N 复核（v6）**：`Lost_Drakeling_Costume` 在 4 种精灵龙各出一 TAB；红 tip / 角标按各物种独立评估；模块栏移出仅一次
13. **同类判定沉淀（v8）**：数据模式「家族无基础形态、仅多形态并存 ⇒ 1:N 全形态」——全量排查仅精灵龙与飞龙两族命中；后续新增皮肤/附件可复用此判据（查物种表家族形态结构）
