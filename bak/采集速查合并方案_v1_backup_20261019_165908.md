# 采集速查合并到搞事系统 · 方案 v1

- 制定日期：2026-10-19
- 目标系统：dino-import（粑粑服搞事系统，CF Workers 纯 Assets + 物理服务器后端）
- 涉及需求：玩家级独立存储 / 物品浮窗入口 / 有流程标识 / 流程自由可配 / 复用物品物种浮窗数据

---

## 0. 结论摘要

把 ASA 后台「部落运维速查 → 采集速查」从**全服静态表格**升级为搞事系统内的**物品维度采集流程库**：

- 入口：物品浮窗选中物品后，底部繁育栏（物种同款功能条）右侧的「采集流程」按钮组
- 有采集流程的物品项显示镐图标角标（仅标识，不可点击）
- 流程步骤自由增删改、可插入物品/生物引用
- 引用选择直接复用现有物品/物种浮窗（中英文、图标、数据同源）
- 数据按**玩家账号**云端存储，切换角色（pid）不丢、不同玩家互不可见
- 原采集速查页面（`info_whiterober` → `efficient_farming`）**保留不动**，仅把 20 张卡片迁移为内置模板

不改 lovelace、不改 ASA 后台、不动 `tribe_ops.json`。

## 2. 现状盘点

### 2.1 现有采集速查（数据源）
- 位置：`tribe_ops.json` → tabs → `id: efficient_farming`（名称「采集速查」）
- 类型：`mixed_content`，块 = 1× `map_filter` + **20× `info_card`**
- 列头：`地图 | 采集点 | 产出 | 流程`
- 卡片内容：
  - `title`：采集点或资源名（野外 / 生肉 / 纤维 / 毒气洞 / 林中湖 / 血池 / 木材 …）
  - `descriptions`：流程行；`^` 前缀 = 编号步骤，`*` 前缀 = 备注；`[中文名]` = 物品/生物引用（如 `[跳蛛][星尾兽][低温冰箱]`）
  - `map/spot/output/flow` 字段当前基本为空（数据都写在 descriptions 里）
- 规模：20 张卡片，引用约百余处，解析后可得到步骤与引用清单

### 2.2 搞事系统物品浮窗（复用点）
| 功能 | 现有实现 |
|------|---------|
| 浮窗构建 | `lbOpenSpeciesPicker()`（物种 / 物品双 TAB） |
| 物品项渲染 | `lbPickerItemHtml(kind, base, cls, cnt)`（图标 / 中文名 / 数量/品质行 / 英文名） |
| 点击选择 | `lbPickerSelect(el)`（`data-cls="item:<kind>:<base>"` 或物种类名） |
| 物品数据 | `LB_ITEM_ZH`（`汉化/item_zh.json`，zh/en/icon/kind/alias） |
| 元数据解析 | `lbItemMeta(cls)` → `{base, zh, en, icon, kind}`（含别名/设施表回退） |
| 图标 URL | `lbItemIconUrl(cls)` |
| 物种名 / 图标 | `lbSpName(k)` / `lbIconForDinoClass(k)` |

### 2.3 玩家身份与存储
| 层 | 现有机制 |
|----|---------|
| 登录 | `dinoAuth`（`user` / `nick` / `at`），后端 `POST /api/login` 校验 accounts.json |
| 玩家级标识 | `dinoAuth.user`（登录账号）、`LB.playerEos`（eosId） |
| 角色级标识 | `LB.playerRoles` / `lbCurPid`（**本方案不使用**） |
| 后端存储 | `D:\dino_backend\accounts.json`（线程锁 + .bak + 原子替换），尚无通用用户数据接口 |

## 3. 数据模型

### 3.1 玩家流程文档（`harvestFlowDoc`）

```json
{
  "version": 1,
  "owner": "<登录账号>",
  "updatedAt": 1792330000000,
  "cards": [
    {
      "id": "hf_<随机>",
      "title": "野外（石头）",
      "map": "Isl",
      "spot": "石头富集区",
      "outputs": ["Stone"],
      "order": 0,
      "steps": [
        {
          "text": "带[跳蛛][星尾兽]和吃喝、低温冰箱、电池",
          "note": "",
          "refs": [
            {"type": "species", "key": "Bloodstalker"},
            {"type": "species", "key": "Ankylo"},
            {"type": "item", "key": "Fridge"}
          ]
        }
      ],
      "builtin": false,
      "updatedAt": 1792330000000
    }
  ]
}
```

- `outputs`：产出物品 base 数组，是**物品索引主键**（角标与面板入口都靠它）
- `steps[].refs`：持久化引用键；`text` 中的 `[中文名]` 只是展示语法，渲染以 refs 为准，避免同中文名多键歧义
- `map`：服务器 ID（Isl/Sco/...），可空；仅作展示与筛选，不做权限限制
- `builtin`：标记来自内置模板（导入后复制为新卡片，`builtin=false`）

### 3.2 运行时索引

```
LB._flowDoc     // 当前玩家文档（内存）
LB._flowIdx     // { outputBase: [cardId, ...] }，加载/保存后重建
LB._flowsByItem(base) -> card[]
```

物品浮窗渲染时 O(1) 查询；文档变更后仅重建索引并触发当前浮窗重绘。

## 4. 存储设计（玩家级）

### 4.1 后端新增接口（`独立后端/dino_backend.py`）

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/harvest_flows?username=xxx` | 返回该玩家文档；不存在返回 `{ok:true, doc:null}` |
| POST | `/api/harvest_flows` | body `{username, doc}`，校验后落盘 |

落盘规则：
- 路径：`D:\dino_backend\userdata\harvest_flows_<username>.json`
- 机制复用 `_save_accounts`：线程锁 + `.bak` 备份 + `.tmp` 原子替换
- `username` 必须存在于 `accounts.json`（防乱写)；未登录的匿名数据不落服务端
- 数据非敏感；接口无会话令牌（与现有接口一致的信任模型），后续可平滑加 token

### 4.2 前端缓存与同步

- 本地键：`localStorage['harvestFlows_<user>']`（`user` 无登录时为 `guest`）
- 加载顺序：本地立即渲染 → 登录态下 GET 云端 → 云端较新则覆盖并重建索引
- 保存顺序：先写本地（即时生效）→ POST 云端；失败提示「已存本地，云端同步失败」，下次登录重试
- 身份切换：
  - 换账号（`dinoAuth.user` 变化）→ 重新加载对应文档
  - 切换角色（`lbCurPid` 变化）→ **不重载**
- 未登录：可用（guest 本地存储），面板顶部提示「登录后可云同步」

## 5. 交互设计

### 5.1 物品浮窗入口（需求 2 / 3）

- 入口位置：选中物品后，底部繁育栏 `#lbBreedBar`（与物种模式同款功能条）右侧按钮组 `#lbBreedActions`
- 按钮组规则：
  - 每个采集流程 = 一个按钮：`地图专属图标 + 流程标题`（标题自由配置）
  - 无流程时显示一个「新建流程」按钮（点击进入新建）
  - 品类准入：仅「其它」分组中的「资源」(kind=resource) 与「消耗品」(kind=consumable) 允许新建流程
  - 非准入分类（护甲 / 武器 / 工具 / 弹药 / 建筑 / 食用卵 / 战利品 / 染料等）一律隐藏新建按钮与流程按钮，角标同时隐藏（用户确认）
  - 品类判定：`lbItemMeta(base).kind`；kind 缺失/未知按非准入处理
  - 有流程时按 `order` 排序，「+」新增按钮固定在第一个流程按钮之前
  - 移动端允许换行（沿用 `#lbBreedBar > div{flex-wrap:wrap}`）
  - 功能条显隐：仅当存在可见按钮时显示（新建流程 / 流程按钮 / 装备榜任一）；全部不可见则整条隐藏（沿用 v4231「空条不显示」，判定范围纳入流程与新建按钮）
- 地图图标：按流程 `map` 字段取服务器 MDI 图标（Isl=mdi:island / Sco=mdi:volcano / Cen=mdi:diamond-stone / Abe=mdi:radioactive / Ext=mdi:meteor / Ast=mdi:star-four-points / Rag=mdi:lighthouse-on / Val=mdi:forest / Bob=mdi:party-popper / Los=mdi:castle / Gen=mdi:dna）；未设地图 → mdi:map-marker
- 图标渲染走现有 `lbMdiSvg(name, 13)`，与同栏按钮一致
- 物品项角标：保留，仅标识不可点击（用户已确认）；主网格 / 最近栏 / 搜索 / 折叠区统一
- 点击流程按钮 → 打开该流程详情（查看）；「+」或详情内「编辑」→ 编辑器
- 面板打开对象：当前物品（`{kind, base}`）+ 被点流程卡片

### 5.2 采集流程面板（查看）

```
┌ 物品图标 + 中文名 + 英文名（来自 lbItemMeta）────────────┐
│ 流程卡片 1：标题 / 地图 / 采集点 / 步骤预览（前 3 行）      │
│ 流程卡片 2：…                                             │
│ [+ 新建流程] [编辑] [复制] [删除]        [查看全部流程]      │
└──────────────────────────────────────────────────────────┘
```

- 卡片列表按 `updatedAt` 倒序
- 点击卡片进入编辑器
- 「查看全部流程」：全屏列表（可按地图/关键词筛选），后续可扩展

### 5.3 流程编辑器（需求 4）

| 区域 | 控件 |
|------|------|
| 基本信息 | 标题（input）、地图（select：全部服务器 + 空）、采集点（input）、产出物品（标签，可增删） |
| 步骤列表 | 每行：步骤文本 + 引用 chips；行操作：上移 / 下移 / 删除；支持备注行 |
| 插入引用 | 「+ 物品/生物」按钮 → `lbOpenSpeciesPicker({onPick})`，选中后插入 `[中文名]` 并写入 refs |
| 保存 | 本地 + 云端；离开前提示未保存更改 |

- 步骤文本自由编辑；`[中文名]` 手动输入也允许，保存时尝试解析为 refs
- 产出物品选择同样走现有浮窗（物品 TAB）
- 编辑器内引用 chip 显示：图标 + 中文名 + 英文名（与物品浮窗一致）

### 5.4 浮窗复用（需求 5）

- `lbOpenSpeciesPicker(opts)` 新增可选参数：
  - `opts.onPick({kind, base})`：选择后回调，**不执行 `lbView()`**，不关闭编辑上下文
  - `opts.title`：自定义搜索占位符（可选）
- `lbPickerSelect()` 增加回调分支：存在 `LB._pickHook` 时先回调再关闭浮窗，默认行为不变
- 引用解析/渲染统一函数：
  - `lbHarvestRefMeta(ref)`：返回 `{iconUrl, zh, en}`（物种走 `lbSpName`/`lbIconForDinoClass`，物品走 `lbItemMeta`/`lbItemIconUrl`）
  - 渲染与 `lbPickerItemHtml` 同源，保证图标、中英文完全一致

## 6. 内置模板（迁移现有 20 张卡片）

- 一次性脚本 `tmp/_cf_migrate_defaults.py`：
  - 读取 `data/tribe_ops.json` → `efficient_farming`
  - descriptions 行 → steps：`^` → 编号步骤，`*` → 备注，其余 → 普通步骤
  - `[中文名]` → refs：先按 `item_zh` 中文名精确匹配，再按物种名表匹配；匹配失败保留纯文本（不阻塞迁移）
  - `outputs` 推断：标题命中物品名 → 绑定该物品；否则取引用中的产出物品（如「野外」卡片 → `Stone`）；推断结果在模板中可人工校正
  - 输出 `harvest_flows_default.json`（CF 静态资产，随部署打包）
- 导入策略（待用户选定，默认推荐 A）：
  - A. 模板只读展示，用户点「导入为我的流程」后复制成可编辑卡片
  - B. 首次使用自动把模板复制进玩家文档
- 原页面保留：ASA 后台「采集速查」继续可查（双轨），后续稳定后再评估下线

## 10. 风险与规避

| 风险 | 规避 |
|------|------|
| 物品 base 归一/别名导致索引错位 | 统一用 `lbCanonBase()` 建索引；引用持久化 key 而非中文名 |
| 同中文名多键（如 Horn/The Horn） | 保存 refs key；迁移时按 en 归一去重 |
| 后端无鉴权 | 仅存非敏感数据；username 白名单校验；后续可加 token |
| 并发写文件 | 线程锁 + `.bak` + 原子替换（复用 accounts.json 机制） |
| PWA 缓存旧版 | 递增 `LB_VERSION`，必要时同步 `pwa/sw.js` CACHE |
| 大文件编辑风险 | 用 `_replace.py` 脚本替换 + 语法预检 + 部署后浏览器验证 |
