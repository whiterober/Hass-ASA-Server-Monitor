- 日期：2026-11-08（v2 修订：MOD 名称取法、MOD 生效机制、插件 DLL 分发落地设计）

## 零、v1 → v2 的关键修正（全部为本次实测证据）

| # | v1 的错误假设 | v2 实测真相 | 证据 |
|---|---|---|---|
| 1 | MOD 名称靠本地映射表 / CurseForge | **可从服务器启动日志直接提取**（`Mod valid: <名称> (<id>)`） | Cen/Ast/Ext/Gen 日志实测 |
| 2 | 改 `GameUserSettings.ini` 的 `ActiveMods` 即可分发 MOD | **不生效**：ASAM 用**命令行 `-mods=`** 启动，不读 ini | ini mtime `2026-11-03 20:12:10` 内容 `ActiveMods=983782`；ASAM 于 `2026-11-08 02:24:27` 用 `-mods=877752` 启动 |
| 3 | MOD 文件在本机能找到（paks/mods 目录） | `Content\Paks` 只有 `pakchunk2~11`，**无 Mods 子目录**，无法从文件反查 ID | 目录实测 |
| 4 | ASAM 有 mods 编辑 API | ASAM Web API 只有 `config / destroy / fullbackup / kill / rcon / saveworld / start / stop / update`，**无 mods 端点** | `D:\ASADedicatedManager\ui.html` 端点提取 |
| 5 | 插件只需覆盖 dll | 每插件是**一组文件**（dll + PluginInfo.json + 可选 config.json），且目标服必须先停服 | 插件目录实测 |

## 一、MOD 名称怎么取（已定，无需外网）

### 1.1 唯一可靠来源：服务器启动日志

**路径**
```
\\SERVER\ARK Server\Servers\<srv>\ShooterGame\Saved\Logs\ShooterGame.log
```

**实测原文**（Cen / Ast / Ext / Gen 四台一致）：
```
LogCFCore: No need to update existing mod: Fear Ascended (877752)
LogCFCore: Mod valid: Fear Ascended (877752)
UShooterEngine::LoadGameMods with 1 mods
UShooterEngine::LoadGameMods no primal game data found for mod Fear Ascended : 877752
```
⇒ 名称与 ID 成对出现，格式稳定。

**提取规则**（三条正则，命中任一即可）：
```python
_PAT_MOD_NAME = [
    r'No need to update existing mod:\s*(.+?)\s*\((\d{5,})\)',
    r'Mod valid:\s*(.+?)\s*\((\d{5,})\)',
    r'LoadGameMods.*?for mod\s+(.+?)\s*:\s*(\d{5,})',
]
```

**聚合策略**
1. 逐台读日志**尾部**（取最后 2000 行，避免 3~5 MB 全读）
2. 提取 `{id: name}` 对，跨 11 台合并（同名多发以最后出现为准）
3. 落盘 `\\SERVER\ARK Server\DinoData\mod_names.json`（**自动学习缓存**）：
   ```json
   { "877752": { "name": "Fear Ascended", "src": "log", "at": "2026-11-08 02:24" } }
   ```
4. 人工可在同文件加 `"src":"manual"` 覆盖日志结果（manual 优先）
5. 都取不到 → 卡片显示 `MOD <id>` + 灰字「名称未学得（该服日志无加载记录）」

**为什么不用 CurseForge / ASAM**
- CurseForge 需 API Key + 外网可达；本项目公网链路已多次抖动
- ASAM 的 mod 列表不进 HTTP（见 §零.4）
- 日志方式**零外部依赖、零凭据、含真实加载结果**（比「配置里写了什么」更有价值）

### 1.2 顺带能诊断的问题（这是卡片的核心价值）

| 诊断项 | 数据来源 | 判定 |
|---|---|---|
| **配置 ≠ 实际加载** | ini `ActiveMods` vs 日志 `-mods=`/`LoadGameMods` | 不一致 → 红色告警（**当前就中招：983782 vs 877752**） |
| 各服 mods 不一致 | 各服日志 | 列出差异服 |
| mod 加载失败 | 日志 `no primal game data found for mod` | 黄色告警 |
| mod 更新失败 | 日志 `Error querying server mods: ApiError` | 灰字提示（实为网络不可达） |

## 二、MOD 的生效机制与分发路径（结论：不可自动化）

### 2.1 生效链（实测）

```
ASAM（ASADedicatedManager.exe v3.8.2.5）
  │  自己的 profile 里存 mods 列表
  ↓ 拼启动命令行
AsaApiLoader.exe "<Map>_WP"?SessionName=... -mods=877752 -ServerPlatform=PC ...
  ↓
游戏按 -mods= 从 CurseForge 下载并加载
```

**不是**：
```
GameUserSettings.ini 的 [ServerSettings] ActiveMods=...   ← 当前值 983782，从未生效
```

### 2.2 ASAM 的 profile 存放位置（已排查，未找到 mods 字段）

| 位置 | 内容 | 有 mods 吗 |
|---|---|---|
| `C:\Users\Administrator\AppData\Roaming\ASADedicatedManager\profils.json` | 11 条 `{Name, ServerPath, IsSelected}` | **无** |
| 同上 `config.json` | `{ListeningUrl:"http://+:5050/", Port:5050, ListenExternally:true}` | 无 |
| 同上 `SavedTab.json` | 仅 UI 页签 | 无 |
| `D:\ASADedicatedManager\` 程序目录 | exe + dll + `ui.html` + 模板 | **无 Profiles 目录** |

⇒ ASAM 的 mods 配置在**桌面 WPF UI 的私有存储**里（未暴露为可编辑文件/API）。

### 2.3 结论与卡片定位

**MOD 分发不做**（三条路都不通）：
1. 改 ini → 不生效（已实测）
2. 调 ASAM API → 无端点
3. 直接改 ASAM 私有存储 → 格式未知，改错会毁 ASAM 配置

**MOD 卡片定位改为「一致性诊断 + 引导」**：
- 展示：配置值（ini）/ 实际加载值（日志）/ 名称（日志学习）/ 各服差异 / 加载异常
- 不一致时给**明确操作指引**：「请到 ASAM 桌面端 → 服务器设置 → Mods 修改后重启」，不提供本站按钮

> 若后续要求自动化，唯一可行路径：**改用本项目自己的启动器**（绕开 ASAM 托管启动），属架构级改动，另立方案。

## 三、API 插件：DLL 文件覆盖分发（本期落地）

### 3.1 目录与文件集（实测）

```
\\SERVER\ARK Server\Servers\<srv>\ShooterGame\Binaries\Win64\ArkApi\Plugins\<插件名>\
    <插件名>.dll          ← 必需，主程序
    PluginInfo.json       ← 必需，含 FullName / Description / Version / MinApiVersion
    config.json           ← 可选，服务器专属配置（**默认不覆盖**）
    config_help.json      ← 可选，说明文档（可覆盖）
    *.pdb                 ← 调试符号（**忽略**，AdvancedMessagesAscended.pdb 达 14 MB）
    *.db / *.db-wal       ← 运行时数据（**绝不覆盖**，如 Permissions\ArkDB.db-wal 2.3 MB）
```

API 本体：`...\ArkApi\AsaApi.dll`（7,308,288 B，mtime `2026-07-30 00:27`）—— 配套但**不在本期分发范围**（版本升级另立）。

### 3.2 分发规则

| 文件 | 规则 |
|---|---|
| `<名>.dll` | 覆盖（先备份） |
| `PluginInfo.json` | 覆盖（版本判定依据） |
| `config.json` | **目标不存在才复制**（保护各服独立配置） |
| `config_help.json` | 覆盖（纯文档） |
| `*.pdb` / `*.db*` / `*.lib` | **完全忽略** |

### 3.3 执行序列（每台目标服）

```
① 前置校验
   · 目标服 ArkApi\AsaApi.dll 存在？不存在 ⇒ 拒绝（该服未装 API 加载器）
   · 源服插件目录存在？不存在 ⇒ 拒绝
② 若目标服在运行 → 走既有 savekill（存档校验通过才停服）；失败则整台放弃
③ 备份：<名>.dll → <名>.dll.bak_<YYYYMMDD_HHMMSS>
④ 复制：dll + PluginInfo.json（+ config.json 若不存在）
⑤ 校验：md5(源) == md5(目标)，不符 ⇒ 回滚 .bak
⑥ 起服：仅当 **wasRunning=True**；原本停服的服保持停服（v6272 原则）
⑦ 汇总：每台一行结果进任务总线（action='plugin_deploy'）
```

### 3.4 复用现有能力（不新造轮子）

| 能力 | 复用 |
|---|---|
| 存档+停服 | `_srvctl_one(srv,'savekill',...)`（已有四重 .ark 校验） |
| 起服 | `_srvctl_startq_new('plugin', [srv])`（走重压池 + advertising 判定） |
| 是否原本在运行 | `_srvctl_proc_snapshot()` + `wasRunning` 判定（v6272 那套） |
| 任务条 | `_utask_put('plugin|%s', ..., action='plugin_deploy')` |
| 互斥 | `_batch_busy_probe()`（v6276）：批次互斥 |

### 3.5 新接口

```
GET  /api/plugins/status                       → 只读扫描（卡片数据）
POST /api/plugins/deploy                       → 分发（高危，需二级管理员 + 确认）
     body: {username, src:"Isl", names:["ExtendedRcon","ServerOpsKitAPI"], targets:["Bob"],
            dry:false, confirm:"DEPLOY"}
GET  /api/plugins/deploy/status?jobId=...      → 进度（或复用 /api/tasks）
```

### 3.6 安全约束

1. **必须停服**才能覆盖 DLL（进程占用 → 写失败），已内建「先 savekill」
2. **只允许 dll / PluginInfo.json / config_help.json** 三类扩展名（白名单）
3. **禁止**分发 `*.db*`（Permissions 的权限库各服独立，覆盖会串权）
4. 全部操作先备份 `.bak_<ts>`，md5 校验失败自动回滚
5. 目标服 `AsaApi.dll` 缺失 ⇒ 只告警、不自动安装加载器
6. `dry=true` 时只出计划不落地（沿用现有演练语义）

## 五、后端实现要点

| 函数 | 职责 | 缓存 |
|---|---|---|
| `_ini_active_mods(srv)` | 正则取 ini `ActiveMods`（不做完整 ini 解析） | 300 s（ini 极少变） |
| `_log_mod_pairs(srv)` | 读日志尾部 2000 行 → `{id: name}` + 加载错误行 | 120 s（按文件 mtime） |
| `_mod_names_load()/save()` | `DinoData\mod_names.json` 自动学习缓存（manual 优先） | 300 s |
| `_mods_status()` | 汇总 11 台 → configured / loaded / names / mismatch / loadErrors | 120 s |
| `_plugins_scan(srv)` | 列 `Plugins\*` 一级目录 → `PluginInfo.json` + `stat *.dll` | 120 s |
| `_plugins_status()` | 汇总并集 / 缺失 / 版本不一致 / 无 AsaApi | 120 s |
| `_plugin_deploy(src, names, targets, dry)` | 串行逐台：校验→savekill→备份→复制→md5→起服 | — |

实现纪律：
1. **每台独立 try/except**，单台失败写 `err[服]`，接口恒 200
2. 文件不存在 = 正常态（无该插件），不是错误
3. 日志读取**只读尾部 2000 行**（`collections.deque(f, maxlen=2000)`），不整文件读
4. 分发**串行**（一次一台），避免多台同时停服清空传送窗口
5. 所有写操作前先 `_batch_busy_probe()` 互斥；进行中占用 `_srv_lock` hard 锁

## 六、前端卡片

插入位置：`lb-upd-stack` 内、汉化包卡片**之后**（缓存 → 汉化 → **MOD** → **API 插件**）。

### 6.1 MOD 卡片（只读诊断）

```
🧩 MOD                                       配置 1 个 / 实际 1 个
配置（ini）：983782
实际加载：877752  Fear Ascended
⚠ 配置未被加载：983782 —— ASAM 用命令行 -mods= 启动，ini 的 ActiveMods 不生效，
   请到 ASAM 桌面端 → 服务器设置 → Mods 修改后重启
各服：11/11 台实际加载一致
```
- 一致（无 mismatch）时只显示两行：`启用：<id> <名称>`、`各服：11/11 台一致`
- 有 mismatch → 红色告警行 `#f87171`（因为这是「改了没生效」的典型坑）
- 加载错误 → 黄色 `#fbbf24`
- **不放「分发」勾选**、不放按钮（见 §二.3）

### 6.2 API 插件卡片（只读 + 分发入口）

```
🔌 API 插件                                     5 个
AsaApi：7.0 MB · 2026-07-30
插件：Advanced Messages Ascended 1.41 · Extended Rcon 0.1 ·
      Permissions 1.1 · Server Ops Kit 0.7 · Unicode Rcon 1.0
各服：Bob 缺 Extended Rcon、Server Ops Kit
────────────────────────────────
右下角：[分发插件 ▸]（点开选源服/插件/目标服，走确认卡）
```
- 插件项 `.lb-tipb` + `title` 显示 `Description` + `MinApiVersion`
- 缺失黄 `#fbbf24`，全一致绿 `#4ade80`
- 「分发插件」链接复用 `.lb-upd-link` 样式；无缺失时置灰

### 6.3 分发确认卡（复用 `lbAskCard`）

```
tone: danger
title: 分发 API 插件
badge: N 台
servers: [目标服...]
steps: ['校验 AsaApi', '存档并停服', '备份原 DLL', '覆盖文件', 'MD5 校验', '按原状态起服']
warn: 每台「原 DLL 备份为 .bak_时间戳；Permissions 权限库不会被覆盖」
```

### 6.4 样式纪律

- 卡片外壳复用 `_card` 变量，**不新增 CSS 类**（与现有两张卡片一致）
- 告警色沿用项目既有：红 `#f87171` / 黄 `#fbbf24` / 绿 `#4ade80` / 灰 `#9ca3af`
- **界面禁止 ✓ / ✗ 符号**，一律 MDI 图标（`mdi-check` / `mdi-alert-circle-outline`）

## 七、实施步骤

1. **后端只读部分**：`_mods_status()` + `_plugins_status()` + 两个 GET 路由 + 缓存
2. **后端自测**（部署前）：直接调函数打印 JSON，核对

4. **部署验证只读**（第一轮）：后端 + 前端

> 分三轮的目的是：先把「看得见」的部分交付（无风险），再上线「会改文件」的部分（有风险）。

## 九、风险与缓解

| 风险 | 缓解 |
|---|---|
| 覆盖 DLL 时进程仍占用 → 写失败 | 强制先 `savekill`（含 .ark 四重校验）才进入复制阶段 |
| 动作失误覆盖各服独立配置 | `config.json` 只在目标不存在时复制；`*.db*` 硬黑名单 |
| 多台同时停服清空传送窗口 | 分发**串行**，复用 `_kill_serial` 闸门 |
| 日志读取拖慢接口 | 只读尾部 2000 行 + mtime 缓存；11 台并发 |
| MOD「配置/实际」不一致被误当 bug | 文案明确指向 ASAM 托管启动的机制原因 + 操作指引 |
| 分发中途失败留下半套文件 | 每文件先备份、逐文件 md5、失败回滚并 `_srvctl_log` 留痕 |
