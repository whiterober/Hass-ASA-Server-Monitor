# 接口使用报告 — 恐龙突变数据查询（网页端对接版）

> **面向对象**：网页端（中转页）工作区开发者
> **生成日期**：2026-08-02
> **插件**：TransferIdentityFixAPI（版本 `0.2.0`）
> **传输方式**：纯 RCON 同步响应（无 HTTP、无文件交换、无存档读写）
> **对接依据**：本文档为唯一权威契约，以插件**实际已实现**的代码为准（已实服验证）

---

## 1. 接口总览

插件在服务器进程内注册以下 RCON 命令，网页端通过 **RCON 客户端**发送命令，插件在回调中**把结果作为 RCON 响应包同步回传**（JSON 或文本）。

| # | RCON 命令 | 类型 | 返回 | 用途 |
|---|-----------|------|------|------|
| 1 | `TransferIdentityFix.DinoMutPing` | JSON | `ok/plugin/version` | 健康检查 / 连通性测试 |
| 2 | `TransferIdentityFix.DinoMut <dino1> <dino2>` | JSON | 恐龙全量原始数据 | **核心接口**：查指定龙逐属性数据 |
| 3 | `TransferIdentityFix.Ping` | 文本 | `pong` | 连通性测试（旧） |
| 4 | `TransferIdentityFix.Status [player]` | 文本 | 身份链快照 | 诊断（旧） |
| 5 | `TransferIdentityFix.Reconnect` | 文本 | 重连恢复 | 运维（旧） |
| 6 | `TransferIdentityFix.ReconnectTarget` | 文本 | 设置重连目标 | 运维（旧） |
| 7 | `TransferIdentityFix.ReloadConfig` | 文本 | 重载配置 | 运维（旧） |
| 8 | `TransferIdentityFix.CurrentMap` | 文本 | 当前地图 | 运维（旧） |
| 9 | `TransferIdentityFix.DebugChat on\|off` | 文本 | 开关聊天回显 | 运维（旧） |
| 10 | `TransferIdentityFix.Trace <message>` | 文本 | 记录 MOD_TRACE | 运维（旧） |

> 🔴 **网页端对接只需关注 #1 和 #2**（JSON 接口）。#3~#10 为诊断/运维文本命令，格式不稳定，不建议依赖。

### 传输链路

```
网页端（本地中转页）
   │  ① 标准 RCON 客户端发命令（SERVERDATA_EXECCOMMAND）
   ▼
插件（服务器，进程内）
   │  ② 命令回调：GetDinoCharacterByID 查龙（内存对象，不读存档）
   │  ③ SendMessageW(request_id, 0, &JSON) 回传
   ▼
网页端  ④ RCON 客户端同步收到响应正文 = JSON 结果
```

## 3. 接口 2：突变查询 `DinoMut`（核心）

### 请求

```
TransferIdentityFix.DinoMut <dino1> <dino2>
```

- `<dino1>` / `<dino2>`：恐龙 DinoID 的两段数字（对应 `.ini` 导出中的 `DinoID1` / `DinoID2`）。
- 示例：`TransferIdentityFix.DinoMut 397174429 187449547`

### 成功响应（JSON，`found:true`）

```json
{
  "requestId": "dinomut_1785638400123",
  "dinoId": "397174429_187449547",
  "found": true,
  "statPoints": {
    "health": 45, "stamina": 12, "torpidity": 5, "oxygen": 6,
    "food": 20, "water": 3, "temperature": 0, "weight": 18,
    "meleeDamage": 52, "movementSpeed": 14, "fortitude": 0, "craftingSpeed": 0
  },
  "statMutations": {
    "health": 10, "stamina": 0, "torpidity": 0, "oxygen": 0,
    "food": 0, "water": 0, "temperature": 0, "weight": 0,
    "meleeDamage": 4, "movementSpeed": 0, "fortitude": 0, "craftingSpeed": 0
  },
  "statValues": {
    "health": 52300, "stamina": 1200, "torpidity": 90, "oxygen": 750,
    "food": 9300, "water": 600, "temperature": 50, "weight": 850,
    "meleeDamage": 320, "movementSpeed": 100, "fortitude": 0, "craftingSpeed": 0
  },
  "randomMutations": { "male": 3, "female": 4 },
  "ancestors": [
    { "maleId": "100_200", "femaleId": "300_400" },
    { "maleId": "500_600", "femaleId": "700_800" }
  ],
  "error": null
}
```

> 上方数值为**示意**，实服已对真实熊验证：`statMutations.health=10`、`statMutations.meleeDamage=4`，为逐属性精确突变次数。

### 字段说明（网页端对接必读）

| 字段 | 类型 | 说明 |
|------|------|------|
| `requestId` | string | 本次请求唯一 ID（`dinomut_` + 毫秒时间戳），用于对账/并发区分 |
| `dinoId` | string | `"<dino1>_<dino2>"` 格式，回显请求参数 |
| `found` | bool | `true`=找到该龙 |
| `statPoints` | object | **每属性已应用点数**（野生点 + 突变点混入，不可逆）；键为属性名，见 §4 索引表 |
| `statMutations` | object | **每属性已应用突变次数**（⭐ 网页端直接取此字段填 Wikily 突变芯片） |
| `statValues` | object | 每属性**当前实际数值**（已四舍五入为整数） |
| `randomMutations` | object | 累计突变计数器：`male` / `female`（RandomMutationsMale/Female，非逐属性） |
| `ancestors` | array | **谱系链**：从父母到祖父母，每项 `{maleId:"父", femaleId:"母"}`（DinoID 两段拼接为字符串） |
| `error` | string/null | 成功为 `null` |

> 💡 **核心用法**：网页端只需 `statMutations` 即可拿到**逐属性精确突变次数**（实服验证可直接读，无需子代-父母对比计算）。`ancestors` 用于谱系展示；`randomMutations` 用于与 `.ini` 的 `RandomMutationsMale/Female` 对账。

### 错误响应（JSON，`found:false`）

| 场景 | 响应 |
|------|------|
| 缺少参数 | `{"requestId":"dinomut_...","dinoId":"","found":false,"error":"missing dino1/dino2"}` |
| 参数非数字 | `{"requestId":"dinomut_...","dinoId":"","found":false,"error":"invalid dino id"}` |
| 世界未就绪 | `{"requestId":"dinomut_...","dinoId":"<d1>_<d2>","found":false,"error":"world not ready"}` |
| 龙未找到 | `{"requestId":"dinomut_...","dinoId":"<d1>_<d2>","found":false,"error":"dino not found"}` |

> ⚠️ **`dino not found` 是常态**：该龙必须是**当前地图世界中存在的活龙**。已死亡、已释放、封存在低温仓、在别的图/服务器上的龙查不到。

### 网页端判定逻辑建议

```
if 收到响应 JSON 且 found == true:
    取 statMutations 填突变芯片（逐属性）
    可选：用 ancestors 展示谱系、randomMutations 对账
elif found == false:
    按 error 分支处理：
      "dino not found"      -> 龙不在世界，提示玩家先释放/确认在本地图
      "world not ready"     -> 服务器加载中，稍后重试
      "missing/invalid"     -> 参数错误（bug）
      "invalid dino id"     -> DinoID 解析失败
else:
    超时（建议 5s）-> 降级手动输入，不阻塞导入
```

## 5. RCON 连接参数与权限

### 连接参数（网页端需配置）

| 参数 | 值（实服示例） | 说明 |
|------|----------------|------|
| 地址 | `work.whiterober.cn` | 服务器 IP / 域名 |
| 端口 | `32321` | 服务器 `-RCONPort=32321` |
| 密码 | RCON 密码 | `RCONClientConnection::IsAuthenticated` 认证，未认证不响应 |

### 权限模型

- **通道级**：RCON 本身需密码认证（`IsAuthenticated`）。
- **命令级**：`DinoMut` / `DinoMutPing` 回调内校验 `tif.operator` 权限（复用 `HasPermission`）。
- **无文件权限问题**：全程无文件输出。

### 协议细节（RCON 标准）

| 方向 | 包类型 | 说明 |
|------|--------|------|
| 网页端 → 插件 | `SERVERDATA_EXECCOMMAND`（Type=2） | 携带命令字符串 |
| 插件 → 网页端 | `SERVERDATA_RESPONSE_VALUE`（Type=0） | **响应正文即 JSON**，请求 ID 回显 |

> ⚠️ 插件回传**回显请求 ID**（Type=0）。这是实服传图崩溃修复的关键，网页端无需特殊处理，标准 RCON 客户端天然匹配。

## 6. 调用示例（Python RCON 客户端）

> 以下为标准 RCON 协议同步实现，网页端/中转页可直接参考。

```python
import socket
import struct
import json


def _read_packet(sock):
    """读取一个 RCON 包: (id, type, body)"""
    header = b""
    while len(header) < 4:
        chunk = sock.recv(4 - len(header))
        if not chunk:
            raise ConnectionError("RCON 连接被关闭")
        header += chunk
    (size,) = struct.unpack("<i", header)
    payload = b""
    while len(payload) < size:
        chunk = sock.recv(size - len(payload))
        if not chunk:
            raise ConnectionError("RCON 连接被关闭")
        payload += chunk
    pkt_id, pkt_type = struct.unpack("<ii", payload[:8])
    body = payload[8:-2]  # 去掉结尾 \x00\x00
    return pkt_id, pkt_type, body.decode("utf-8", errors="replace")


def rcon_command(host, port, password, command, timeout=5.0):
    """发送 RCON 命令并同步取回服务器响应正文（即插件 JSON）。"""
    sock = socket.create_connection((host, port), timeout=timeout)
    try:
        # 1) 认证 SERVERDATA_AUTH (type=3)
        auth_body = password.encode("utf-8") + b"\x00\x00"
        sock.sendall(struct.pack("<ii", 10 + len(password), 1) + struct.pack("<i", 3) + auth_body)
        resp_id, resp_type, _ = _read_packet(sock)
        if resp_id != 1 or resp_type != 2:
            raise PermissionError("RCON 认证失败（密码错误）")

        # 2) 发命令 SERVERDATA_EXECCOMMAND (type=2)
        req_id = 2
        cmd_bytes = command.encode("utf-8") + b"\x00\x00"
        sock.sendall(struct.pack("<ii", 10 + len(command), req_id) + struct.pack("<i", 2) + cmd_bytes)

        # 3) 循环读响应，直到拿到回显 req_id 的 Type=0 响应（插件回传 JSON）
        responses = []
        while True:
            rid, rtype, body = _read_packet(sock)
            if rtype == 0 and body:
                responses.append(body)
                if rid == req_id:  # 插件回显请求 ID
                    break
        return responses[-1]
    finally:
        sock.close()


# ---- 用法 ----
HOST, PORT, PASS = "work.whiterober.cn", 32321, "你的RCON密码"

# 健康检查
ping = rcon_command(HOST, PORT, PASS, "TransferIdentityFix.DinoMutPing")
print(ping)  # {"ok":true,"plugin":"TransferIdentityFixAPI","version":"0.2.0"}

# 突变查询
raw = rcon_command(HOST, PORT, PASS, "TransferIdentityFix.DinoMut 397174429 187449547")
data = json.loads(raw)
if data.get("found"):
    print(data["statMutations"])   # {"health":10, ..., "meleeDamage":4, ...}
    print(data["ancestors"])
else:
    print("未找到:", data.get("error"))
```

## 7. 与需求文档 §5 契约的差异说明（网页端注意）

需求文档 `计划/API需求_恐龙突变查询与改名.md` §5 与**实际实现**存在以下差异，网页端以此文档为准：

| 项 | 需求文档 §5 设想 | 实际实现 | 网页端影响 |
|----|------------------|----------|------------|
| 返回结构 | 插件直接算好 `mutations` 对象 | 插件返回**全量原始数据**（`statPoints/statMutations/statValues/ancestors`） | 网页端直接读 `statMutations`，无需自行对比计算 |
| 逐属性突变来源 | "子代-父母逐属性对比"推断 | **引擎直接给出** `NumberOfMutationsAppliedTamed`（实服验证精确：熊 health:10 / meleeDamage:4） | 更准更省：不用查父母算突变 |
| `ancestors` | 仅父母（motherId/fatherId） | **全谱系数组**（父母+祖父母，每项 `maleId/femaleId`） | 展示用，可忽略 |
| 错误码 | 简化 | 4 种明确错误（见 §3） | 按 error 分支处理 |
| 属性等级/分布 | 本地计算 | 本地计算（**未改变**，插件不返回等级） | 维持现状 |

> 🔴 **最核心差异**：突变查询**已由服务器直出精确值**，网页端不必再实现"子代-父母对比"推断算法——直接从 `statMutations` 取值填入 Wikily 突变芯片即可。这同时满足「减轻服务端压力」（只查 1 只龙，不递归查父母）与「精确突变」两个目标。

## 8. 已知限制（务必知悉）

1. **只能查世界中存在的活龙**：`DinoMut` 基于 `GetDinoCharacterByID` 内存对象查询。**封存在低温仓 / 已释放 / 已死亡 / 其他地图的龙查不到**（返回 `dino not found`）。
2. **低温冰箱批量查询不可行**：SDK 无 `APrimalStructureCryoFridge` 类，低温仓物品数据为**序列化字节**（`FCustomItemData::CustomDataBytes`），无反序列化接口。封存龙不是世界活对象，无法读取属性。→ 若需查冰箱里的龙，**必须先释放为活龙**再逐个 `DinoMut`。
3. **触发面**：按需求约定，仅对 `C>0` 的龙调用（`C=0` 已隐藏突变模块），避免无效请求。
4. **无 HTTP**：插件无入站 HTTP 端点，**只能走 RCON**。
5. **无存档读写**：全程内存对象查询，不写存档、不读存档文件。
