## 2. MOD 卡

### 2.1 真实目录结构（实测）

```
<ServerPath>\ShooterGame\Binaries\Win64\ShooterGame\Mods\
└── 83374/                        ← CurseForge gameId（ARK: Survival Ascended，固定）
    └── <ProjectId>_<FileId>/     ← 例 877752_9411569
        └── <ModRoot>/            ← UE 插件名，例 FearEvolved / BobsMissions
            ├── <ModRoot>.uplugin                     ← 权威元数据
            ├── Content/
            │   ├── Movies/LoadingScreen.bk2          ← 709 MB（占 99%）
            │   └── Paks/WindowsServer/*.pak|.ucas|.utoc
            ├── Manifest_NonUFSFiles_Win64.txt
            ├── Manifest_UFSFiles_Win64.txt
            └── Preview/
                ├── mod_settings.ini                  ← mod 自身设置
                ├── diff.txt / diffOffset.txt
                ├── entry_map.txt / dependencies.txt  ← 仅部分 mod 有
                └── preview_image.png
```

### 2.2 权威元数据来源

**磁盘扫描（唯一判定源）**，`Profile\modInfos.json` 只作补充展示。

实测 `modInfos.json` 已全面滞后：
| 服 | modInfos 登记 | 磁盘实际 |
|---|---|---|
| 10 服 | `877752_9349437` | `877752_9349440` / `877752_9411569` |
| Bob | `1005639_6719213` | `1005639_9418028` |

`.uplugin` 内可取：`FriendlyName`（mod 名）、`Description`（含 `cf_ugcID=<modId>`）、`MarketplaceURL`（CF 页）、`ExplicitlyLoaded`。

### 2.3 卡片内容

| 行 | 内容 | 数据来源 |
|---|---|---|
| 汇总 | 已装 N 台 · 版本一致 M/G 组 · 总体积 X GB · 可回收 Y GB | 磁盘扫描聚合 |
| 每服行 | `<服>` `<FriendlyName>` `<ProjectId>_<FileId>` `<大小>` `<mtime>` | 磁盘 + uplugin |
| 分叉告警 | 不同 FileId 的服分组高亮（旧组/新组/异组） | 按 FileId 分组 |
| 缺失 | 该服 Mods 目录不存在 / 目录为空 | 磁盘 |
| 空间建议 | `LoadingScreen.bk2` 可硬链接共享，预计回收 Z GB | 同名同大小同 hash |

当前实测快照（供 UI 校对）：

| 组 | FileId 目录 | 服 | 单服大小 |
|---|---|---|---|
| 旧 | `877752_9349440` | Abe, Isl, Los, Rag, Sco, Val（6） | 714.4 MB |
| 新 | `877752_9411569` | Ast, Cen, Ext, Gen（4） | 714.6 MB |
| 异 | `1005639_9418028` | Bob（1，Club ARK / BobsMissions） | 125.4 MB |

合计 **7.10 GB**；`LoadingScreen.bk2`（743,597,116 B）在 11 台服中 **11 份重复**，硬链接后可回收约 **7.09 GB**。

### 2.4 一致性判定（实测背书）

- 旧 6 服：10/10 文件**字节级完全一致**（含大文件按大小+hash 抽样）
- 新 4 服：10/10 文件**字节级完全一致**
- 新旧组之间：`LoadingScreen.bk2`、`preview_image.png`、`mod_settings.ini`、`diff.txt` **相同**；仅 `.uplugin`、`Manifest_*`、pak 不同

→ 结论：**同 FileId 组内可安全共享/硬链接；跨 FileId 不可**。

### 2.5 下载 / 分发（Round 2 能力）

- 下载源（两条路，二选一）：
  - ASAM 同款直链：`https://www.curseforge.com/ark-survival-ascended/mods/{slug}/download/{fileId}`
  - 官方 API：`https://api.curseforge.com/v1/mods/{modId}/files/{fileId}/download-url`（需自备 CF key）
- 下载一次 → 落到共享缓存 `\\SERVER\ARK Server\_mod_cache\83374\<pid>_<fid>\`
- 分发到各服 `...\Win64\ShooterGame\Mods\83374\<pid>_<fid>\<ModRoot>\`

分发白名单（覆盖）：
- `<ModRoot>.uplugin`
- `Content/**`（pak/ucas/utoc/bk2）
- `Manifest_NonUFSFiles_Win64.txt`、`Manifest_UFSFiles_Win64.txt`

分发**默认不覆盖**（各服可能有本地设置）：
- `Preview\mod_settings.ini`

禁止：
- 跨 FileId 目录名覆盖（必须先删旧目录，避免新旧文件混装）
- 服务器启动中替换 pak（需先停服/`stop`）

体积优化（推荐，低风险）：
- `Content\Movies\LoadingScreen.bk2` 用**硬链接**指向共享缓存中的同一份（同卷 NTFS 支持；实测各服该文件完全相同）
- pak/ucas/utoc 体积小（< 1 MB），直接复制即可

### 2.6 现状风险（需在卡片上提示）

- 新旧 FileId 混跑：旧 6 服 `9349440` / 新 4 服 `9411569`，客户端跨服可能提示 mod 版本不一致
- `ShooterGame.log` 记录 `LogCFCore: Error querying server mods: ApiError: Failed (serverUnreachable)` → 服务端无法向 CF 查询 mod 更新（出网受限），因此**无法依赖游戏自更新**，必须由我们主动推送新版本

## 3. API 卡（库 + 插件，一张卡两段）

### 3.1 卡片结构

```
.lb-upd-api
├── 顶部汇总：库一致 11/11 · 插件缺失 1 台（Bob 缺 2 个）· 缓存 47.6 MB/服
├── 段 A：ASA: Server API（库）
│   ├── AsaApi.dll 版本/大小/mtime · 全服是否一致
│   ├── Loader · config.json（AutomaticCacheDownload 源）
│   └── ArkApi\Cache 体积 · generations 分代
└── 段 B：插件
    ├── 插件矩阵（行=插件，列=11 服，标出缺失/版本不一）
    └── 展开：单服单插件的 dll 版本 / 目录成分 / 危险文件提示
```

### 3.2 段 A · ASA: Server API（库）实测基线

| 文件（相对 `Binaries\Win64`） | 大小 | mtime | 全服一致 |
|---|---|---|---|
| `ArkApi\AsaApi.dll` | 7,308,288 | 2026-07-30 00:27 | ✅ 11/11 一致 |
| `AsaApiLoader.exe` | 331,264 | 2023-11-28 19:40 | ✅ 11/11 一致 |
| `ArkApi\AsaApi.pdb` | 52,678,656 | — | — |
| `Lib\AsaApi.lib` | 122,422 | — | — |
| `ArkApi\pdbignores.txt` | 975 | — | — |
| `config.json` | 687 | — | ✅ 全服均有 |

安装清单由 ASAM 记录在每服 `API_File_Installation.txt`（可作为「应装文件」参照）。

**库的自维护机制**（`Win64\config.json`）：
```json
"AutomaticCacheDownload": {
  "Enable": true,
  "DownloadCacheURLs": [
    "https://cdn.pelayori.com/cache/",
    "https://cdn.shadowhunter.co.za/cache/",
    "https://cdn.shadowhunter-systems.co.za/cache/"
  ]
}
```
- 缓存落盘：`ArkApi\Cache\cached_offsets.cache` **47.6 MB**、`cached_offsets.txt` 40.1 MB、`cached_bitfields.cache` 961 KB、`cached_key.cache` 262 B
- 分代目录：`Cache\generations\<sha256>-57340-9793308281-0\`（57340 = ASA build；2026-11-03 20:15 更新）
- **含义**：库版本必须与 ASA 服务端 build 匹配；ASA 更新后缓存会分代重建，插件若 `MinApiVersion` 不达标会加载失败

**卡面判定**：
- 正常 = 11 服 `AsaApi.dll` 的 size+mtime+hash 三者全同
- 异常 = 任一台不同 → 标红「库版本分叉」（当前无此问题）

**禁止**：覆盖 `config.json`（含 CDN 源与插件重载策略）、覆盖 `Cache\**`（各服 build 可能不同）

### 3.3 段 B · 插件实测基线

| 插件 | PluginInfo.Version | dll 大小 | dll mtime | MinApiVersion | 装有该插件的服 |
|---|---|---|---|---|---|
| Permissions | 1.1 | 5,099,008 | 2025-07-30 | — | 11/11 |
| AdvancedMessagesAscended | 1.41 | 330,240 | 2026-07-24 | — | 11/11 |

**每插件目录成分不同（分发必须按插件定制白/黑名单）**：

| 插件 | 目录内容 |
|---|---|
| `Permissions\` | dll, pdb(17.6 MB), config.json, notes.txt, `ArkDB.db / -shm / -wal`（**每服独立数据 2.3 MB**）, `ONLY FOR DEVELOPERS/` |

## 4. 接口设计

| 路由 | 用途 | 返回要点 |
|---|---|---|
| `GET /api/mods/status` | MOD 卡数据 | `servers{<srv>:{gameId,pid,fid,root,name,size,mtime,files[]}}`、`groups{fid:[srv]}`、`totalBytes`、`reclaimableBytes` |
| `GET /api/api/status` | API 卡数据（库+插件） | `lib{srv:{dll,size,mtime,hash,consistent}}`、`cache{srv:{offsetsBytes,generation}}`、`plugins{name:{version,minApi,servers[],missing[]}}` |
| `POST /api/mods/link` | 硬链接复用 LoadingScreen | `confirm:"LINK"`，逐服 dry-run → 备份 → 建立链接 |
| `POST /api/mods/deploy` | 下发新 FileId | `confirm:"DEPLOY"`、`pid`、`fid`、`targets[]` |
| `POST /api/plugins/deploy` | 下发插件 dll | `confirm:"DEPLOY"`、`plugin`、`targets[]` |

统一 `srvctl` 权限守卫；写操作一律「先停服 → 备份 → 写 → md5 校验 → 起服（原本运行才起）」。

## 5. 分轮落地

### Round 1（只读，零风险）
- 后端：`_mods_status()`（磁盘扫描 `Mods\83374\*`，读 `.uplugin`，按 FileId 分组）、`_api_status()`（库一致性 + 插件矩阵）
- 路由：`/api/mods/status`、`/api/api/status`
- 前端：`.lb-upd-mods`、`.lb-upd-api` 两张卡，`lbUpdFetch()` 并行拉取
- 验收：MOD 卡显示 3 组（6/4/1）；API 卡显示库 11/11 一致 + Bob 缺 2 插件

### Round 2（空间回收，中风险）
- `LoadingScreen.bk2` 硬链接共享（省 ~7.09 GB）
- 前置：先校验各服该文件 size+前 6 MB hash 相同（已实测相同）→ 建共享缓存 → 逐服替换为硬链接
- 回滚：保留原文件 `.bak_hardlink_<ts>`，失败即恢复

### Round 3（写能力，高风险）
- `POST /api/mods/deploy`：统一下发新 FileId 到目标服（停服 → 备份旧目录 → 解压新目录 → 校验 → 起服）
- `POST /api/plugins/deploy`：按白名单推 dll（禁 db/config）
- 前端二次确认 `lbAskCard`

## 6. 硬规则（实现时必须遵守）

1. **判定以磁盘为准**，`modInfos.json` 只做展示（实测已全面滞后）
2. MOD 目录名必须 `\<pid>_<fid>\`，**新旧 FileId 不得混装**（部署前先删旧目录）
3. 只有**同 FileId** 组内才可共享文件
4. 插件分发白名单 `*.dll` / `PluginInfo.json` / `config_help.json`；黑名单 `*.db*` / `config.json`
5. 库（`ArkApi\AsaApi.dll` 等）必须全服同版本，**不覆盖 `config.json` 与 `Cache\**`**
6. 所有写操作：停服 → 备份 → 写 → md5 校验 → 按原状态起服
7. UI 禁 ✓/✗ 字符，用 MDI 图标
8. 不自动清理 pdb 残留，只展示

## 7. 与 ASAM 的分工（避免冲突）

| 职责 | ASAM | 我们的面板 |
|---|---|---|
| MOD 搜索/元数据 | ✅ 主力（走自建 CF 代理） | 只读展示 |
| MOD 下载 | ✅ 有（Download / Sync Mods） | Round 3 补位（共享缓存 + 硬链接） |
| 命令行 `-mods=` | ✅ 唯一写入方 | 只读，绝不写 |
| API 库安装 | ✅ 有（API_File_Installation.txt） | 只读比对一致性 |
| 插件分发 | ⚠️ 母本过时（2024 版） | Round 3 主导（自建母本） |
| 空间优化 | ❌ 无 | ✅ 硬链接去重（核心差异化价值） |
